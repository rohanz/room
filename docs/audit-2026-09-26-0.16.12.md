### 1. Late base texts can survive retirement indefinitely

**P1 — sharing correctness.** Locations: [doc.ts:183](/private/tmp/room-audit3/packages/shared/src/doc.ts:183), [index.ts:712](/private/tmp/room-audit3/packages/roomd/src/index.ts:712), [index.ts:759](/private/tmp/room-audit3/packages/roomd/src/index.ts:759).

**Problem:** A flat base key published concurrently with eviction can arrive after its owner’s overlays have been deleted. The sweep removes it only when another reconciliation occurs. The observer handles deletions of the live daemon’s own keys, not additions belonging to departed owners; unchanged-HEAD polling returns without sweeping.

**Consequence:** Source text remains in the shared document after retirement, potentially indefinitely in an otherwise idle room.

**Smallest clean change:** Schedule the existing orphan sweep when remote flat-key additions leave an owner without overlays or deletion marks. Preserve live-owner repair. Add a regression that waits for automatic cleanup without explicitly invoking reconciliation.

**Reproduced:** Two Yjs peers converged to no published paths for `Gone`, but `baseText('Gone', …)` still returned the late text. The existing [regression:156](/private/tmp/room-audit3/packages/shared/src/base-text-ownership.test.ts:156) manually calls the missing reconciliation.

### 2. Fresh-spawn cancellation can delete a running worker’s worktree

**P1 — work preservation.** Locations: [workers.ts:195](/private/tmp/room-audit3/packages/room-mcp/src/tools/workers.ts:195), [worker-launch.ts:109](/private/tmp/room-audit3/packages/room-mcp/src/worker-launch.ts:109), [workers.ts:426](/private/tmp/room-audit3/packages/room-mcp/src/workers.ts:426).

**Problem:** The launcher now distinguishes a started process whose stop was unconfirmed through `WorkerLaunchError.delivered` and `.stopped`. The fresh-spawn caller ignores both and unconditionally calls `abortPrepared()`, which force-removes newly created worktrees.

**Consequence:** Cancellation, refused signalling, or exit-observer failure after process start can remove a live worker’s checkout. Even a confirmed stop can leave edits that this rollback deletes without recovery.

**Smallest clean change:** Restrict preparation rollback to failures before process start. Once started, retain the checkout and worker record, report the confirmed lifecycle state, and leave removal to normal collection/discard.

**Inferred:** Traced the post-start error through the unconditional rollback to `git worktree remove --force`. No process launch or destructive cleanup was executed.

### 3. The local workers room erases the team room’s retained-path record

**P2 — lost sharing state.** Locations: [retained-declared.ts:13](/private/tmp/room-audit3/packages/roomd/src/retained-declared.ts:13), [workers.ts:249](/private/tmp/room-audit3/packages/room-mcp/src/tools/workers.ts:249).

**Problem:** Server, room and participant identify the contents of one worktree-wide file, rather than separate records. Constructing another identity deletes that file. A team lead routinely opens its local workers room using the same checkout, triggering this collision.

**Consequence:** Finished declared output loses its persistence merely because the lead spawns workers. After restart with an empty scope, previously retained files disappear from sharing. Concurrent publishers can also overwrite each other’s records.

**Smallest clean change:** Use separate files keyed by normalized server, room and participant. Make retirement remove only the matching record.

**Reproduced:** With filesystem operations replaced by an in-memory store, creating the local-room record erased the team record; reopening the team identity restored zero paths.

### 4. Joining workers discard broadcasts delivered through the bridge

**P2 — lost messages.** Locations: [bridge.ts:276](/private/tmp/room-audit3/packages/room-mcp/src/bridge.ts:276), [join.ts:89](/private/tmp/room-audit3/packages/room-mcp/src/tools/join.ts:89).

**Problem:** The bridge converts team broadcasts into addressed notes to individual workers. The join-history exception preserves only **unaddressed** post-spawn notes from the lead. A relayed note arriving between spawn and join therefore becomes filtered history.

**Consequence:** A worker can miss a team interrupt such as “stop now” despite the bridge successfully delivering it to the local document.

**Smallest clean change:** Preserve post-spawn notify/interrupt notes from the lead when addressed either to nobody or to this worker. Test bridge delivery followed by the real history filter.

**Reproduced:** Passing a team interrupt through `relayDown()` produced an addressed local note; `markHistorySeenOnJoin()` immediately marked that note filtered.

### 5. Flat baseline ownership is absent from the server identity guard

**P2 — baseline integrity.** Locations: [doc.ts:176](/private/tmp/room-audit3/packages/shared/src/doc.ts:176), [readonly.ts:143](/private/tmp/room-audit3/packages/server/src/readonly.ts:143), [readonly.ts:201](/private/tmp/room-audit3/packages/server/src/readonly.ts:201).

**Problem:** `basetextFlat` introduces participant-owned keys, but `DocumentIdentityGuard` never checks their owner prefixes. Another authenticated participant can add or replace Alice’s baseline. Owner reconciliation does not correct an existing replacement: `setBaseText()` returns when the key exists.

**Consequence:** Foreign text can persist as Alice’s baseline and corrupt browser diff and merged-view attribution.

**Smallest clean change:** Validate flat-key additions and replacements against the authenticated owner, including separator/name validation. Keep legitimate cross-owner cleanup deletions allowed. Add a guard regression using an encoded Yjs update.

**Reproduced:** An update replacing `Alice\0sha:f.py` was accepted under login `Bob` with `{ ok: true }`.
