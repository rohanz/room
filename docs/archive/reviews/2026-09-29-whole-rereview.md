## New must-fix findings introduced by the fixes

### N1 — Graph provenance never catches up when graph content is unchanged

**Owner: graph publication / readers.** `packages/room-mcp/src/graph-index.ts:120–125,452–453,484–491`; consumer `packages/room-mcp/src/conflict-set.ts:431–434`. Introduced by `e4f34f6`'s exact `sourceRev` gate without corresponding publication identity changes.

A signature conflict has a published graph at revision r. A later edit changes only the body (or a non-source file), so the manifest revision becomes r+1 but paths/edges/observations are identical. `publicationKey` omits rev, both deduplication keys omit provenance, and the publisher returns without updating `sourceRev`. The consumer thereafter treats the graph as stale indefinitely and redacts/withholds contract checks. Waiting for the throttle does not fix content-key equality.

**Probe:** real temporary Git checkout and GraphIndex, `minPublishMs:0`: publish `def call(a,b): return a`, then change only the body to `return b`; after both builds/publications, `graph.sourceRev !== manifestHead.rev`. The same graph is rejected by the new consumer gate. The probe also performed the exclusion withdrawal check described under sharing M2.

**Fix direction:** include the source fence/revision in publication scheduling and deduplication, or publish a correctly validated content-equivalence provenance token consumed by the reader. Cover body-only and non-source changes, and restoration after a transient incomplete head; equal symbols must not leave a permanent coverage gap.

### N2 — Contract redaction resets notice identity and emits a contradictory clear

**Owner: derived conflicts / delivery.** `packages/room-mcp/src/conflict-set.ts:63–79,82–96,498–512`. Introduced by `e4f34f6`.

Redaction deletes every per-symbol slot and replaces it with a `subject:'*'` slot. When readable evidence returns, the real symbol's key is new, so `settle` restarts its epoch at 1, reusing an old deterministic notice ID. A changed signature can therefore be suppressed by hub deduplication or an existing receipt. The cleanup loop then considers the wildcard absent from the live keys and settles it clean, posting “the conflict with B cleared” while the recreated per-symbol slot is still conflicting. This can happen after an ordinary revision mismatch, not only deliberate privacy narrowing.

**Probe:** exercised real ConflictSlots through conflict→clean→second conflict (epoch 2), redact, and re-evaluation. The symbol restarted at epoch 1 and its new post reused the first conflict's ID. Applying the exact wildcard cleanup evaluation used by `contracts()` produced a clear alongside the still-conflicting symbol. This is a primitive-level probe plus the production-loop trace, not a live hub rehearsal.

**Fix direction:** retain a monotonic episode/notice identity across redaction without retaining restricted signature text. On restoration reconcile the redacted aggregate with the current per-symbol set; remove/replace the aggregate without announcing a clean evaluation while any represented contract still conflicts. Test through ConflictSet with a deduping post adapter and prior receipts.

### N3 — A lead's readable revert to base no longer notifies its carried worker

**Owner: carried conflict comparison.** `packages/room-mcp/src/conflict-set.ts:438–474`. Introduced by `e4f34f6`.

The carried branch correctly derives changes between the worker's inherited baseline and the lead's current readable version, but the new common provider check rejects **every `kind:'base'`**, labelling it unreadable. A lead reverting an inherited signature or deleting an inherited untracked API often has no manifest entry: its current version is legitimately base (including absence). That is still a real change relative to the worker's carried tree, and the worker can continue using the removed contract without a notice.

**Probe:** actual ConflictSet with a real Git base, carried-untracked `api.py` defining `call`, worker `consumer.py` importing/calling it, and a complete full-sharing lead whose current base has no `api.py`. No contract slot or contract notice was produced. All inputs were readable; no socket was involved. The existing positive carried-contract test only covers a lead with a named shared entry.

**Fix direction:** permit certified base versions for the carried-baseline comparison; distinguish an ordinary stale observation from a change explicitly derived against C. Add both removal-to-base and signature-revert-to-base cases, with the resulting worker notice.

### N4 — A late reclaimed scope is stored under the old participant key

**Owner: local cutover / identity.** `packages/relay/src/local-migrate.ts:178–184`. Introduced by `bf058ef`'s alias-aware translation and new non-placeholder branch.

Start with mail-only ambiguous `ben` in main and feature; reclaim main's identity as `ben-new`; the still-running old main session then declares its first scope. `translated()` returns `ben-new`, but the importer tests and sets `target.scopes` under **`person` (`ben`)**, while the value says `by:'ben-new'`. The intended owner has no scope. An existing scope at `ben` causes the new scope to be silently skipped instead, and its ledger key is still marked imported.

**Probe:** actual catch-up importer, two snapshot files, alias/reclamation state between passes, then a new main scope. `scope('ben-new')` was undefined and `scope('ben').by` was `ben-new`.

**Fix direction:** key and collision-check the scope by the translated owner; retain the source provenance/fingerprint for later ambiguity handling. Test arrival after real reclamation, both with and without an unrelated schema-2 scope at the old spelling.
