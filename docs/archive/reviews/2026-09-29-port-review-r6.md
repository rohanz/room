## Findings

1. **should-fix — The root-listability check enumerates the entire root synchronously.** `packages/roomd/src/index.ts:1212`.

   **Evidence:** the new `fs.readdirSync(this.dir)` runs immediately before Chokidar setup and discards its entire result. It reads no file text and does not recurse, but allocates every root entry and prevents an event-loop turn until the listing finishes. Its work and result size grow with root width, including ignored entries. Thus a very wide or slow root adds a synchronous startup delay; the overall startup timer cannot fire during that syscall. Ordinary readable-root behavior and watcher options are unchanged. Unreadable roots now fail promptly with the intended watch-phase error, verified by the passing startup regression.

   **Fix:** open the directory with `fs.opendirSync`, call `readSync` at most once, and close in `finally`, preserving the existing `RoomdError` wrapper. That reads a bounded directory buffer rather than the full inventory; an empty root is still listable. Add an operation-count regression asserting one directory read and closure on both success and read failure, preserving the real unreadable-root test. This bounds enumeration work, not arbitrary filesystem syscall latency.

   **Severity ruling:** rohanz answered room question `m_mun2a7jm61vrtr`: root listing only needs to establish listability, so grade this “nit/should-fix” and use the open/read-one-entry approach. Reported as **should-fix, not must-fix**. It does not invalidate sign-off.

Each mapped range still walks the prepared diff, but no longer rebuilds its table or splits/hashes the owner text.

**PID reuse and orphan temps:** `packages/relay/src/leases.ts:44–73`. Yes, a temp can remain indefinitely if its old writer's PID is reused by a long-lived process, or if every later sweep observes that PID alive. The new rule deliberately prefers this over unlinking a live writer's temp after an unreliable identity probe. These files use unique `.roomtmp-…` names, carry small record payloads in normal usage, are never accepted as the authoritative lease, and do not block the authoritative filename's create/replace/recovery. Successful and ordinary failed writes remove their own temp in `finally`; a later sweep removes a mismatched/absent-identity temp once the PID is actually gone. The unchanged lease-token liveness/recovery path still distinguishes reused PIDs; only opportunistic temp cleanup became more conservative.

There is **no hard global retained-file count, byte quota, or retention deadline** in this function; “bounded” means small individual normal-use records, not a strict bound across unlimited crashes/PID reuse. Retained temps also add work to later sweeps. The lead explicitly accepted this tradeoff in the answer to `m_mun2a7jm61vrtr`: small inert leftovers are preferable to deleting a live writer's temp. **Not a finding under that ruling.** Passing lease tests cover missing/disagreeing identity for a live PID, preserving a real child writer's temp, cleanup after child death, and recovery of the authoritative lease after PID reuse.

**Startup behavior:** the new root check catches a root already unreadable at watch setup, without changing subdirectory-ignore policy or Chokidar's normal setup. It is a preflight, not a guarantee against permissions changing after the check; the existing fatal-error listener and startup deadline remain. Its new width-dependent synchronous work is finding 1.

**Bundle:** inspected every bundle hunk. The committed bundle carries the same map preparation/grouping, cap check, root check, and PID-alive guard as the reviewed source. No unrelated bundle behavior appeared in the diff. No bundle rebuild was performed during this read-only review.
