# Registry review — 2026-09-28

Reviewed the 728-line registry draft against 0.16.33, the audits, host surveys, ledger and draft manifest. References below use that snapshot. Read-only inspection; no runtime or network tests.

## Must-fix

1. **The tag reservation has a live-owner deletion window.** Spec `docs/superpowers/specs/2026-09-28-registry.md:223`, `:102`, `:211`; code `packages/room-mcp/src/owned-file.ts:23`, `:37`. A creates `tags/tests.json`, pauses before writing its worker record; B sees the missing record and recovers the tag, so both prepare `room/tests` under different ID-scoped op leases. Also, tags contain only `{id}`, although reconciliation tests their holder identity. Define an owner-bearing reservation and recovery that distinguishes an unfinished live reservation from an orphan. Specify atomic publication/recovery of lease contents: kill after O_EXCL creation but before JSON writing currently leaves an unreadable lock that cannot be reclaimed. Ordinary temp-and-rename replacement does not provide exclusive creation.

2. **Preparation is not write-ahead.** Spec `docs/superpowers/specs/2026-09-28-registry.md:233`, `:574`; code `packages/room-mcp/src/worker-git.ts:111`, `:183`, `:229`. Kill after `worktree add` or a carry-ref update, before `prepared` is persisted: the record lacks `created`, `branchCreated` and `previousCarryRefs`, so recovery cannot distinguish newly created resources from pre-existing work or restore refs. Even the proposed completed record omits the latter two fields required by `cleanupPreparedWorktree`. Persist the preparation plan and original ref/resource facts before mutation; recover each substep. `prepareWorktree` cannot remain unchanged when its carry-record ownership checks at `:202–218` are also being deleted.

3. **A missing process is not proof a launch never happened.** Spec `docs/superpowers/specs/2026-09-28-registry.md:235`, `:331`, `:576`; code `packages/room-mcp/src/worker-launch.ts:78`, `:81`, `packages/room-mcp/src/worker-process.ts:179`, `:247`. Kill the lead after spawn, before PID persistence; the child consumes the prompt and exits before joining Room. Recovery finds neither a report nor a live cwd process and labels the run `never`, permitting the prompt to run again. Conversely, an unrelated host started in an explicitly supplied directory can satisfy the cwd/time/executable scan and receive that worker's stop signal. OS start markers are also boot ticks/second-resolution strings, not directly comparable with `intentAt`. Require launch-specific durable acknowledgement/evidence; represent an ambiguous launch explicitly, never as definite non-delivery or proven ownership. Define the pre-exec/unreadable-identity and asynchronous spawn-error cases too.

4. **The status table does not cover its own recovery states.** Spec `docs/superpowers/specs/2026-09-28-registry.md:283`, `:289`, `:590`; code `packages/room-mcp/src/registry.ts:92`. A fresh `exit.never=true` run has no process or joined report, so first-match row 2 returns `starting` forever; row 11 is unreachable. It consumes capacity and refuses resume despite the recovery text saying failed. Terminal phases likewise have no explicit result. Separately, report-then-SIGKILL is `failed` under row 8 with a live lead but `done` under row 9 without one, contradicting Failure §2's “report ... still makes ... done.” Make the table total and settle report-versus-exit precedence explicitly.

5. **The unchanged lifecycle adapter rejects the new statuses.** Spec `docs/superpowers/specs/2026-09-28-registry.md:310`, `:556`, `:654`; code `packages/shared/src/types.ts:124`, `packages/room-mcp/src/worker-state.ts:135`, `:174`, `:195`. Import a running old worker, let it exit, then explicitly collect it: `statusOf` gives `stopped`, but unchanged `decideCollect` accepts only `done` or stopped `running`/`dismissed`, so it skips the edits. `starting`, `unknown` and `collecting` are also outside `WorkerStatus`; `workerRealState` treats any non-`running` status as finished. Specify a complete mapping, including finished/dismissed/exit facts, or revise the decision types. Keeping the old tests unchanged does not verify this boundary.

6. **Witnessed exit evidence can still be lost on an edge.** Spec `docs/superpowers/specs/2026-09-28-registry.md:214`, `:267`; code `packages/room-mcp/src/registry.ts:376`, `packages/room-mcp/src/worker-process.ts:116`. A resumed worker exits 1 while another op holds its lease; the callback is skipped. Reconcile can discover only that the PID is gone, so row 10 calls it `done` using the earlier report instead of row 8's `failed`. Reconcile can also persist an unwitnessed exit before the callback acquires the lease. Keep exit observations pending until durably recorded and define witnessed-over-unwitnessed precedence for the same run; process polling cannot reconstruct an exit code.

7. **Discard recovery lacks the authorized plan and is not idempotent.** Spec `docs/superpowers/specs/2026-09-28-registry.md:340`, `:588`, `:653`; code `packages/room-mcp/src/tools/collect.ts:164`, `:212`, `packages/room-mcp/src/worker-git.ts:408`, `:437`. `discard` without force writes `discarding`, then refuses on ignored artifacts or nested workers. The next reconcile is told to finish it, but the record stores neither `force`, the refusal, descendant selection nor the recovery-patch path. Kill after `saveDiscardPatch`: replay writes a second timestamped patch (or EEXIST within the same second), contradicting test 16. Validate before committing destructive intent; persist exact authorized options, stable patch identity/verification and substep progress, with an explicit refusal/retry state.

8. **Report writes need run/process fencing, not just worker ID.** Spec `docs/superpowers/specs/2026-09-28-registry.md:151`, `:250`, `:260`; code `packages/room-mcp/src/tools/workers.ts:57`. Restart a worker MCP in the same run after it reported done: the prescribed assignment `report.runs[n] = {joinedAt, host}` erases `done`. Overlapping old/new MCPs can also replace the whole report file with stale snapshots; a resumed run intentionally retains the same worker ID. Define monotonic per-run updates, one current report writer, and admission against the current run and non-retired phase. A stale process must not rejoin or recreate a report after collection just because ID and directory still match a kept worktree.

9. **Migration launders replicated authority into local capabilities.** Spec `docs/superpowers/specs/2026-09-28-registry.md:540`, `:549`, `:707`; code `packages/relay/src/memory.ts:35`, `packages/room-mcp/src/registry.ts:451`, `packages/room-mcp/src/worker-process.ts:216`. A valid canonical worktree exists; its old replicated record names another conversation or another same-host live PID/start time. Checking the directory and process identity independently does not establish that either belongs to this worker. The spec explicitly accepts unverifiable host session IDs, then authorizes resume. A snapshot is replicated data even when stored locally. Require worker-bound local evidence for each capability (including run/session/process correlation); otherwise import it as non-resumable/non-signalable, with explicit recovery. Do not turn legacy `status: done` alone into an authoritative worker report either.

10. **Migration is neither restartable nor complete for retained work.** Spec `docs/superpowers/specs/2026-09-28-registry.md:533`, `:536`, `:567`, `:606`; code `packages/room-mcp/src/worker-git.ts:303`, `packages/room-mcp/src/tools/collect.ts:119`. Kill after creating `room/registry/` and importing one of several workers: next open skips migration because the directory exists. Two first opens can also mint different IDs for the same worker. A collected-but-kept worktree has no live legacy worker record and is reimported as active; deletion of a new registry after M7 also loses its removed carry metadata and terminal history. Use a migration lease, resumable per-source mapping and completion marker; distinguish active/retired/unmanaged worktrees. Without baseline evidence, preserve files but disable delta collection/resume rather than recreating capability from path shape.

11. **First sync plus a local holder check does not settle concurrent clones.** Spec `docs/superpowers/specs/2026-09-28-registry.md:403`, `:413`, `:459`, `:594`; code `packages/room-mcp/src/session.ts:345`, `packages/roomd/src/index.ts:604`. A and B sync an empty room, independently acquire clone-local leases, write their own holder, pass the local check and publish under the same name. During a partition each continues to see itself as holder. Merging can select A's holder and B's independently keyed text/projection; stopping B on the next tick does not undo those writes. Document the actual eventual arbitration guarantee under R1a, and fence publication generations/readers so losing-holder data cannot be accepted as the winner's. A session-ID field checked only before writes is not a cross-replica fence. Define the 90-second grace for a newly joined observer with no presence history too.

12. **Same-session takeover does not fence the old MCP; name loss strands the publisher lease.** Spec `docs/superpowers/specs/2026-09-28-registry.md:397`, `:408`, `:418`; code `packages/room-mcp/src/owned-file.ts:28`, `packages/room-mcp/src/session.ts:391`. A live MCP is replaced within the same host session; the successor takes its name lease, but the predecessor's session-ID-only check still passes. Both can project/report/write session files. Separately, a publisher loses its name to another machine and stops publishing; only its name lease is released, so another local session sees a live publisher PID forever and cannot take over. Require an instance token/process identity in local ownership checks and compare-and-release; specify publisher withdrawal/release on holder loss as well as ordinary leave.

13. **Retirement can clear a new worker's participant state after tag reuse.** Spec `docs/superpowers/specs/2026-09-28-registry.md:344`, `:363`, `:455`; code `packages/shared/src/doc.ts:152`, `:158`. W1 retires and releases `tests`; W2 immediately acquires it and joins as the same `<owner>+tests`. W1's delayed retirement projection then clears claims, overlays, base and receipts by participant name. The old guard depends on the current worker record already being projected; W2 can publish before that occurs. Bind retirement and participant cleanup to the worker ID/holder incarnation being retired, including offline replay, or keep the alias reserved until cleanup is fenced. Globally unique worker IDs do not make the reused participant name unique.

14. **The team participant record still has two declared writers.** Spec `docs/superpowers/specs/2026-09-28-registry.md:254`, `:431`; sibling `docs/superpowers/specs/2026-09-28-manifest.md:108`, `:274` (draft); code `packages/room-mcp/src/tools/workers.ts:40`, `packages/room-mcp/src/bridge.ts:80`. A `where: here` worker joins the team room: §3 says its daemon writes the team base, while §14 says the lead's bridge alone writes that worker's team participant record. For local workers, the bridge additionally lacks an explicit contract for projecting their policy/manifest while their daemon is absent. Apply binding R3b consistently to both spawn modes: state who joins which room and who owns base, manifest, coordination and holder fields in each. Do not leave this as a manifest follow-up.
