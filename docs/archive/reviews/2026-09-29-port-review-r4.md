## Findings

1. **must-fix — The new line-diff shortcut changes claim identity semantics: it releases uniquely moved blocks and moves ambiguous duplicates.** `packages/roomd/src/reanchor.ts:73`, `:74`, `:115–121`; enabled by `packages/roomd/src/index.ts:943`, `:966`, `:1025`.

   A diff hunk touching the old claim is treated as proof that its block is gone; an unchanged hunk is treated as proof of a unique destination. Neither follows from a line diff. The resumable digest search is skipped in both cases.

   **Actual-daemon reproduction:** `/tmp/astra4-daemon-move.mts` commits `a / claim1 / claim2 / b / c / d / e / f`, claims lines 2–3, then commits a cut/paste to lines 7–8. The daemon **removes the claim and publishes complete=true**, although its exact block is still present once. In the second case, committing `new` followed by two copies of the original makes the daemon **move the claim to lines 3–4 and publish complete=true**, although its block occurs twice. `/tmp/astra4-reanchor-move.mts` compares the same inputs through the helper with/without `previousTexts`: without it, the unique block moves to 7–8 and the duplicate is released; with it, both results reverse. Output is also recorded in `/tmp/astra4-daemon-move.log`.

   **Lead clarification:** rohanz answered room question `m_mun032vrovc3bk`: no ruling allows diff-selected identity; exactly one matching block permits a move, zero/multiple matches use the gone-block rule. Both reproduced cases are must-fix. The existing same-range digest-match behavior is not being reopened.

   **Fix:** use the diff only to propose a digest-verified candidate, preserving the required uniqueness decision for a relocated range. A removed/changed hunk must fall back to the bounded resumable search, not release immediately. An apparent moved unchanged hunk must not bypass ambiguity detection. Add real HEAD-transition cut/paste and duplicate regressions with `previousTexts` populated; keep the dirty-file retention rule downstream of the decision.

2. **must-fix — An already-invalid peer snapshot prevents all hook-state writes and schedules retries forever.** `packages/room-mcp/src/hooks-bridge.ts:158–160`; `packages/shared/src/manifest.ts:113–117`.

   Hook preparation correctly falls back to a whole-file warning when an owner's fence is invalid. Its final guard then calls `snapshotStillCurrent` for that same snapshot. That function always returns false when the captured snapshot was not fence-valid, even if absolutely nothing changed during preparation. Every retry captures the same invalid snapshot and aborts again. A peer with a retained old manifest after a holder change can therefore block the entire state file, including current company, own claims, and message counts, rather than merely degrading that peer's line mapping.

   **Reproduction:** `/tmp/astra4-hooks-stale.mts` uses the real `HooksBridge.write`, forty claims by Bob, Bob's manifest at fence `1`, and Bob's current holder at epoch `2`. After awaiting `write()`, it reports **`stateExists: false, retryScheduled: true`**. No peer/input changes are injected during preparation. The same final guard necessarily repeats for the unchanged state. This differs from the valid old prepare losing authority during its read, which is correctly refused.

   **Fix:** separate "already unavailable, render conservatively" from "changed since capture, retry." Guard the identity/revision of unavailable snapshots without requiring them to have been authoritative, and publish their conservative warnings. Retain the writer's stop/fence/revision/session-directory checks. Test a persistent stale peer with another healthy claim and pending-message counts; writing must finish without an endless retry schedule.

3. **must-fix — Copy collection's new asynchronous write loop invalidates its all-destination preflight and can overwrite a new lead edit without force.** `packages/room-mcp/src/tools/collect.ts:442–451`.

   The final identity gate checks every destination, but each subsequent `await fs.promises.copyFile` opens a new event-loop interval. There is no check of a later destination or source after earlier copies finish. The comment that no await separates the gate from the write phase does not protect the rest of that phase.

   **Reproduction:** `/tmp/astra4-collect-race.mts` invokes the real collect handler with a registered finished worker, two absent lead destinations, and `mode: 'copy', paths: ['a.txt', 'b.txt']`, with no `force`. The copy seam performs the real first copy, yields one immediate, and creates `b.txt` in the lead with `new lead edit during copy`. Collection then returns **`copied a.txt\ncopied b.txt`** and `b.txt` contains **`worker b.txt\n`**. The new lead edit is lost. No preflight data or Git result was fabricated. See `/tmp/astra4-collect-race.log`.

   **Fix:** prepare asynchronous source copies into temporary files first, validate all source/destination identities immediately before installation, and install with a synchronous bounded metadata-operation phase plus rollback. Alternatively provide equally strong per-destination refusal and rollback when a later destination changed; a partial refusal must preserve both the concurrent edit and prior originals. Add a second-path change during the first copy and a source change during that interval. Do not restore uncapped JS whole-file comparison reads.

4. **must-fix — File text still reaches synchronous processing without a pre-read byte bound on several active routes.** Primary: `packages/room-mcp/src/tools/claims.ts:137–141`, `packages/room-mcp/src/graph-index.ts:542–579`, `packages/roomd/src/publisher.ts:195`.

   The new bounded helpers cover the original direct diff/preview/worker-text routes, but the final audit finds these remaining routes:

   - **Claim overlap mapping:** `tools/claims.ts:137–138` still reads an owner's unchanged base through uncapped `gitShow` or a held hash through `git cat-file -p`, then line-splits/maps it at `:141`. The fan-out at `:83` invokes this even for foreign claims on other paths, before filtering overlap. An unchanged tracked file need not have passed the publication size cap. Neither Git read is preceded by blob-size metadata.
   - **Graph/observed contracts:** `graph-index.ts:338`, `:344`, `:378`, `:381` still use `gitShow` for historical text. More significantly, `:542–545` reads the old baseline through `gitShow`/`readBaseline`, and `:579` passes it to `observedContractChanges`. A small new file does not bound its large old version. `shared/src/graph.ts:113–130` falls back to regex definition processing when the supplied parser declines input, so the parser's own size check does not bound that baseline processing. `/tmp/astra4-text-bounds.mts` reads a real **2,097,154-byte** committed file through the actual `GraphIndex.textFor` method. Post-read checks elsewhere are not pre-read bounds.
   - **Carried publication bases:** `publisher.ts:195` calls `checkoutText` for carried untracked blobs without their size metadata. `baseline.ts:114–115` permits up to the generic 64 MiB subprocess output guard. `/tmp/astra4-carried-base.mts` seeds a real 2 MiB Git blob as a carried baseline, replaces its disk file with six bytes, and calls the actual publisher prepare: **`baseTextBytes: 2097152, currentBytes: 6`**, with `cat-file --filters --path=carried.txt <blob>` and no size query for that blob. The prepared base is installed into `ownedBaseTexts` at `publisher.ts:302`. This is historical content publication, not the excluded carry hash check.
   - **Repository configuration text:** `roomd/src/index.ts:501–503` synchronously reads/parses `.roomignore` without a descriptor bound; `/tmp/astra4-text-bounds.mts` records **2,097,154 bytes read with a scheduled immediate still unserviced**. `tools/scope.ts:255–258` fetches and parses CODEOWNERS via uncapped `gitShow`. `worker-git.ts:61` and `:206` similarly read/split `.roomlinks` without a descriptor cap. These are repository-controlled file text, not the accepted parsing of Git's path inventory.

   **Fix:** route every disk text read through a descriptor cap and every historical blob read through size metadata before content retrieval; also bound checkout-filter output. Oversized source/baseline/config text must produce an explicit gap or conservative behavior (especially conservative ignore/privacy behavior), not exact-looking empty content. Keep graph parsing/regex fallback downstream of the bound. Add large-old/small-new, large unchanged claim-owner, carried-base, and oversized config probes at the production callers.

5. **must-fix — Whole-participant snapshot fan-out remains in ordinary MCP/web readers and claim mapping.** `packages/room-mcp/src/tools/state.ts:104`; `packages/web/src/manifest-reader.ts:32`; `packages/room-mcp/src/tools/claims.ts:134–135`.

   The projected `ConflictSet.read` path is fixed, but each ordinary `readVersion` and `readWebVersion` still copies every manifest entry and converts every overlay text to read one path. `room_claim` repeats the same whole-owner snapshots once per foreign claim. This violates the binding per-path snapshot rule independently of whether a caller awaits between requests.

   **Reproduction:** `/tmp/astra4-reader-fanout.mts` uses the real `createHandlerState().readVersion` and real `readWebVersion` against a valid 1,000-overlay participant. Each performs 1,000 successful one-path reads. Instrumented `Y.Text.toString` totals are **MCP: 1,000,000; web: 1,000,000**. The MCP helper is called in actual many-path routing at `tools/messaging.ts:382–385` and once per claim in `tools/scope.ts:65` through `readText`. The web per-path conversion is still unnecessary even when the UI reads only its selected path. The claim loop's synchronous `Promise.all(...map(...))` invokes whole snapshots before the callbacks reach their first await.

   **Fix:** use `snapshotPath` at single-path reader boundaries and in claim mapping, or one guarded snapshot per complete operation with per-owner/path caching. Keep post-await authority checks. Add conversion-count regressions for ordinary readers and the claim path, not only projected conflict reads and metadata-only web coverage.

6. **must-fix — Preview test preparation still contains filesystem loops over arbitrarily many paths with no yield.** `packages/room-mcp/src/tools/files.ts:332–336`, `:370–399`.

   The merged-file materialization loop now yields, but the preceding mode-preparation loop calls synchronous lstat/`mergedFileMode` for every merged path without yielding. `linkSharedDirs`/`mirrorLinks` then synchronously enumerate workspace dependency directories and create every package symlink. Neither is a final atomic publication/collection gate or a single parse of Git output.

   **Reproduction:** `/tmp/astra4-link-stall.mts` invokes the real exported `linkSharedDirs` with 2,000 package directories. It creates **2,000 symlinks while a previously scheduled immediate remains unserviced** (`/tmp/astra4-link-stall.log`). Mode preparation's no-await filesystem loop is direct line-level evidence. The first probe attempt used macOS's `/tmp` symlink spelling and was correctly refused; the recorded successful fixture uses captured canonical roots as production does.

   **Fix:** make dependency-link preparation asynchronous/yielding with a bounded batch at loop tops, including skipped entries and scoped package recursion; likewise yield in mode preparation. Preserve containment revalidation across the new intervals. Add event-loop-turn assertions inside these phases instead of relying on a later materialization yield.
