# Room reference

[Quickstart](../README.md#start-in-five-minutes) · [First session](onboarding.md) · [Upgrade from 0.16](upgrading.md)

## Rooms and destinations

A local room is named `local/<main-worktree basename>`. It uses a loopback relay, needs no account, and is shared by sessions in a clone and its linked worktrees. A team room is named from the canonical Git origin, such as `github.com/owner/repo`; all branches of that repository meet there. The room shows each participant's branch and base separately. A GitHub team repo must be opened once with `room_create`, and joining it requires push access. A server without GitHub or OIDC login can admit a non-GitHub room with a shared token. GitHub rooms cannot use that token.

Room selects local automatically only when no environment or remembered team destination overrides it. Sessions in the same clone and its linked worktrees share one relay; independent clones remain separate even if their origins or folder names match. Claude normally joins when its Room MCP starts. Codex’s shared app-server defers repository binding until the first Room tool request provides workspace metadata (observed in Codex 0.157.1; current code also defers when the parent cannot be identified, and on native Windows). Listing tools alone does not join. Asking **“show room state”** establishes the connection without an explicit `room_join`.

Since 0.17.1, remembered automatic host labels are reused only for the matching host, and automatic naming avoids retained worker identities. An explicit tag still selects that exact identity subject to its name lease. Default `room_state` lists online sessions outside your work area with their identity and activity; offline history is summarized separately. Detailed claims and changed files remain filtered to your area unless `all=true`.

The destination rule is **tool argument > `ROOM_SERVER` > legacy `ROOM_URL` > remembered clone choice > local**. `room_join(where="team")` chooses `ROOM_SERVER`, then the server in `ROOM_URL`, then the team server this clone used before, otherwise asks for a server URL without making a network request. There is no default public server. An explicit URL wins. `room_join(where="local")` keeps everything on this machine. Saying “join the room” makes a team choice; “work locally” switches back. The choice is stored in the common Git directory and applies to linked worktrees. `room_leave(forget=true)` clears it. Environment settings override the choice without saving it. Room never moves to a team room on its own initiative.

For a self-hosted server, see [self-hosting](../deploy/self-hosting.md). If launching Codex with `ROOM_SERVER`, use `codex --no-daemon`; the shared app-server daemon does not inherit your shell's `ROOM_*` variables. In a team room, `room_login` prints a GitHub device URL and code. The server holds the approved token; Room does not send your `gh` token. `room_state(link=true)` returns a seven-day, room-scoped browser view key. Anyone holding the link can read the shared code and activity.

## Sharing and agent context

On the first team join from a worktree, Room tells the user what will be shared. The notice includes that teammates on any branch can see it. `room_share` changes the level while connected; a server can set a ceiling.

| Level | What others receive |
|---|---|
| `full` (default) | Full text of eligible changed files. |
| `declared` | Paths of eligible changed files; text only in the agent's declared area. Ignored, unsafe, oversized and budget-excluded paths remain digest-only. |
| `intent` | Plans and claims, with no file text. |

At `declared`, a changed file that was declared stays shared while it differs from its base, even after `room_done` or a daemon restart. Changing the sharing level, ignoring the file, or exceeding the size budget withdraws its text; declaring it again shares it. “Share plans only” withdraws file text. An invalid `ROOM_SHARE` value falls back to `intent` and reports the setting. When two sessions use one checkout, its primary session publishes file text; the secondary session's area does not control that publication. Reading a person who shares less produces a short explanation.

Automatic reconnects retain the current session's sharing choice. A worker's launch-time `ROOM_SHARE` supplies its initial default; once the worker changes sharing, its saved choice survives a retained-session resume. An explicit `room_join(share=...)` or `room_share(level=...)` can still change that choice. A non-worker's explicit startup environment keeps its normal precedence over saved settings.

Areas come from `CODEOWNERS` at each participant's HEAD. If no rule matches, an uncommitted file gives its top-level directory an area for its editor. `room_scope` states intended work. Claims are advisory and can include planned public interface changes. Room indexes definitions and references with tree-sitter and reports likely consumers of changed signatures; a body-only edit does not become a contract change. Announced plans take precedence over observed signatures. Routine scopes and releases stay in the feed. An inbox receives addressed messages, relevant conflicts and interrupts; `room_state` gives full detail near your work, one line per online participant elsewhere, and a compact summary of offline history. The bus keeps a rolling window and archives older messages in the ledger.

Since 0.17.2, distinct connected participants count as company even when they watch the exact same physical checkout. Eligible addressed messages can reach their hooks and host wake paths. Routine activity remains in the feed, and own-worker notices retain their existing delivery rules. Shared file reports are deduplicated independently: explicit scopes and claims still coordinate separate agents. This corrects the same-checkout wake suppression present through 0.17.1.

While nobody else is present, nothing wakes the session or reaches its hook inbox; the waiting items appear in `room_state` and the next Room tool reply. Your own workers count as company only for their own messages and Room's notices about them, and your human's messages always arrive. A possible conflict is announced once per teammate and file, naming all their claimed ranges, and once more when it clears. `room_state`'s recent messages leave out migrated 0.16 history and say how many there are; `room_state all=true` shows them. A new worker that reuses a tag is not owed messages addressed to the earlier worker of that name; a resumed worker still gets what was sent while it was stopped.

The local browser link is `file:///…/plugins/room/web/viewer.html#room=…&view=…&participant=…&relay=1`. The installed viewer contains its JavaScript and CSS, so the loopback relay cannot supply executable page content. The capability remains in the fragment for reloads and in page memory; the file viewer does not put it in session storage. The explicit `relay=1` selects the local relay proof and encrypted WebSocket; a team server on localhost uses the ordinary team credential flow. Its room-scoped view capability mints single-use, read-only websocket tickets with a WebCrypto HMAC proof; the private clone key stays in Node processes and the discovery file. Node clients send a port-bound `Authorization: Room-Proof` header. Every relay WebSocket authenticates itself in-band and encrypts document frames with AES-256-GCM. The relay accepts loopback connections only. Old `http://127.0.0.1:<port>/` viewer links no longer load a page; ask your agent for a fresh file link. Old local `?key=` links are rejected. When another session uses your login, Room assigns a stable clone tag such as `rohanz+claude` so an offline overlay cannot be confused with another clone's work.

Team HTTP requests send a login session as `Authorization: Bearer <session>` or a shared token as `X-Room-Token: <token>`. Node websocket upgrades use the same headers. Browser view links carry a read-only capability in the URL fragment; the page keeps it in session storage and calls `POST /ws-ticket` before each connection. Older query-form team view links are still read and stripped after arrival; those requests can appear in access logs. Old local `?key=` links cannot connect and the view asks for a new link. Tickets are single-use, bound to one room and credential, and expire within 60 seconds. With `ROOM_WEB=http://localhost:5173`, the web dev server can serve the view separately from the room server on localhost:1234; `/ws-ticket` permits only the JSON ticket exchange from that origin.

At-least-once delivery applies to messages retained in a surviving replica's ledger. An acknowledged post can be lost if every replica holding it disappears before persistence; local snapshots are delayed. Expiry and caps can remove retained messages. The team server and the local relay enforce one live room document cap: once a room is over it, writers are refused (close 4413) and reads continue. A Room client pauses publishing and retries once a minute. The local relay still accepts writes that add nothing over the cap, such as a newcomer's sync or a deletion, so a local room stays joinable and can shrink. A local relay's cap is 64 MiB; it also skips snapshots above 64 MiB and keeps the previous file.

The browser's Network tab shows upstream dependencies, a participant's own edits and plans, and potential downstream consumers. Announced plans and observed definition changes are separate sources. Blue indicates edits, purple contract changes, and red potential impact. The graph is a projection and does not prove a change has landed or works. Participant colors follow join order and repeat after eight people; names disambiguate them. Search, participant selection, zoom and “Relevant to my work” help narrow larger views.

Open pull requests to or from participants' branches appear as `pr#<n>` participants with scopes from their changed files. One elected client refreshes the mirror about every two minutes; server GitHub PR data is cached for a minute. `room_pr_note` can update one coordination comment on your branch's PR. It summarizes declared work, revised plans, questions, and previews.

## Common tools

| Tool | Purpose |
|---|---|
| `room_login` | GitHub device login or logout. |
| `room_create`, `room_join`, `room_leave`, `room_close` | Open a repository room, join, leave, or close it for everyone. Closing requires an explicit request. |
| `room_state`, `room_read`, `room_export` | Inspect people and files, read permitted versions, or export the ledger and old archives. |
| `room_scope`, `room_claim`, `room_impact` | Declare intended work, claim lines, and inspect consumers before changing an interface. |
| `room_send`, `room_wait`, `room_done` | Ask or answer, wait for a dependency, and finish a task. |
| `room_preview_merge`, `room_collect`, `room_spawn` | Check combined work, collect finished workers, or dispatch a worker. |
| `room_share`, `room_pr_note` | Change the sharing level or update a PR's coordination comment. |

## Wake paths

For missing wakes, check `room_state(check=true)` and `<git common dir>/room-mcp.log`. Host settings, disconnections or transport errors can prevent a wake even when a transport is configured.

Routine progress notes from the lead's own workers stay quiet. Addressed questions, worker completion (`room_done`) and eligible interrupts can wake it. An interactive lead with a configured wake path need not poll or watch worker PIDs just to receive those events. A headless lead must stay alive with `room_wait` while supervising workers; use that fallback for unavailable/disabled wake paths too. Messages also arrive on Room tool replies and eligible before-edit hooks. A process-exit watcher alone misses mid-task questions.

Claude Code **2.1.224+** on macOS, Linux and WSL 2, and **2.1.234+** on native Windows, can wake an idle session through its cross-session messaging inbox with plain `claude`. Room sends a short pointer; the agent reads the message through Room. Claude Code may frame the pointer as a message from another session. It is a prompt to inspect Room, not authority from another user. Events close together are coalesced. `crossSessionInbound=hold` delays the wake and `refuse` drops it; the Room message remains for the next turn. An organization may disable cross-session messaging.

`ROOM_WAKE=auto` (default) uses the inbox socket when available and an admitted channel if needed. `ROOM_WAKE=socket` uses only the inbox socket; `ROOM_WAKE=channels` forces the optional channel path; `ROOM_WAKE=off` turns wakes off on both hosts; addressed messages still wait until the agent next reads the room. For older Claude Code, `plugins/room/bin/claude-room` launches the channels fallback with `--dangerously-load-development-channels plugin:room@room`; channels are a research preview. Codex uses `codex queue`. Codex **0.157+** attaches Room to the session's folder on its first Room request; this was observed with the shared app-server daemon in **0.157.1**.

## Workers and previews

For an explicitly requested precollection review, a reviewer or controller in the **destination checkout** can call `room_collect(checkpoint="hold", reason="independent review")`. The reviewer and every collecting session must run a bundle with checkpoint support; old plugin processes do not enforce this new gate, so restart them after upgrading. Wait for a successful reply before relying on it. This durable local hold blocks new apply, copy and discard calls for that checkout, including `force`; preview, tests and follow-up messages still work. It persists across MCP restarts and does not expire when the reviewer goes offline. It is not a hosted-room control over another machine or checkout.

`room_collect(checkpoint="status")` lists holds. The creating host session releases its own hold with `room_collect(checkpoint="release")`; a replacement reviewer can supply the private `reviewToken` returned when the hold was created. Keep that token with the reviewer, not the collecting lead. Multiple reviewers must each release their hold. Checkpoint calls cannot include collection arguments, and release never collects automatically. The hold serializes with collection: it cannot undo or interrupt a collection already underway. It does not freeze other lifecycle operations, such as explicit room leave, ancestor discard or recovery of an already-started discard. This is cooperative workflow enforcement, not a security boundary against local filesystem access.

Apply, copy, discard and checkpoint operations share the destination collection lease. A concurrent operation can wait up to 30 seconds, then report that another collection is in progress; retry after the earlier operation finishes. Before creating a hold, verify that the reviewer is running in the lead’s destination checkout, not a worker worktree. A hold in one checkout does not protect another. Ownership uses a bound host session when available, otherwise the MCP process identity. If a host shares one unbound MCP process across chats, those chats must not be treated as independent reviewers; use a separately bound session or a separate MCP process.

If both the creating identity and recovery token are lost, or saved hold state is corrupt, recovery requires an explicit human decision. Stop collection activity and preserve a backup of the affected hold file before clearing it. Its location is `<git-common-dir>/room/registry/collection-reviews/<sha256-of-canonical-destination-path>.json`: resolve the destination checkout with `realpath`, then SHA-256 that exact path string. Remove or move only the verified file for that destination, not the registry or all review holds; this clears every reviewer hold stored in that file. Restart the affected sessions, check `checkpoint="status"`, and re-establish any holds still required before resuming collection. Agents must not silently use this escape hatch to bypass a review.

Ask explicitly for “Room workers” or “use Room to have Codex do part of it” for substantial parallel work. Generic agent, parallel or background requests use the host’s normal delegation; an existing Room worker workflow can continue without repeating the Room qualifier. `room_spawn` makes a worktree under `.room/workers/<tag>`; each worker gets its own development port. It carries eligible tracked and non-ignored untracked work from the lead. Files over 5 MB or beyond 50 MB total, nested repositories, and unsafe links are skipped and named in the reply. The worker's changes return through `room_collect` as uncommitted, unstaged edits. A conflict leaves the lead's files untouched. Collection of a finished worker removes its worktree, branch and logs; a failed collection preserves them. Discard retains a recovery patch for a week. A worker in a borrowed checkout detaches without deleting the owner's worktree. A message from its lead to a finished worker resumes its retained session until collection or discard. Other participants ask that lead for a follow-up. Add `refresh=true` to `room_send` to first rebase a stopped worker's branch onto your HEAD, so it sees commits you made after spawning it; its uncommitted edits stay uncommitted and the message lists the commits that came in. A conflict changes nothing and sends nothing, as does a running worker, one started with `dir=`, one whose checkout another worker borrows, one whose branch has a merge commit (a rebase would drop it), or one with ignored files where the rebase would write (names are compared case-insensitively); the reply says how to proceed. The spawn reply warns about brief paths missing from the worktree, ignoring `.room/`, `.git/`, absolute, `~/` and URL paths.

A worker's tests run the worker's code. At spawn, when your clone has `node_modules`, a lockfile (`package-lock.json`, `npm-shrinkwrap.json`, `yarn.lock` or `pnpm-lock.yaml`) and Git ignores `node_modules`, the worktree gets its own `node_modules` made of links: to your installed packages, except workspace packages (from `workspaces` or `pnpm-workspace.yaml`), which link to the worktree's own package directories. Per-package `node_modules` are rebuilt the same way. Nothing is installed or copied, and linking gives up after 3 s. When Room cannot link (no `node_modules` or lockfile, a workspace pattern using more than `*`, `?` and `**`, a workspace package missing from the worktree, a failure or the time limit), it removes what it made, and the spawn reply and the worker's brief warn that cross-package tests in the worktree would run your code, naming the packages. To change dependencies, the worker deletes `node_modules` (only the links) and installs. For Python, a `VIRTUAL_ENV` inside your checkout is repointed at the same path in the worktree, and editable installs of your sources produce the same warning; the worker is told to run `uv sync`.

On native Windows, Room identifies host processes through CIM creation timestamps and executable names, and can stop a verified worker host. Launch makes at most three fresh identity attempts (each Windows query has a three-second limit), checking the retained child handle before and after each read. If a live child remains unverifiable, launch stops it and reports failure instead of losing the ability to manage it after a lead restart. It cannot inspect which descendant processes still use a worktree. Collection brings back edits but retains the worktree when that inspection is unavailable; discard refuses before saving a recovery patch or removing the folder, even with `force=true`. Recovery after a restart also retains these worktrees. Stop any remaining processes and preserve needed files before manually removing a retained checkout with Git. WSL uses the Linux process path.

Room's coordination variables (`ROOM_WORKER_ID`, `ROOM_TOKEN`, `ROOM_REGISTRY` and the other `ROOM_*` variables it gives a worker) belong to its Room MCP server and hooks. Shell filtering preserves `PORT`, thread caps and other user environment settings. A Claude worker gets a `CLAUDE_ENV_FILE` (`.room/workers/<tag>.env.sh`, mode 0600) that runs your own env file, if any, then unsets every `ROOM_*` variable before Bash commands. PowerShell does not read that file. Instead, a worker-specific `PreToolUse` hook (`<tag>.shell-env.mjs`) uses `updatedInput` (Claude Code 2.0.10+) to prepend `Get-ChildItem Env:ROOM_* | Remove-Item -ErrorAction Stop` to the visible command. It preserves every other input field and leaves normal permission checks in place; it never auto-approves. Hook exec-form arguments (Claude Code 2.1.139+) preserve Windows paths without shell quoting. A conservative text check denies commands containing `param`, `#requires` or `using` declarations, including matches in strings/comments; invoke a `.ps1` file for those commands.

The hook joins existing hook lists through `--settings`; managed settings retain precedence. [Matching hooks run in parallel](https://code.claude.com/docs/en/hooks#configuration), and the docs do not define which input wins when several hooks return `updatedInput`, so Room cannot guarantee the scrub when another hook replaces input. Room's inbox hook supplies only context. This is best-effort isolation: disabled hooks, hook startup errors or timeouts can also leave PowerShell commands with `ROOM_*`. Offline tests verify hook output. Authenticated Windows runs must verify harmless prefixed commands execute under the unchanged `acceptEdits`/`--allowedTools` configuration and original deny rules still block: [PowerShell has its own permission rules](https://code.claude.com/docs/en/tools-reference#bash-deny-rules-also-turn-off-the-powershell-tool), and allowing Bash does not establish PowerShell approval. A Codex worker uses `shell_environment_policy.filters={"ROOM_*"="exclude"}` (Codex 0.146+). Spawn/resume warns when shell artifacts cannot be written or Codex is too old.

A worker runs tests and builds in the foreground and waits for them: a headless worker's process ends with its turn, and its background jobs die with it. When a Claude worker exits without `room_done`, Room reads its log for background shell tasks still running at exit; its status and the lead's notice then say `ended without a report — background work was still running (N background task(s) killed at exit)`. Codex logs carry no such events. While a worker runs, `room_state` adds a line with its latest tool or file action, such as `editing api/tax.py · 20s ago`, read from the worker's log. It names files, tools and programs (`running npm test`), never message text, tool output, environment values or other command arguments, and stops at 80 characters.

Room has **no default worker model or effort**. The model and effort named in the request win, then a per-host setting (`ROOM_CODEX_WORKER_MODEL`, `ROOM_CLAUDE_WORKER_MODEL` and their `_EFFORT` variants), then `ROOM_WORKER_MODEL` / `ROOM_WORKER_EFFORT`; otherwise the host's own default applies (Codex's `config.toml` or built-in default, Claude Code's settings). The spawn reply reports what the worker runs with. `ROOM_WORKER_THREADS` overrides its compute thread budget; `ROOM_WORKER_MAX_BUDGET_USD` caps a Claude worker through that host's `--max-budget-usd`. Workers are capped at eight by default (`ROOM_MAX_WORKERS`). A lead can dispatch locally while in a team room: its worker messages remain on this machine and the lead bridges relevant team updates.

`room_preview_merge` combines selected participants at each pair's merge base. Untracked files a worker was carried and did not change are not merged again. Normal collection also removes recognized generated Python environments (`.venv/` or `venv/` with `pyvenv.cfg`, an interpreter and a standard layout), including contents inside their package directories. Unknown top-level files, wrong entry types and linked environment roots remain protected. Worker scratch (untracked, never committed and not carried: `*.log`, `*.tmp` and temp, swap and OS files) is listed in one line, not previewed and not collected; `room_collect` saves a copy under `.room/scratch/<tag>/` (5 MB per file, 50 MB total) and names what it did not save. When two participants each create the same new file with different contents, the preview reports that it needs a human or a rewrite. With `run=`, it runs the check in a cached worktree under the Git common directory's `room-preview/`, so ignored build output (`node_modules/`, `target/`) stays warm between previews. Each clone and checkout configuration has one cached worktree; one preview uses it at a time under an OS file lock (`lockf` on macOS, `flock` on Linux) that is released even if Room crashes, and a second preview at the same moment uses a temporary checkout. After a preview, Room tries to remove the least recently used cached worktrees through Git until the repository's cache is under its nominal cap (`ROOM_PREVIEW_CACHE_GB`, default 4; 0 turns the cache off). Active or locked entries and temporary checkouts can exceed it; this is not a disk quota. Windows and systems without `lockf`/`flock` always use temporary checkouts. A sparse clone's check uses a full-tree checkout without changing the source's sparse settings. To reclaim the space by hand, stop Room sessions, then for each entry under `room-preview/` run `git worktree unlock <entry>` and `git worktree remove --force <entry>`, then `git worktree prune`.

## Files Room writes

Room never writes a teammate's live edits into your working tree. It writes session bookkeeping in the worktree's Git directory (`room.json`, migrated from root `.room.json`) and choice, relay discovery, local snapshots and a rotating `room-mcp.log` in the common Git directory. The local browser link uses a read-only capability derived from the private key in `room/relay.json`, works only over loopback, and requires a running session. Local memory is saved in `room/relay/*.ydoc`; retained claims remain in local memory, while connected sessions republish current file text. Completed workers keep their final shared publication on normal exit. Local snapshots also retain a bounded read cache of completed workers’ shared files; after a relay restart, these become readable when the live lead confirms the same retained worker and run. Current publications and sharing gaps take precedence. Collection or discard removes that worker’s cache; oldest completed publications are dropped first when the 5 MB snapshot target is exceeded. Cached files never restore live presence or publisher authority. Small revision records survive cache eviction so a stale replica cannot restore an older sharing policy after another restart. `room_leave` preserves memory. `room_close confirm=true` exports the ledger and closes the repository room for everyone; in a local room it also forgets saved memory. Exports go under `.room/ledger/`; worker worktrees and logs go under `.room/workers/`. Room adds `.room/` to Git's private `info/exclude`.

Credentials live in `~/.config/room/credentials.json`, subject to `XDG_CONFIG_HOME` or `ROOM_CREDENTIALS`. `ROOM_LOG_FILE` changes the log location. The log is mode 0600 and rotates at 1 MB with one older generation. Temporary merge directories use the OS temp directory.

When a teammate pushes a commit on your branch, Room can show that your clone is behind. To catch up with uncommitted edits, run `git pull --ff-only --autostash`. If it refuses, get help before trying another Git history operation.

## Updating plugins

Finish active worker batches, update the marketplace and the plugin, then restart the host app and agent sessions. Existing sessions retain their original tools, instructions and hook paths; an installer can remove a versioned cache directory that an old session still uses. Refreshing the marketplace alone is not enough: update the installed plugin too. If a hook definition changes, trust it again when prompted. Codex always runs the installed plugin, including for Codex workers, so a lead running another Room version (a Claude `--plugin-dir` checkout, say) is told at spawn to install its version for Codex or use host `claude`.

```sh
claude plugin marketplace update room
claude plugin update room@room

codex plugin marketplace upgrade room
codex plugin add room@room
```

Codex accepts Git marketplace references such as `owner/repo@ref` and `--ref <REF>` when adding a marketplace. See [the 0.17 upgrade steps](upgrading.md) for the protocol cutover.

For a local-directory Codex marketplace, update its source checkout and run `codex plugin add room@room` directly; `marketplace upgrade` is for Git marketplaces. In a fresh session, ask “is Room set up right?” (`room_state(check=true)`) to verify installed versions, hook trust and the running bundle. If repeated hook-exit warnings began after an update, check whether the old session's hook path still exists and restart before diagnosing the current bundle. Do not disable hooks or change trust to hide a missing-file error.

## Limits and diagnostics

Claims depend on agent cooperation. Coordination messages, including requested review pauses, are advisory: successful delivery does not guarantee compliance or prevent collection. Use the explicit collection review hold described above when a checkpoint is required. The dependency graph infers possible effects; tests establish compatibility. A graph view projects overlays and renders at most 250 files at once. A team room trusts admitted participants, and shared files and history reach the server. Connection failures, stale claims, missing Git bases and files over sharing limits are reported. If a tool is slow, `room-mcp.log` records its phase durations and process ID (a preview's merge line also counts its Git calls). Room does not watch or read wholly gitignored folders: Git lists them when a `.gitignore` changes and at least every 60 s, folders holding tracked files are still searched, and the log says once per change what was skipped, such as `skipped 1 gitignored folder, not watched: libs/JUCE/`. `room_state` shows connection and sharing state; asking “is Room set up right?” requests the setup check. `bin/room-doctor` is also available in a checkout or installed plugin. On Linux, Room names a process by `/proc/<pid>/comm`, then its `argv[0]`, then its executable, so a natively installed Claude Code, which runs from `~/.local/share/claude/versions/<version>`, counts as `claude`.

## Local development

```sh
git clone https://github.com/rohanz/room.git
cd room
npm ci
npm run build
npm run build:plugin
```

Start `HOST=127.0.0.1 PORT=1234 npm run server:dev` and `npm run web` in separate terminals. For a local team-server test, use `ROOM_SERVER=ws://localhost:1234 ROOM_WEB=http://localhost:5173 codex --no-daemon`. Set `GITHUB_CLIENT_ID=fake` on a development server for test login; production refuses it. A repo still needs `room_create` before joining. Without `YPERSISTENCE`, a server restart resets state. Run `npm test`, `npm run typecheck`, `npm run build -w @room/web`, and `npm run build:plugin` before shipping.
