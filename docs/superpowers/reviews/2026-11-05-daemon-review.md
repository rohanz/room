# Local daemon cutover: batch 2 pre-merge review

Date: 2026-11-05. Scope: the uncommitted `local-daemon` working tree, including the new daemon, private-state, cutover and lifetime-test files. Reviewed against the revised daemon specification, its specification review, the plumbing plan's maintainer decisions, and the local upgrade instructions. This is the drained cutover release, not the earlier negotiation release.

## Verdict

Do not merge to main as the cutover release yet. The authority recovery and client retirement paths below violate the revised preservation contract; the inventory can also mistake malformed process evidence for a harmless binding. Windows initialization needs correction and native validation. The separately tracked worker-marker race remains a prerequisite too, but is not counted below.

This was a source review. No tests were run, no existing files were modified, and no commit was made. Test descriptions below distinguish assertions present in the tree from execution evidence. Release checks, native platform runs and the real batch required by the plan are not established by this review.

## Must-fix

1. **Lease-load failure still starts an issuing authority.** `packages/relay/src/index.ts:185` starts the daemon hub through the existing `startHub`; `packages/hub-core/src/hub.ts:267` catches invalid/unreadable lease storage, clears the retained leases and continues startup. Consequently `packages/relay/src/daemon.ts:122` can finish initialization and publish readiness despite corrupt private ownership evidence. Concrete failure: after a daemon crash, the room snapshot is readable but its lease JSON is truncated or temporarily unreadable. The successor advances incarnation and serves with no restored ownership instead of stopping for repair; later lease persistence can replace the failed evidence. The revised spec explicitly requires authority-store failure to be fail-closed. Propagate a typed startup failure or retain a non-issuing recovery state, preserve the original lease file, and test malformed and unreadable lease storage through daemon startup. The existing hub test expecting the “no leases adopted” behavior is not evidence for the revised contract.

2. **Automatic idle retirement still destroys the surviving client replica.** `packages/room-mcp/src/session.ts:1374` makes disposal the default for `leaveSession`, but `packages/room-mcp/src/index.ts:163` invokes `tools.drop` for automatic idle expiry, and `packages/room-mcp/src/tools/state.ts:212` calls `doLeave(s)` without preservation. This path does not call `detachCheckout`. Concrete failure: a daemon dies with an acknowledged post present only in an otherwise idle client; recovery exhausts its bounded retries while startup/storage is unavailable. The host remains alive, but its idle lease later drops the session and destroys that last Y.Doc without an explicit user leave. The next join cannot restore the post. Carry the paused replica through automatic retirement and reuse it on the next join; reserve disposal for explicit leave. Test the actual idle/drop/rejoin chain, not only a direct `leaveSession(..., { preserveReplica: true })` call.

3. **The cutover preflight creates state that the Windows daemon then refuses.** `packages/room-mcp/src/daemon-cutover.ts:180` writes the drain record before launch. Its `writeAtomic` helper creates missing directories through `packages/relay/src/leases.ts:41`, without the Windows private-state initialization. At `packages/relay/src/daemon-bin.ts:18`, `privateStateDirectory` therefore sees an existing directory; `packages/relay/src/private-state.ts:29` passes `created=false`, and line 8 rejects an inherited, unprotected DACL. Concrete failure: first use in a fresh Windows clone whose parent grants only the user/SYSTEM/Administrators still creates an inheriting Room directory during preflight and then fails daemon startup. This does not require an unsafe broad grant. The error occurs before the file logger is installed, so the parent can additionally direct the user to a nonexistent log. Initialize newly created Room state consistently before the drain write, without relaxing the rejection of genuinely unsafe existing state. Validate through the real MCP-to-daemon path on Windows; the synthetic `AclReport` unit test cannot cover creation order or inheritance.

4. **Malformed process-bearing records can be classified as binding-only.** `packages/room-mcp/src/daemon-cutover.ts:141`–`:145` treats any worker with no parsed identity as binding-only unless its outcome is exactly `ambiguous`. Likewise line 129 treats an invalid `hostPid` as absence of process evidence. Concrete failure: a valid-JSON worker record says `launch.outcome: "launched"` but has a missing or malformed PID/process identity and no usable report. The worker may still be running, yet the inventory ignores it for blocking and writes completed-drain evidence. A session with a present but invalid `hostPid` has the same problem. Distinguish genuinely absent binding fields from malformed process evidence; a launched record without a verifiable process must remain unknown and block. Add fixtures for structurally invalid, syntactically valid JSON, alongside the existing invalid-JSON cases. This is separate from the known upgraded-worker marker race.

## Should-fix

1. **Make the rollback stop procedure executable.** `docs/upgrading.md:19` refers to a “supported maintenance path,” but the changed HTTP implementation exposes `/daemon/status`, not a stop command, and the packaged entry has no maintenance CLI. The code has signal-driven save-first shutdown and automatic idle shutdown. Document an actually supported drained procedure, including identity verification, how to request or await shutdown, how to observe save failure and how to establish exit. Do not imply `room_close` stops the daemon or recommend forced termination. This can be documentation rather than a new endpoint.

2. **Remove the retained session-owned lifecycle implementation from the cutover artifact.** `packages/relay/src/index.ts:873` still exports the complete `ensureLocalRelay` creation/takeover loop, including seed, ownership, warnings and owned stop. MCP production calls no longer use it, so this is not an observed fallback route; nevertheless the cutover retains two lifecycle implementations and tests/matrix coverage for the retired one. Keep transport primitives and pinned historical fixtures, but remove or explicitly isolate the old lifecycle instead of shipping it as a current API. The remaining MCP `takeover` argument is name-lease takeover and must not be removed by a blanket grep cleanup.

3. **Complete the failure-boundary coverage and preserve release evidence.** The added tests do not establish the whole revised acceptance contract. Add focused regressions for the must-fixes, simultaneous independent first starts with one key publication, publication failure after bind, lease-flush failure, and recovery from the real 64 MiB protected-memory ceiling with deletion-only repair and unsent client growth. Record the required macOS/Linux runs, Windows smoke and real batch before treating this as a cutover release. Detached Node subprocess survival does not by itself establish survival under supported hosts' termination behavior, terminal closure or Windows process-tree management. Rebuild and verify the committed standalone daemon/plugin assets as part of the normal release checks; this working diff changes the build recipe but does not supply rebuilt committed assets.

## Noted—not blocking independently

- **Known worker-marker race:** arbitration marker stamping versus the binding move can classify this release's workers as legacy in the three reported auto-join cases. Excluded from the numbered findings and not investigated further; its separate fix must land before release.
- **Exclusion and drain:** both daemon starts and the retained old implementation use the common-directory authority lock. A draining daemon retains that lock. The idle callback checks the writer clock and synchronously sets the admission fence before awaiting lease flush; secure handshake completion, negotiation after hub readiness, ACK attachment and ready attachment check that fence. Final-save failure reopens admission and retains the listener/documents/authority with bounded retries. I found no source path allowing two conforming daemon children to own the clone merely because readiness is false during drain. Unknown/live birth identity is not reclaimed by a timeout.
- **Snapshot failure states:** corrupt/unsupported/oversized snapshot loads throw rather than silently initialize empty memory. Periodic save failures distinguish capacity and I/O, preserve in-memory state and retry without another update. Capacity feeds hub/full and non-growing-update admission; I/O alone does not blanket-disable writers. These observations do not prove the full capacity-repair/export scenario. Initial-room load failure aborts startup; it does not expose a running recovery/export service for that unreadable room.
- **Launcher and readiness:** the transport child uses `process.execPath`, an absolute entry path, argument arrays, `shell:false`, ignored stdio, detachment/unref, an environment allowlist, and the canonical common directory as cwd rather than a removable worker worktree. The Windows ACL subprocess is a separate bounded inspection, not a shell used to launch the daemon. Native survival remains an acceptance question. Health metadata for the daemon is nonce-MAC authenticated, and the readiness path checks clone, runtime, required `room.daemon` capability and discovery/listener PID agreement before returning a client handle. A PID mismatch refuses rather than authorizing takeover.
- **Client recovery:** MCP has no `ensureLocalRelay` call, startup seed or relay takeover interval. Its local `stop()` handles are non-owning no-ops. Same-port and fallback recovery change transport references on the existing provider/Y.Doc; the same-port connected branch also refreshes `Session.local`, including PID. Host rebind explicitly carries the replica, and local generation mismatch pauses rather than replaces it. `room_close` passes preservation after authorized forget. These paths do not cure the automatic idle-drop finding above.
- **Viewer and legacy behavior:** viewers have no daemon-launch route and are excluded from the writer idle clock. Old writer sockets lacking negotiation are refused before `attachReady`; negotiating clients lacking `room.daemon` fail selection before sync. Read-only compatibility remains a distinct path. The hub's base advertisement intentionally does not globally require the daemon capability for team servers and retained relay fixtures.
- **Cutover evidence and forgery:** the drain record stores version, clone hash, time, optional key fingerprint, dead-owner identity and disregarded binding paths. Reuse still follows a fresh inventory, so a stale or fabricated record alone does not bypass live-owner/client checks. It is not authenticated checkpoint evidence or proof that unrecorded hosts were drained. Same-user clone-key holders are within the stated trust domain. Inventory errors and unauthenticated daemon-owner claims block; binding-only files are intentionally not blockers. Refusal rows include owner PID/port where available. Finding 4 concerns invalid process fields being incorrectly put in that binding-only category.
- **Matrix:** the plan adds each pinned old client against the new daemon plus a candidate/candidate daemon pair. The fixture checks explicit refusal, no successful provider sync, no incoming sync/awareness frames and no false populated room state for incompatible old clients. This is receiver-side refusal evidence; an old non-negotiating client can still attempt an outgoing sync frame. The matrix is not a mixed-runtime cutover inventory test or a real host lifecycle test, and it was not executed in this review.
