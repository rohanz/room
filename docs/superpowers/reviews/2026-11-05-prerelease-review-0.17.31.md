# Room 0.17.31 pre-release review

Reviewed the uncommitted changes against HEAD, including the listed untracked source and test files, against CLAUDE.md's engineering priorities and the seven Unreleased bullets. No full suite or release checks were run. Three focused inline probes exercised audit rotation, log replacement and preview cleanup on macOS arm64 / Node 22.14.0; their temporary fixtures were removed. Findings below distinguish those reproductions from static control-flow findings.

## Must-fix

1. **Non-leads can still start the relay.** `packages/relay/src/index.ts:746`, `packages/room-mcp/src/session.ts:955`. The no-relay path rejects only `joinOnly`, not `lead === false`. A manually launched or nested host with scrubbed ROOM_* variables in a Room worker worktree is classified as non-lead but starts the clone's relay if the lead is absent. This contradicts the release's lead-only ownership contract and recreates ownership by a worker-side process. Enforce lead-only creation as well as takeover; the new ownership test currently explicitly expects this exception.

2. **Handover destroys the only replica after a failed memory save.** `packages/relay/src/index.ts:697`, `packages/relay/src/index.ts:602`, `packages/relay/src/memory.ts:146`. Handover clears ownership and closes the relay unconditionally; `RoomMemory.flush()` discards `saveMemory()`'s failure result. If a writer disconnects after delivering a claim/message and the final save fails (for example ENOSPC), a newly joining lead has no replica yet, loads the old snapshot, and the old relay destroys the only current document. Make successful state transfer a prerequisite for releasing ownership. `relay-owner.test.ts` proves successful persistence of a pre-handover claim and reconnect, not failed persistence or preservation of every live document type.

3. **A pending collection ignores an explicit keep request.** `packages/room-mcp/src/tools/collect.ts:798`. After an ordinary collect retains a checkout for an unconfirmed exit, the user can call `room_collect(tag=..., keep=true)` once the host exits. The pending branch invokes `finishPendingCollect` before the keep path, which removes the worktree and retires the record instead of retaining it for follow-up. Handle keep under the operation lease, cancel pending automatic cleanup and preserve the collected baseline; add a pending-to-keep regression.

4. **Audit rotation can report missing history as complete.** `packages/server/src/store.ts:276`. The reader captures the pruned marker before awaiting the current-file open, then enumerates segments after rotation may have pruned them; missing segment opens are also silently ignored at line 270. Reproduced with one retained segment: write events 1 and 2, rotate with event 3 immediately after opening audit.log, then read the full tail. Result was only event 2 with `complete: true, gaps: []`, although event 1 existed when the read began and was deleted during it. Establish a consistent segment/retention generation or detect changes and return an incomplete result; cover `readAllAudit` through the same helper too.

5. **A rewritten log can retain false acceptance evidence.** `packages/room-mcp/src/run-log-facts.ts:95`. Same inode plus larger size is treated as proof of append-only modification. Reproduced by caching an assistant event for session `old`, then overwriting the same file with a longer event for `new`: the returned session set remained `[old]`. Truncate-and-regrow between projections can therefore keep a stale answer or falsely satisfy `resumeAccepted`, while parsing begins in the middle of the replacement. Validate the consumed prefix or use a reliable log-generation contract before reusing facts. Existing replacement tests cover rename and shrink, not longer in-place replacement.

6. **Cleanup deadline releases a cache still used by an escaped child.** `packages/room-mcp/src/tools/files.ts:1391`, `packages/room-mcp/src/preview-cache.ts:75`. On `PreviewCleanupIncomplete`, calling release closes the lock helper's input; it waits only for recorded process groups. A detached descendant can retain the preview cwd and stdout after that group dies. Reproduced with a detached `sleep 30` and the 500 ms test seam: the first check returned incomplete, then a second check reset and ran in the identical cached path while the child was still alive. Quarantine the entry when pipe ownership/liveness is unresolved, or track the surviving owners before releasing it. The escaped-pipe test uses an uncached tree and misses this reuse.

## Should-fix

1. **Bounds silently remove coordination from legitimate edits.** `plugins/room/hooks/common.mjs:45`, `plugins/room/hooks/before-edit.mjs:13`. A valid tool input exceeding 32 MiB, or arriving after two seconds on a loaded host, becomes `{}` and exits successfully without delivering claims, pauses or inbox context. Logging to stderr/debug output does not put the missing coordination in the agent's context. Preserve bounded routing metadata or emit an explicit coordination-unavailable result that the host/agent sees; test a large valid Write and a slow valid input, not only bounded allocation.

2. **Persistence queues bound values but not pending acknowledgements.** `packages/server/src/store.ts:156`, `packages/server/src/store.ts:193`. Every coalesced save or same-session operation still appends a new waiter. With a stalled Postgres write, repeated registry snapshots or repeated logouts of one token grow these arrays indefinitely despite the distinct-session cap. Share the acknowledgement promise for a coalesced generation or bound admissions without discarding owed revocations. The queue tests bound snapshots/keys, not retained waiters.

## Noted-not-blocking

- **Relay authentication and compatibility boundary:** `/handover` checks loopback and the clone-key proof; `lead: true` is a caller assertion, not a separate authorization capability. Dispatched workers are join-only, and a lead-less clone makes those workers wait. The older-owner path joins with a warning and waits for owner exit; this is not an immediate forced takeover. No host feature assumptions were needed for this review.
- **Collection evidence limits:** pending cleanup and the sweep use the same non-reentrant operation lease, including a fresh record check. Legacy adoption selects the exact old kept reason and rechecks it under the lease. The shared-checkout path deliberately retires the owner while a live borrower holds the checkout; the invariant must describe that exception. `justCollected` skips the comparison because merge results may legitimately differ from worker bytes; the lease serializes Room operations, not arbitrary external writers. It is not proof that nobody can write between application and removal.
- **Server persistence:** SessionWrites preserves call order across batches and coalesces per-key operations; Auth retains failed known and unloaded-session logout deletions for retry. A busy rejection is not a successful durable logout. Settings default on absent/empty values and reject explicit invalid values. OIDC refresh has a cooldown, so an unknown key immediately after a successful fetch can remain rejected until that cooldown passes.
- **Bounds and lifecycle coverage:** Git stream overflow rejects with a typed incomplete-result error; migration over-budget sources keep migration pending, and watcher overflow requests reconciliation. PR publication checks generation, cancellation and session closure after fetching. These observations do not establish end-to-end recovery under every storage or process failure.
- **Hook and refactor scope:** `git diff --stat -- plugins/room/hooks.json` was empty. Malformed select replies are not confirmed, leaving messages owed. Named-option and logger extraction did not yield a separate finding; the collection and cache behavior changes above should not be treated as covered by the “no behaviour change” description.

Must-fix count: **6**. Should-fix count: **2**.
