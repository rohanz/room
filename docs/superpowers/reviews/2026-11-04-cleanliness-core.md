# Core cleanliness review — 2026-11-04

Scope: `packages/shared/src`, `packages/hub-core/src`, `packages/relay/src`, `packages/roomd/src`, and `packages/server/src`. Read against `CLAUDE.md`, `README.md`, `docs/reference.md`, and the roadmap. This is a source review: the failure scenarios below are deductions from the cited paths, not runtime reproductions. No source changes, tests, builds, commits, or pushes were requested or performed; typecheck evidence is recorded below. Rankings reflect privacy, availability, recovery, and then maintenance cost. Experimental identity enforcement is distinguished from the default, trusted-member observe mode.

## Top ten

1. **High — A failed `.roomignore` read widens sharing silently.** `packages/roomd/src/index.ts:640-646` initializes text to empty and catches every read failure as “none”; a false safety check has the same outcome. `reloadRoomIgnore` at line 1426 immediately applies that empty policy. A temporarily unreadable ignore file can therefore authorize previously excluded tracked content. This contradicts the exclusion promise in `README.md:49`. **Smallest fix:** distinguish `ENOENT` from unsafe/unreadable input, retain the last successfully read policy on other failures, mark publication incomplete and diagnose once; at initial startup refuse file-text publication until the ignore policy is known. An intentional deletion can still select an empty policy. Bound the read too (finding R1).

2. **High — Session storage is neither atomic nor honest about corruption.** `packages/server/src/store.ts:125-130` truncates and rewrites the live credentials file, although this module already has `writeAtomicFile`. `readJson` at line 102 swallows every parse/I/O error; `loadSessions` at line 121 converts that into an empty authoritative map. `Auth.reconcileSessions` (`packages/server/src/auth.ts:326`) then revokes all active sessions on a transient read/parse failure. The same helper makes an unreadable room registry look empty (`store.ts:108`), allowing later saves to replace recoverable state. **Smallest fix:** atomically replace sessions with the existing 0600 writer; treat only `ENOENT` as absence, propagate corruption/read failures, preserve the previous in-memory state, and return a storage-unavailable diagnostic instead of applying an empty reconciliation.

3. **High in enforce mode; medium by default — The identity guard duplicates an obsolete overlay schema.** `packages/server/src/readonly.ts:201,265-268,303-319` treats every `overlays` key as a participant name, passing it to `ownsName`. Current writers use `manifestKey(name, fence)` (`packages/shared/src/manifest.ts:65`; `packages/roomd/src/publisher.ts:337`), containing NUL, which `validParticipantName` rejects. Ordinary overlay additions/edits can thus create false violation diagnostics; experimental enforce mode drops the complete update. Conversely, `manifest`, `manifestHead`, and `workerViews` are absent from the explicit guarded roots. **Smallest fix:** share schema ownership/key decoding in `shared`, distinguish fenced overlays from bare-name maps, and explicitly define coverage for current roots before advertising enforce mode. Keep the documented trusted-member limitation; this is not a claim that observe mode provides isolation.

4. **High over server lifetime — Audit reads allocate the entire ever-growing audit on the main thread.** `packages/server/src/store.ts:136-151` appends forever, then implements a limited `/audit` query by synchronous `readFileSync`, split, parse, filter and slice of the entire log. The route's result limit (`packages/server/src/index.ts:596`) bounds only the response, not the read or transient memory. A routine admin query can stall all rooms or exhaust memory after long operation. **Smallest fix:** stream bounded chunks/lines, keep only the requested tail, enforce an explicit scan-byte/deadline budget and report truncation. Add an operator retention/rotation policy that preserves migration-evidence completeness; do not silently prune evidence and still call it complete.

5. **Medium-high — GitHub pagination failures become successful incomplete coordination data.** `packages/server/src/github.ts:67-79` breaks on failures after page one and reports `{items}` without completeness; hitting a page ceiling also looks complete. `fetchPrs` at line 131 turns a failed file-list request into an empty list. More consequentially, `upsertNote` at lines 155-162 can create a second ledger comment when a later comments page failed or the search ceiling hid the existing one. **Smallest fix:** return completeness/truncation with paged results; propagate failed PR file enumeration as unavailable coverage, and refuse comment creation unless the search completed or found the existing comment. This preserves page ceilings without presenting partial evidence as absence.

6. **Medium-high — Streaming Git helpers have no byte budget.** `packages/roomd/src/git.ts:148-161,210-223` retain every stdout chunk and unbounded stderr, then concatenate; `packages/roomd/src/disk-scan.ts:17-27` repeats that pattern. Timeouts bound duration, not bytes. `gitShowManyCapped` limits admitted normal blob groups, but exported uncapped `gitShowMany` and metadata/ignore enumeration still lack a hard allocation guard. **Smallest fix:** count bytes before retaining each chunk, cap diagnostic stderr separately, terminate the specific child on overflow, and reject with a typed “incomplete/too large” error. Derive blob-batch limits from the already known blob sizes; chunk path inventories rather than lifting the cap. Keep timeout/overflow completion tied to child close so callers do not outlive unmanaged Git work.

7. **Medium-high — Watcher backlog is unbounded and its scheduler can throw on wide checkouts.** `packages/roomd/src/disk-batch.ts:38-43` retains one pending entry per distinct path without a ceiling; line 86 spreads every pending path into `Math.min`. A sufficiently wide burst reaches the engine's argument limit and throws from an event callback, in addition to retaining a large backlog. Continuous arrivals also extend the global settle deadline indefinitely. **Smallest fix:** compute the minimum in a loop, impose a maximum settle latency, and collapse overflow into one full-reconcile flag with a bounded per-path set. A full reconcile already exists, so this does not require dropping file changes or inventing another queue.

8. **Medium-high — Legacy local migration decodes every snapshot, even unchanged ones, with no size or aggregate bound.** `packages/relay/src/local-migrate.ts:95-100` synchronously reads/applies every source to a Y.Doc before the mtime skip at line 170. `packages/relay/src/index.ts:539-547` calls catch-up every second while migration is pending; a surviving legacy relay therefore makes unchanged archives recurrent CPU/allocation work. Unlike `loadMemory`, this loader has no file ceiling, and all decoded docs remain live together. **Smallest fix:** enforce per-file, file-count and aggregate budgets before decoding; retain a bounded per-source identity summary keyed by observed revision so unchanged files need not be decoded again. Preserve the monotonic ambiguity evidence in the existing ledger; do not simply skip the identity pass and change its semantics. Dispose temporary documents in `finally` on every failure.

9. **Medium — Documented participant expiry configuration has no path to the expiry authority.** `packages/shared/src/views.ts:7` fixes seven days; `packages/shared/src/expiry.ts:61,89` uses that constant for deletion and the message. `packages/hub-core/src/hub.ts:269` creates `ExpiryTenure` without a threshold. Yet `docs/reference.md:140` and the README defaults promise that `ROOM_STALE_DAYS` changes destructive expiry; MCP parses it at `packages/room-mcp/src/config.ts:140`. **Smallest fix:** decide one authority-owned threshold and pass it explicitly into expiry/view policy, or remove the unsupported setting and dead config. Do not independently read each participant's environment to choose a shared destructive policy. Coordinate the public contract decision with the lead.

10. **Medium — Relay ticket body handling lacks an owned deadline/concurrency budget and uses stale authentication time.** `packages/relay/src/index.ts:483-509` manually buffers bodies with a 4096-character limit, no explicit per-read deadline or in-flight reader cap, and authenticates the completed body against `now` captured when headers arrived (line 486). Slow requests can extend a view proof's acceptance beyond its intended window and mint already-aged tickets. Runtime HTTP defaults are not the reference's explicit ten-second body contract (`docs/reference.md:156`). **Smallest fix:** extract/reuse the transport-neutral bounded body reader pattern with byte counting, read deadline, cancellation/error cleanup, and admission slots; recompute time immediately before proof verification and ticket issuance. Continue using the smaller local body allowance.

## Remaining findings by package

### Shared

**S1 — The extensible message registry and validator disagree.** `packages/shared/src/types.ts:114` advertises an extensible `MessageMap`; `messages.ts:191` permits registration. But `validMessageShape` (`messages.ts:94-129`) has a separate built-in field table and switch, so a registered extension still fails hub admission and trim validation. The mutable exported registry can also be replaced without changing validation. **Fix:** attach a validator to each registered kind and derive dispatch from that registry, with explicit duplicate/override policy. Keep builtin payload typing; no new schema framework is needed.

**S2 — Schema ownership rules are repeated as raw root names.** `packages/shared/src/doc.ts:225-247`, `expiry.ts:81-90`, `memory.ts:17-37`, `worker-memory.ts:32-51` and the server guard independently enumerate owned roots and synthesize NUL keys. Some differences are intentional (memory must omit live publications), but there is no common ownership descriptor making those distinctions explicit. Finding 3 demonstrates the maintenance cost. **Fix:** centralize root names and participant/fence key helpers, then give persistence, retirement, expiry and guarding their own explicit allowlists built from those constants. Do not make one indiscriminate “delete all roots” routine.

**S3 — Destructive ledger trimming is a long multi-phase function.** `packages/shared/src/delivery.ts:134-222` combines invalid-record removal, bus retention, mail eligibility, owed quotas, outcomes, archival and receipts. At roughly 89 lines it exceeds the requested review threshold and makes ordering changes hard to audit. **Fix:** extract the pure retention/quota decision stages into named helpers returning one plan; preserve the existing transaction order and idempotence. This is a maintenance finding, not evidence that the current trim loses messages.

### Hub core

**H1 — `adoptSynced`'s name and contract describe ownership it deliberately does not adopt.** `packages/hub-core/src/hub.ts:488-497` says it carries/ends earlier holders, but the function only raises `lastEpoch`/`lastSeq`; private `adoptStored` is the ownership source. Call-site comments at lines 276 and 480 also retain adoption-era wording. **Fix:** rename it to `observeCounterBaselines` and document that replicated holders never grant ownership. Remove the unused `MessageKinds` import at line 7 while touching this code. This matters because copying the comment's purported behavior would undo an important trust boundary.

**H2 — Invalid-frame logging copies arbitrary member content into logs.** `packages/hub-core/src/hub.ts:548` logs the first 200 characters of serialized input. Truncation bounds length but does not prevent private message text or arbitrary sensitive fields being logged. **Fix:** log frame byte length, safe bounded operation/request ID when valid, and the rejected field/category, rather than the raw object. Retain the useful rejection count and reason.

### Relay

**L1 — Awareness budget logic and wire classification are duplicated across hosts.** `packages/relay/src/awareness.ts:5-80` and `packages/server/src/readonly.ts:46-119` separately decode awareness payloads, count added IDs, enforce sizes and prune tombstones; defaults are repeated in `packages/server/src/limits.ts:12-21`. They already differ: relay uses sets for within-frame IDs while server counts an array. State-request recognition and rate limits are likewise repeated (`relay/src/index.ts:53-65`, `server/src/readonly.ts:392-435`). **Fix:** extract pure plaintext frame classification and budget accounting into hub-core; keep encrypted-relay and emit-wrapper adapters host-specific. Preserve intentional per-host admission differences.

**L2 — Relay output budget ownership is process-global rather than relay-owned.** `packages/relay/src/index.ts:82-88` keeps socket accounting, aggregate bytes and reservation state at module level. `capacityFor` at line 97 may evict sockets belonging to a different `startRelay` instance in the same process. An intentional process budget is reasonable, but this hidden singleton also couples tests and instance shutdown. **Fix:** wrap accounting in an explicit budget object injected into each relay; choose a documented shared instance only when process-wide sharing is intended, and give it deterministic detach/cleanup.

**L3 — A health probe's socket timeout is not a total operation deadline.** `packages/relay/src/proof.ts:48-66` uses `http.get({timeout})`, which is an inactivity timeout. A foreign listener can drip a small health response and delay relay discovery far beyond the requested 2.5-second probe, or abort its response without the promise's end/error paths being complete. **Fix:** use a separate absolute deadline, settle once on response `aborted`/`error`/premature close too, clear listeners/timer on settlement, and destroy this request on the byte cap/deadline.

**L4 — Unconditional losslessness comment contradicts the recovery contract.** `packages/relay/src/index.ts:11-12` claims every restart “loses nothing.” `docs/reference.md:41` correctly limits delivery to surviving replicas and acknowledges delayed local persistence; snapshots shed droppable history too. **Fix:** state the surviving-replica condition and link the recovery contract. This is a misleading guarantee in the main relay entry point, not a formatting nit.

**L5 — Warning suppression retains room paths forever.** `packages/relay/src/memory.ts:11-17` stores every warning key in a module-global map, never expires/removes entries, and can suppress a different logger/relay instance's first warning. **Fix:** scope the limiter to `RoomMemory` or use a small TTL/LRU map with eviction on close. Keep the existing one-minute cadence.

### Room daemon

**R1 — Policy/control files bypass normal content read limits.** `packages/roomd/src/index.ts:642` reads `.roomignore` synchronously without a byte limit before constructing regex rules; `index.ts:807` similarly loads Git's exclude file, and `room-file.ts:14` loads session metadata unbounded. Publication's 512 KiB limit does not govern these reads. **Fix:** add small explicit control-file limits and a bounded descriptor read, validate JSON shapes, and diagnose oversized/unreadable policy without widening sharing (finding 1). Give `.roomignore` a pattern-count limit as well as a byte cap.

**R2 — Lifetime caches lack repository identity or eviction.** `packages/roomd/src/disk-scan.ts:44-52` caches object format forever by directory string: replacing a repository at the same path can reuse an obsolete format. `packages/roomd/src/base.ts:217-234` never removes `(dir, SHA)` fetch-attempt entries after the five-minute suppression expires. **Fix:** own object format on a daemon's verified checkout identity, and expire/cap the retry map (or scope it per daemon) while preserving the five-minute retry rule.

**R3 — Error de-duplication stores every distinct error indefinitely.** `packages/roomd/src/publisher.ts:72,150-154` keeps complete error strings in a set for the daemon lifetime. Errors containing changing SHAs/paths can grow it without bound; a recurring identical error after recovery is suppressed forever. **Fix:** use a bounded recent error-class/time cache and reset recovered classes; retain total failure/recovery counts rather than all message text.

**R4 — Publication preparation combines too many independent stages.** `packages/roomd/src/publisher.ts:167-296` handles checkout facts, carried blobs, base budgets, replanning, overlay diffs, stale checks and deletions in one ~130-line method. `packages/roomd/src/disk-scan.ts:71-158` takes eight positional arguments and combines enumeration, policy filtering, file identity checks, hashing and text budgeting. **Fix:** give `readDisk` one options/context argument and extract bounded carried-base reading and publication-diff preparation as helpers. Keep the captured inputs/fence and final synchronous publication gate explicit; do not move safety checks across awaits casually.

**R5 — Whole-tree timeout policy is bypassed by full reconciliation.** `packages/roomd/src/disk-scan.ts:55-60` calls ordinary `git` for whole-tree diff/inventory, using the fixed 30-second default. Related inventory operations use `gitWholeTree` (`git.ts:40-46,259-278`) with a path-sensitive bounded deadline. **Fix:** use that existing helper with known inventory size so a large supported repository does not enter repeated full-scan failure/retry despite the more appropriate timeout policy already being available.

**R6 — Watcher cleanup failures are silently discarded.** `packages/roomd/src/checkout-watch.ts:82` ignores handoff-disposal errors; `index.ts:635` catches watcher close errors without reporting. These are ownership operations whose failure can leave native watches active or hide a resource problem. **Fix:** route cleanup failures through the existing bounded daemon logger and retain a close promise/result that shutdown can inspect. Do not report an expected “already closed” result as a failure.

### Hosted server

**V1 — A static-file stream error can escape the request handler.** `packages/server/src/index.ts:932-937` checks a file, then calls `fs.createReadStream(file).pipe(res)` without an error listener. Deletion, permission change or disk I/O failure after the check emits asynchronously, outside the surrounding `try/catch`; an unhandled ReadStream error can terminate the process. **Fix:** use `pipeline` with a handled rejection or explicit stream error cleanup, destroying/ending that response and logging a bounded diagnostic.

**V2 — Admission collapses upstream uncertainty into a permission denial.** `packages/server/src/admit.ts:113-114` treats `canPush(...) === undefined` as false and says the user cannot push. The checker deliberately returns undefined for GitHub rate limits, timeouts and malformed replies (lines 54-73); the connected-session revalidator correctly preserves that distinction (`packages/server/src/index.ts:441-451`). **Fix:** branch explicitly on true/false/undefined, propagate an unavailable/503 verdict, and never cache or describe an uncertain answer as access revoked.

**V3 — OIDC caches make routine key/endpoint rotation require waiting or restart.** `packages/server/src/auth.ts:192-212` caches discovery for the process lifetime and JWKS for ten minutes; verification at line 253 creates a local key set from that snapshot and never refreshes on an unknown key ID. A valid token signed with a newly published key can fail for the remainder of that cache period; changed discovery endpoints remain stale until restart. **Fix:** retain bounded caching/coalescing but refresh once on unknown signing key, and give discovery a finite refresh policy. Do not retry invalid signatures indefinitely.

**V4 — Successful logout does not establish durable revocation.** `packages/server/src/auth.ts:309-316` deletes the in-memory session and fires a persistence promise whose rejection is only logged (`auth.ts:117-119`). If that delete fails, a restart can reload the still-stored bearer token after logout reported success. **Fix:** make the logout endpoint await deletion before acknowledging durable success, returning a retryable persistence failure when necessary. Local sockets can close immediately. Similarly, distinguish a newly issued but unpersisted login from one guaranteed to survive restart.

**V5 — Persistence queues have no backlog/backpressure contract.** `packages/server/src/store.ts:51-57` chains every write and `saveRooms`/`writeSessions` capture whole serialized tables before enqueueing (lines 113-126); PgStore serializes each whole-registry replacement too (lines 203-221). A slow database can retain many redundant full snapshots. **Fix:** coalesce pending replace-all room/session snapshots where semantics allow, bound non-coalescible session operations, and reject new work with an unavailable result when saturated. Preserve acknowledgement and write ordering; do not coalesce away required revocations.

**V6 — Configuration can accidentally disable resource limits.** `packages/server/src/index.ts:135-151` converts capacity and byte-budget environment values with bare `Number(...)`; NaN makes comparisons such as `active >= maxActive` false (`packages/server/src/http.ts:51`), silently defeating the intended cap. Infinity and negative values also have inconsistent effects. **Fix:** share a finite positive-integer/byte parser and fail startup for invalid explicit settings; preserve intentional zero/off semantics only where documented. Relay's `capacity` helper demonstrates the existing validation pattern.

**V7 — The entry point's mutable state and oversized handlers obscure lifetime ownership.** `packages/server/src/index.ts:465-947` is a roughly 480-line HTTP callback and lines 1044-1202 a roughly 160-line upgrade callback, closing over module-global registries, queues, meters and timers. `dropLog` (line 969) and `identityLog` (line 1027) have no eviction; some other caches clear only on explicit room close, rather than document destruction. `ServerHubs.compactionDecided` (`server/src/hub.ts:129`) also retains closed room names indefinitely. **Fix:** first extract route-group handlers receiving a single explicit server context, retain timer handles in that context, and make room-close/process-stop cleanup own their caches. Bound throttle maps independently. No framework or transport rewrite is necessary.

**V8 — Atomic writers can leave orphan temporary files before rename.** `packages/server/src/store.ts:13-18` and `packages/server/src/hub.ts:43-50` clean up rename failure but not a failure in the preceding write/fsync block. Repeated disk trouble accumulates private temp files. **Fix:** wrap the complete temp-file lifetime in `try/finally` that removes the temporary path on every unsuccessful replacement; keep descriptor closure and directory fsync semantics unchanged.

## Evidence and limits

Read-only inspection and targeted reference/caller searches were used. No runtime fault injection, socket suites, benchmarks, full tests, plugin rebuilds, or live host-feature assumptions are part of this review. Existing bounded designs were considered: document metering is intentionally approximate; room admission retains idle docs deliberately; `CoalescedPoll` has a stop owner/backoff; watcher handoffs have a TTL; publication uses captured inputs/fences and bounded normal file reads. Those are not reported as missing mechanisms merely because they use timers or caches.

`npm run typecheck` completed without TypeScript diagnostics. The requested `nice -n 10` wrapper reported `setpriority: Operation not permitted`, so scheduling priority could not be applied; no heavy tests were run. Git inspection showed no tracked source changes and only the requested review report as an untracked deliverable. Typecheck generated ignored workspace build output, which Room excluded from preview/collection.

Current named peer preview with `rohanz+clean-mcp` and `rohanz+clean-tests` was conflict-free; no combined runtime check was needed for independent review documents. The MCP reviewer confirmed that its current historical-text callers use bounded per-blob reads, so finding 6 does not assert an uncapped MCP text-read path. It also confirmed `config.staleDays` is used only for offline-claim display marking in `tools/scope.ts:321,378`, reinforcing finding 9's deletion-contract mismatch. Runtime-severity labels remain source-based; a follow-up implementation should reproduce each selected failure with a focused regression before changing its mechanism.
