# Must-fix

1. **The proposed success boundaries still receipt before delivery.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:251`, `:246`; code `plugins/room/server/room-mcp.mjs:42532`, `packages/room-mcp/src/worker-process.ts:84`, `packages/room-mcp/src/worker-launch.ts:81`. The shipped transport resolves `send()` immediately when `stdout.write()` returns true, without a write callback or error rejection. Small reply buffered → receipt committed → process killed before flush → lost inbox item. Likewise `proc.started` means Node's `spawn` event (possibly for `nice`), not acceptance of the resume prompt: host starts, rejects authentication/session/arguments, exits → all included backlog gets false `prompt` receipts. Specify a flush/error-aware transport and a host prompt-acceptance boundary; distinguish handoff from model acknowledgement and narrow the claimed guarantee accordingly.

2. **Broadcast cursor advancement can lose an unsent batch.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:198`, `:389`; code `packages/room-mcp/src/tools/index.ts:86`, `packages/room-mcp/src/tools/messaging.ts:317`. `take()` advances past judged broadcasts, while receipt commit waits for send. Select broadcast interrupt M → persist cursor past M → cancel or crash before send → restart preserves cursor, so M is excluded despite no receipt. Stage cursor changes with the batch, distinguish rejected-by-routing from selected-for-delivery, and advance delivered candidates only after successful handoff. A filtered `take()` must not skip another eligible message it did not include.

3. **Post-send receipts need delivery arbitration, including within one reply.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:239`, `:240`, `:246`; code `packages/room-mcp/src/tools/messaging.ts:215`, `packages/room-mcp/src/tools/index.ts:93`, `plugins/room/hooks/before-edit.mjs:71`, `packages/room-mcp/src/tools/messaging.ts:161`. Wait selects M without committing → wrapper calls inbox while M is still unseen → M appears in both the wait body and inbox prefix. Two concurrent tool calls or hooks similarly select M before either records it. Newly resumed worker can consume existing backlog while the lead is still recording prompt receipts. Specify one owner for an in-flight batch, union selected IDs for each response, and an explicit lead-to-worker delivery handoff. Temporary reservations must be reclaimable and must never masquerade as receipts.

4. **The hook outbox is explicitly a second seen set.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:172`, `:241`; code `plugins/room/hooks/before-edit.mjs:70`, `packages/room-mcp/src/hooks-bridge.ts:130`. MCP dies with fresh snapshot listing M → first hook prints M and appends → next hook reads that local line and suppresses M although CRDT has no receipt. This directly contradicts R2, regardless of calling the file an outbox. Conversely, hook reads snapshot before a tool receipts M → tool sends M → hook prints its stale copy. Require live arbitration against the ledger for content delivery, or explicitly defer content while that authority is unavailable; do not claim the local filter implements CRDT-only send-iff-unseen.

5. **Migration fabricates receipts for genuinely unread messages.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:230`, `:373`; code `packages/room-mcp/src/tools/join.ts:91`, `packages/room-mcp/src/tools/messaging.ts:209`, `packages/shared/src/doc.ts:504`. Q addressed to offline P → old join hides Q in memory → P receives later M → migration finds M's receipt and marks Q `legacy` → Q is permanently suppressed without delivery. A newest receipt is not a contiguous acknowledged prefix. Import only evidenced receipts; accept replay for uncertain legacy history. Also preserve `syncHookSeen`'s actual conditional at `hooks-bridge.ts:137`: an explicit foreign `shown[id]` must not be overridden by `m.to === me`, as the spec's stated OR rule allows.

6. **Pending-mail bounds do not bound pending delivery.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:119`, `:130`, `:483`; code `packages/shared/src/doc.ts:458`, `:464`, `packages/relay/src/memory.ts:36`. Send 10,000 unanswered questions to offline P → all remain on bus → none reaches `mail`'s 500-entry/14-day limits. Even notes below the bus cutoff threshold never reach mail expiry. Per-recipient counts also leave recipient cardinality and message bytes unbounded; a >5 MiB snapshot is skipped entirely by the local relay, so restart can lose pending mail. Apply an explicit count/byte/age policy to bus ∪ mail and define admission/backpressure or durable expiry outcomes. Preserve question validation in a bounded independent index if needed.

7. **The mixed-version window knowingly preserves message loss.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:355`, `:362`, `:364`; code `packages/roomd/src/index.ts:986`, `packages/shared/src/doc.ts:455`, `packages/shared/src/memory.ts:5`. Old sorted-first trim leader removes an unread answer → no new client can reconstruct it. More seriously than the stated repeat risk, an old relay excludes the entire new `mail` root from its snapshot → full local-room restart permanently loses pending addressed messages already moved there. A `meta` field that old clients ignore cannot refuse them. Gate the schema transition on relay/server admission plus disconnection of incompatible writers before moving messages; read-only backward display compatibility is separate from mixed write compatibility.

8. **The bind mark makes wake recovery edge-dependent again.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:265`, `:270`; code `packages/room-mcp/src/hooks-bridge.ts:278`, `:357`, `packages/room-mcp/src/tools/messaging.ts:259`. M arrives, wake fails, MCP restarts inside the same idle host → new bind mark is after M → M is forever excluded from wake retries. SessionStart already happened and cannot display the promised pending count. Similarly, pending wait suppresses all wakeable messages, then cancellation removes suppression without bus/receipt/binding change; the conditional timer may be off. Persist the original session boundary, reconcile on wait completion/cancellation and reconnect, and retry owed unwoken messages after a restart.

9. **Strict single-holder and single-writer assumptions are false.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:93`, `:104`, `:135`, `:400`; code `packages/room-mcp/src/session.ts:312`, `packages/roomd/src/index.ts:986`, `packages/roomd/src/index.ts:735`. Lead clarification of R1a: cross-machine ownership is eventually consistent; each process must fence itself against `participants[me].sessionId`. Partitioned A and replacement B can both act as P. If A's HEAD contains base C and B's does not, A's unfenced `moot` receipt can hide C from B without either delivering it. All selection, wake, commit, outbox-fold and prompt operations need the registry's holder/fencing contract; stale snapshots must stop delivering. Also assign receipt-writer ownership during resume, and trim authority during partition: awareness-sorted leadership permits two trimmers and lost read-modify-write archive counts. “Whoever delivered” and LWW do not satisfy R5's single-writer rule.

10. **Notice claims are still pre-delivery acknowledgements.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:163`, `:242`, `:435`; code `plugins/room/hooks/common.mjs:84`, `plugins/room/hooks/session-start.mjs:37`, `packages/room-mcp/src/index.ts:120`. Hook creates `notices/id` → crashes before stdout → MCP finds the file and suppresses the sharing/startup notice forever. `O_EXCL` arbitrates ownership, not successful delivery. Separate recoverable claim from post-handoff completion, or apply the ledger rule to synthetic notice messages; test owner death, not only two successful racers.

11. **Outbox folding, rotation and cleanup lack a durable ownership protocol.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:158`, `:165`, `:176`, `:195`, `:394`; code `packages/room-mcp/src/tools/state.ts:43`, `packages/shared/src/doc.ts:507`, `packages/relay/src/memory.ts:31`. One Ledger per room shares one session outbox and scalar byte offset: room A can advance past room B's line or overwrite its snapshot unless a session-level writer owns the whole file. Folding into a local Y.Doc then persisting/rotating the offset is not proof that a relay durably retained the receipt; crash can erase the only recoverable copy. A dead session's unfolded outbox is also deleted after seven days, before orphan recovery. Define one session coordinator, per-generation complete-line offsets, fold durability, and rotation synchronized with appenders; never age-delete an unfolded outbox or a live session. `PIPE_BUF` is a pipe guarantee, not a portable regular-file JSONL protocol.

# Should-fix

1. **A Y.Array position is not a stable observed prefix.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:188`, `:218`; code `packages/shared/src/doc.ts:497`, `packages/room-mcp/src/tools/state.ts:30`. Disconnected replicas append A and B at the same tail; P processes A and stores it as cursor; reconnect orders previously unseen B before A → B is skipped forever. Define whether late concurrent broadcasts are intentionally best-effort, or use a causal boundary that distinguishes unseen inserts. Test merge and trim together.

2. **Mail lookup must extend beyond inbox delivery.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:130`, `:246`, `:306`; code `packages/room-mcp/src/registry.ts:302`, `packages/room-mcp/src/tools/messaging.ts:86`, `:147`. An addressed note moves to mail → P receives it → `room_send(inReplyTo=id)` searches only bus and refuses the reply added in 0.16.33. Deleting mail immediately on receipt makes it disappear before P can answer. Specify a bounded reply-reference lookup/tombstone lifetime, and use it for question/note validation, `holdingQuestion`, resume and unavailable-recipient checks.

3. **The deleted-code/migration inventory misses live consumers and one delivery path.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:332`, `:348`; code `packages/room-mcp/src/hooks-bridge.ts:112`, `:450`, `packages/room-mcp/src/config.ts:133`, `:160`, `packages/room-mcp/src/session.ts:395`, `packages/agent/src/runner.ts:111`. Delete legacy session files as specified → write-intent attribution, hook health and runtime metadata readers lose their source; transcript refresh still writes that supposedly registry-owned file. `roomagent` also injects full `formatMsg` content without consulting/writing receipts. Map these consumers to their new owners or explicitly exclude/remove that runtime. There are seven `syncHookSeen` call sites in this baseline, not eight. Inventory by consumers, not the claimed net line reduction.

4. **Expiry is a count, not the promised auditable outcome.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:76`, `:95`, `:124`; code `packages/shared/src/ledger.ts:52`, `packages/room-mcp/src/tools/messaging.ts:48`. M expires → only `expired[P]` increments → sender cannot tell whether M or another message expired; the original promise remains unresolved. The existing `foldLedger` reconstructs a fixed object and would also discard the new field on the next fold. Specify bounded per-message terminal outcomes and their renderers, and preserve them through subsequent folds rather than adding only an aggregate counter.

5. **Receipt retention must follow retained message references.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:362`, `:403`; code `packages/shared/src/memory.ts:12`, `:35`, `packages/shared/src/doc.ts:464`. P sees Q but never answers, then sees >2,000 later messages → snapshot drops Q's receipt while retaining Q → local restart delivers Q again with no handoff crash. Pin receipts for retained bus/mail entries; explicitly bound/prune the others. Updating the receipt value type and sort key alone does not address this deterministic repeat.

3. **Keep participant receipts with session provenance and explicit succession.** Spec `docs/superpowers/specs/2026-09-28-ledger.md:133`, `:142`; code `packages/shared/src/doc.ts:503`, `plugins/room/hooks/common.mjs:35`.
