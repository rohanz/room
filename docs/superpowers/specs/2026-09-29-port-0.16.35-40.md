# Porting 0.16.35–0.16.40 into the redesign (0.17), 2026-09-29

`redesign` was cut from main at 0.16.34 (8097a8b). Main reached 0.16.40 (73866e6). Merge commit 5a87063 brought
main in; in every conflicted file the merge kept the redesign's side, and each fix was then carried over
deliberately by one of seven Codex workers (gpt-6-sol, high), split by area with owned files
([briefs](../plans/2026-09-29-port-briefs/)). The lead ruled on cross-area edits and conflicts, integrated,
and ran the socket suites.

Verdicts:
- **PORT**: the behaviour is carried into the redesign's architecture; main's tests are brought and adapted, and pass.
- **OBSOLETE**: the redesign already guarantees it (section named); main's regression test is kept or adapted and passes.
- **CONFLICT**: the fix contradicts a redesign decision; the redesign's rule is kept.

Totals: 33 fix rows: **29 PORT, 4 OBSOLETE (36d, 36f, 37f, 39a), 0 whole-fix CONFLICT**. Four PORT rows carry a
CONFLICT part, where the redesign's rule wins:
- 35c: 0.16 branch-following on a move. There is one repository room per repository (reporooms §B1–B2), so a
  branch switch keeps the same session and name instead.
- 36e: main's Codex turn-metadata session binding (tested only with synthetic metadata). Registry §17 binds Codex
  CLI sessions through SessionStart ancestry and leaves the shared app-server unbound.
- 37b: HEAD-poll failure retry. 0.16.37 kept the publisher's retry, from 1 s doubling to 30 s with each failure
  logged. Manifest §5.3 replaces that backoff timer: a publisher error is logged once per distinct message, and dirty
  publication is retried on a fixed 5 s tick. The tracked refresh's coalescing and exponential backoff (to 60 s) are
  ported as in 0.16.37.
- 36b is a PORT that amends registry §6. Row 13 is split: a fresh run's witnessed clean exit without a report is
  `done` + `noReport` (13a), and a resume run's stays `failed` (13b).
- 38f: path and lines in the claim-release wake. Wakes are content-free pointers (ledger, Invariants; wake
  reconciler: "who and what kind, never the text"). The wake says "Room released a claim of yours", and
  `room_state`/`room_wait` show "Room released your claim on <path>:<lines>".

Two rows are split between workers (38e: join and roomd halves; 40a: roomd publication and readers). HARDEN is
step 4 of the brief (load-only flaky tests).

Out of scope, as in main: worker carry still runs one synchronous `git hash-object` per carried file
(`carriedContentHash`). 0.16.40's CHANGELOG lists this under "Not fixed here". It is carry, not a text diff or
publication.

Lead rulings during the port:
- **40b vs manifest §5.3 (atomic apply).** Publication stays one Y transaction. Disk scan and diff preparation yield
  after about 15 ms or 32 paths and recheck stop, input identity and fence. Each file's bounded diff ops are
  computed in prepare, and apply consumes them when the overlay text is unchanged, so the transaction does no diff
  work in the common case. A prepare whose inputs are replaced stops at its next yield (`StalePublication`), and
  the caller drops it without logging or retrying, as `apply` refused a stale snapshot before.
- **Publication cost after review round 2.** There is no path-count ceiling: round 1's 4,096-path cap could wedge an
  admitted state and block narrowing, so it was removed. All per-file work happens in a prepare that yields between
  files: disk reads bounded by descriptor, old blobs size-checked by metadata before reading, bounded diffs and hashes.
  - The single atomic transaction (manifest §5.3) holds only precomputed Y operations of constant cost per path.
  - Just before it, a synchronous gate checks each file's identity with `lstat` only (file type, size, mtime, inode),
    without reading.
  - Narrowing and withdrawal are never deferred.
  - The bridge's projection follows the same design.
- **Uncertain claims (38a, round 2).** When the reanchor work budget runs out, the claims go into a fenced pending set.
  It is revalidated on later publisher ticks, and the manifest stays incomplete until the set is resolved (§5.4).
  A claimed file that is unreadable, not a regular file, or over the size cap follows 0.16.38's rule for a missing
  block: the claim is released if git shows no local edits, and kept otherwise.
- **40a scope.** The overlay diff (`RoomDoc.setOverlay`) is bounded. So are every reader diff: `room_read diff`,
  the conflict set's changed ranges, the node-diff3 preview fallback in `merge.ts`, and the web merged view.
  Multi-file reader loops yield between files.
- **36e location.** Hook-evidence receipts are per session under `<git common dir>/room/hook-receipts/` (R5). They
  are separate from the ledger's CRDT `seen:` delivery receipts.
- **36a relay.** A worker from an older lead, which names no clone, joins only a relay that is already running
  (`ensureLocalRelay(..., { joinOnly: true })`). It never takes the hub authority lock (R-H3).
