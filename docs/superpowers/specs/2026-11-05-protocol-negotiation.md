Date: 2026-11-05. Status: proposed; no behavior in this document is shipped unless identified as current. Scope: team server, local relay, room-mcp/embedded roomd, roomagent, browser viewer and hook arbitration. Release numbers identify builds; they do not select wire semantics.

## Problem

An upgrade should let an operator deploy first and users restart sessions individually. A client should either join with an explicitly supported contract or report exactly which side must change, before exchanging document updates. Negotiation cannot make arbitrary Yjs schemas interoperable, restore rejected in-flight writes, or make one server/volume deployment highly available.

## Proposed design

### Contracts and advertisement

Introduce one small shared compatibility module, consumed by hub-core, server, relay, clients and doctor. Keep hook constants in a generated dependency-free artifact usable by plain Node hooks. Separate these axes:

- Bootstrap envelope: fixed version 1 for discovering and selecting a contract.
- Hub protocol: inclusive integer range, initially `[1,1]`; changing a request's meaning requires a new version.
- Document schema: explicit readable/writable sets, initially `[2]`, and one active schema per room. Never infer support for intermediate schemas from numerical endpoints.
- Optional capabilities: namespaced names with explicit version sets, e.g. `room.generation:[1]`, `room.manifest:[1]`, `room.ledger:[1]`, `room.worker-handover:[1]`. A registry defines dependencies, wire semantics, document effects and whether each is connection-local, participant-to-participant or room-wide. These names are proposed, not existing flags.
- Separate hook endpoint, relay encryption and viewer-link format contracts. Application release/build ID remains diagnostic only.

Add `compat` to `/health` and `/auth/config`; preserve legacy `schema:2,hub:1` while that baseline is supported. The flat fields describe the legacy route, not the highest available version. Once baseline support ends, do not keep falsely advertising it. Neither endpoint exposes room-specific state anonymously. Room metadata comes only after normal admission. Reject a serialized UTF-8 `compat` manifest above 1 KiB (including keys, punctuation and values); independent field-count limits do not override this total. Keep the manifest below 1 KiB so local health fits its current 2 KiB probe budget ([proof.ts:47](../../../packages/relay/src/proof.ts#L47)); cap capabilities at 32 names, 64 ASCII characters each, eight versions per name. Required capabilities must all fit or advertisement fails at build/startup; never truncate them. Larger registries require a versioned, authenticated digest-bound discovery endpoint with its own byte cap before use, not silently larger health responses. The entire legacy health response must still fit 2 KiB.

Example discovery (illustrative future server):

```json
{"ok":true,"schema":2,"hub":1,"compat":{"bootstrap":1,"hub":{"min":1,"max":2},"schemas":{"read":[2,3],"write":[2,3]},"capabilities":{"room.generation":[1],"room.ledger":[1]},"legacy":{"schema":2,"hub":1},"release":"future-build"}}
```

Protocol versions do not imply a schema upgrade: that server can serve proto 2 over schema 2. Capability selection is the highest common registered version after dependency checks, never a union. No overlap in any required contract is a terminal incompatibility. Unknown optional capabilities are ignored; unknown required ones fail. Ranges contain finite positive integers and have an implementation-supported maximum; malformed advertisements fail without retrying a weaker protocol.

### Handshake and synchronization gate

1. Discover capabilities from the configured origin, using existing timeouts and authentication policy. Discovery is a hint. Do not create/migrate a repository just to test compatibility.
2. For advertised bootstrap 1, open the authenticated websocket with `negotiate=1`, existing room identity, schema hint and replica generation. Browser ticket issuance carries the offer and binds it to the same room/credential; no credentials or capability blobs in URLs. Normal admission still runs. A new server must never route an unrecognized `negotiate` value to legacy sync.
3. Keep the provider disconnected from Yjs handlers. The only allowed application frame is bootstrap hello on type 7, envelope `v:1`, with session ID, release, hub range, schema sets, offered capabilities and required capabilities. This is a new gated hello branch, not extra fields sent to the old strict parser. Allow read-only viewers to negotiate without granting write operations; a ticket determines read-only authority, not the offer.
4. Parse client input outside the lock. Under a short repository/relay authority lock, select the highest common hub protocol compatible with the room's active schema and capabilities. Reply includes selected values, active schema, document generation, policy revision, room-required capabilities, hub incarnation and lease timings. Reject within five seconds/8 KiB of bootstrap input; close idle or early-sync peers without applying their packets. Re-check revocation and room state after awaits. The client validates the selection is a subset of its offer and satisfies its requirements.
5. Release the lock before waiting for the client. Client acknowledges the selection ID; re-enter the lock and re-check authority epoch, migration state, policy revision, credentials and generation before attaching. A delayed ACK from an earlier epoch cannot attach sync. Only then attach Yjs sync/awareness and enable hub operations. Store selection in connection state outside Y.Doc. Freeze it for the connection; reconnect re-negotiates. Generation mismatch uses existing fresh-replica recovery before any sync, never merges an old replica. A schema mismatch additionally requires a schema-aware new replica, not just changing `gen` to `fresh` on the old Y.Doc.

Hello and ACK each have a five-second absolute deadline (ten seconds total), including admission waits; selection output is at most 8 KiB. Reserve pending slots before reading: at most 64 per authority and 8 per principal, with at most 1 MiB total buffered negotiation input/output, subject to stricter existing process quotas. Cancel and release buffers/reservations on disconnect, revocation, timeout or migration; send at most one selection. No client-input wait holds the repository lock. Bound storage work separately and re-check the epoch after every await.

Update both the session probe and final daemon provider, browser, roomagent and relay wrapper. Authentication/encryption precedes bootstrap; do not attach y-websocket's automatic initial sync until selection completes. Gate outgoing as well as incoming data. Canonical room parsing on negotiating routes uses the admitted repository identity, independently of the schema-2 query switch. The schema query remains a legacy routing hint; it cannot override the selected room schema. New HTTP operations that depend on a contract use a similarly validated bounded `compat` offer in their body (or a compact selected-contract header for GET); compatibility is checked before side effects. Bootstrap does not add authority to create, close or migrate rooms.

Errors have stable `code`, supported ranges, missing required capabilities, affected side (`client`, `server`, `room`, `hook`) and restart/update guidance. Use HTTP 426 JSON before upgrade for incompatibility and websocket 4406 afterward, with a bounded reason; legacy routes retain their existing errors. Keep authentication 401/403 distinct, transient capacity 429/503 distinct, stale-replica 4409 distinct, and storage failure distinct. Compatibility errors stop automatic retry; they must not become a paused local name that looks successfully joined.

### Bootstrap deployment and minimum supported range

First ship a negotiating server/relay that still serves the exact schema-2/proto-1 baseline. Then ship negotiating clients that also implement that baseline. No simultaneous fleet update is needed for this introduction, which retains the session-owned relay lifecycle. Call these releases N. Ship the standalone local daemon only afterward as release D, with an explicitly drained runtime cutover; D is not part of N's rolling-local promise. These are ordering labels, not reserved product versions. See the [local-daemon cutover contract](2026-11-05-local-daemon.md#compatibility-and-migration-from-017x-clones).

The first stable supported baseline is **0.17.0**, schema 2/proto 1 with generation support, pinned to commit `ec13dcd83f67895c622410e3d9e8f53b5c5cb7a2` (peeled `v0.17.0`). The upper initial fixture is **0.17.32**, commit `77bf1c448d6ce883b844443204c7c9c7306d0c4c`; “latest 0.17.x” must never be a moving fixture. This is a wire baseline: review holds require 0.17.5+ collecting processes and daemon cutover save-first guarantees require 0.17.31+. Neither safety behavior is backported by negotiation. Initial exception: **0.16 is rejected**, not the previous supported family. Thereafter support the current and previous stable minor release families, with a minimum 90-day overlap after the replacement family ships. Patches within a supported family retain its contracts. Publish tested baseline tags/digests, adapters, deprecation date and any security minimum in release notes. Raising a floor requires a passing mixed-version CI matrix, advance notice and an explicit release decision; elapsed time alone must not rewrite room policy. Emergency security withdrawals can shorten the window with a specific advisory and recovery instructions. Operators may raise minimums, but cannot enable an unimplemented or security-retired adapter. Do not impose a plugin semver floor when a contract floor suffices.

Legacy fallback is allowed only when discovery is a valid, recognized baseline response, the client contains that adapter, and local security policy permits it. TLS errors, redirects to another origin, timeout, malformed JSON, incompatible advertised ranges or an explicit negotiation rejection never trigger fallback. Reconnect cannot silently fall back after an established negotiated connection. Persist a minimum learned security/bootstrap floor per canonical remote origin, or locally per canonical Git common directory/clone identity plus key fingerprint, never per ephemeral localhost port. Store floors atomically in private client state outside Y.Doc; retain across restarts, port fallback and reinstall. Key rotation requires authenticated continuity or an explicit user reset, retaining an audit entry for the old identity; disappearance of the floor is not an automatic reset.

Optional operations use selected capabilities. Room-wide document features require the room's profile to allow them, including disconnected clients eligible to reconnect; do not enable them merely because the last old connection disappeared. New kinds in the shared bus require all admitted profiles to understand them or a proven baseline encoding with the same delivery semantics. Connection filtering alone cannot hide an unknown kind in a shared Y.Doc. New readers should preserve unknown records and show an unsupported-event diagnostic without acknowledging delivery; that improvement does not fix legacy readers that throw.

Legacy routes are an explicit exception to the new hello/ACK gate: admit the frozen profile before attaching automatic Yjs sync, preserve old sync-before-hub-hello ordering, and fence that receive path during migration too. Mandatory new ACKs on old sockets would deadlock released clients. If discovery says negotiation but connection reaches an old server that ignores the query, the new client's early-frame handler must fail closed before applying any unexpected Yjs frame to its actual replica; do not retry weaker after that failure.

### Local daemon, relay, workers and viewer

Keep `room/relay.json`, the schema-2 port derivation and authority lock during the overlap. Add an independent discovery-format version and optional compatibility manifest, leaving old required fields intact. Read unknown extra fields; classify an authenticated live relay as compatible, incompatible, foreign or temporarily unavailable. Incompatible is never “absent”: do not start another authority, choose another port to hide it, kill it or overwrite its snapshots. Existing key proof proves identity, not manifest integrity; confirm capabilities inside the encrypted connection. Retain the existing encryption bootstrap for overlap, negotiate inside it, and never choose plaintext for compatibility.

During N, a newer client joins an older compatible relay with the legacy adapter. A newer session-owned relay accepts older clients while the room remains schema 2. For incompatible owners, report owner process identity and required restart; let the owner drain/save and exit before a successor takes authority. Preserve final-save retry and lease/incarnation continuity ([relay/src/index.ts:588](../../../packages/relay/src/index.ts#L588), [relay/src/hub.ts:19](../../../packages/relay/src/hub.ts#L19)). Same-clone followers and a lead's team/local bridge negotiate each connection independently. roomd keeps its session identity and lease, but its final publisher connection must independently validate a fresh selection, including on reconnect, before publishing; a probe selection cannot authorize another socket.

The effective local profile includes wire schema/proto/encryption, discovery format, runtime kind (`session-relay` at N, `daemon` required at D), the D local daemon-lifecycle capability and durable choice/sharing/worker-record schemas. A matching wire profile is necessary but insufficient for local runtime support.

| --- | --- | --- |

D uses N's shared negotiation machinery, not a separate daemon-only handshake. Its writer capability requires external transport ownership, replica-preserving rebinding and no in-session takeover. Its viewers require compatible read negotiation without launch authority. D's versioned authenticated health proof binds clone identity, runtime, release and compatibility advertisement (or its canonical digest) to the nonce and port; the legacy proof remains available only for N's baseline overlap. Both probe and final publisher, relay and viewer enforce runtime/selection at the consuming endpoint before incoming or outgoing sync. D refuses unnegotiated old writers/viewers even if their underlying schema matches. Discovery metadata cannot stop an old binary from later acquiring the authority lock; the refusal/recovery row above remains essential.

Daemon cutover inventories clone and linked-worktree leads, workers, nested hosts, bridges and viewers, stops old launch/reconnect loops, quiesces publication and verifies preservation while a replica is alive. Require observed final-save success and owner exit plus validated selective memory/private authority files on 0.17.31–0.17.32. Earlier builds need a separately verified quiescent reloadable checkpoint, not merely successful stop or human-readable export; absent evidence postpones cutover. Stop all old clients, verify owner death, then restart updated clients under the same lock. Daemonization retains schema-2 selective snapshots and authority files without bulk schema migration. A subsequent schema migration uses the full source/drain artifacts below, not those selective snapshots.

For new leads, replace release equality as the worker compatibility decision with preflight of the actual executable bundle's **protocol and durable record schema**, plus destination policy. This is the [2026-11-05 roadmap item](../../roadmap.md#L23): a docs-only release must not block an otherwise compatible batch. Unknown child identity is “unverified”, never inferred from the highest cache directory. Release mismatch remains diagnostic. This future change cannot alter an old lead's already-loaded code.

### Hook endpoint negotiation

Keep the Codex hook definition unchanged; behavior belongs in scripts. Extend `mcp.json` with optional `hookCompat:{bootstrap:1,min:1,max:1}` and process build ID. Format 1 is today's keyed select/ping/confirm protocol. A new hook reading an old endpoint uses exactly format 1 if implemented; an old hook reading a new endpoint ignores extras and continues unchanged while format 1 is supported.

When advertised, `openMcp` sends keyed hello with bound host session ID, supported hook range and capabilities. Authenticate and validate binding before responding. Select/confirm cannot run on that connection until selection succeeds; confirm binds batch, session, endpoint incarnation and selected protocol. Rebinding invalidates the selection. A failed hello never falls back to direct select against that endpoint. Keep the entire exchange inside the existing hook deadline, reply/input caps and stdout-confirm rule ([common.mjs:239](../../../plugins/room/hooks/common.mjs#L239), [arbitration.ts:45](../../../packages/room-mcp/src/arbitration.ts#L45)).

No overlap means print one bounded compatibility diagnostic through the existing hook diagnostic path, surface degraded delivery in room state, and leave messages owed. Never fabricate a receipt, commit a batch on hello, or print raw endpoint replies as agent instructions. Each operation still enforces its own safety rules; missing arbitration is not a reason to invent an approval or silently acknowledge inbox content. Add no host-specific flags or assumed host APIs.

### Y.Doc migration without losing retained data

One room has one writable schema and one generation. This proposal deliberately excludes concurrent schema-2 and schema-3 writable replicas and CRDT update translation: Yjs updates encode causal/type identities, not a lossless semantic patch API. A room can remain on schema 2 while its server and clients upgrade independently.

1. **Expand:** ship readers/writers for schema 2 and 3, leaving the active schema at 2. Add a durable, authority-owned room compatibility policy outside the client-writable Y.Doc: active schema/generation, allowed profiles, migration state and policy revision. Mirror diagnostic fields into meta, but never trust them for admission. Use one shared negotiation/selection algorithm in server and relay.
2. **Prepare:** an explicit operator/room-owner action plans migration for that room. Report live and retained unsupported clients, offline reconnect consequences, storage budgets and backup/export locations. Do not migrate on a client hello or merely because no old client is online. Require the schema-3 profile before commit. Persist a migration intent before initiating drain; recovery of an incomplete intent starts fenced until the journal is resolved.
3. **Fence and drain:** use the authority state machine and evidence below. Admission closure alone is insufficient: current server automatic sync attaches at [index.ts:1017](../../../packages/server/src/index.ts#L1017), relay sync applies at [index.ts:264](../../../packages/relay/src/index.ts#L264), and hub maintenance mutates leases, trim and expiry at [hub.ts:715](../../../packages/hub-core/src/hub.ts#L715). After the authority fence, flush accepted state through K before capturing the source artifact; record durable drain before candidate construction. Uncertain old-client writes do **not** block migration: record their uncertainty and the operator's acknowledged recovery point; never call them a lossless drain.
4. **Build and verify:** transform a size-bounded source copy into a separate candidate Y.Doc with a fresh generation. Preserve retained message IDs, ordering, addressed recipients, receipts, archive/outcomes, claims/scopes, participant ownership/fences, worker runs and recovery records, manifest/share-policy revisions, salts and completed-publication caches. Preserve unknown roots/fields only where their semantics are proven independent of Yjs identities. Identical typed values or binary bytes are insufficient for encoded relative positions, type/item IDs and cross-record references in a fresh Y.Doc. Require registered migrations and semantic validators for identity-bearing values, reconstructing references against the candidate and verifying they resolve to the same target. Current `compactDoc` rebuilds known claim anchors and rejects XML/subdocuments ([compact.ts:89](../../../packages/shared/src/compact.ts#L89), [:112](../../../packages/shared/src/compact.ts#L112), [:153](../../../packages/shared/src/compact.ts#L153)); it is not a generic semantic migrator. Unknown opaque values whose identity independence cannot be established, unsupported types, unresolved retained references or budget excess block migration and retain the source. Validate invariants, counts and semantic projections before publication; never silently drop an unresolved retained anchor. Intentional removals must have an explicit retention/export policy, never masquerade as migration success.
5. **Commit durably:** stage candidate and migration journal first. Atomically publish one authoritative storage pointer/record selecting schema, generation and policy revision. Existing LevelDB snapshot atomicity is useful, but document + registry/Postgres + hub files are not one transaction: use a durable journal and idempotent recovery, with the authoritative commit marker deciding which generation is served. Readers must never observe schema 3 with a schema-2 policy. After a crash, finish or abandon preparation according to that marker; keep both artifacts until verified.
6. **Reconnect:** reject old-schema/stale-generation replicas before applying any update. Supported clients construct a fresh Y.Doc, restore their name/session and revalidate leases, sharing choices, current filesystem and pending semantic operations. Deduplicate by stable operation ID; never resend raw old-generation CRDT bytes. Owed messages remain owed unless real delivery receipts survived. Document exactly what was accepted, pending or unrecoverable; client filesystem work is untouched.
7. **Contract later:** retain the previous snapshot/journal and original archives for an explicit recovery period; deletion is a separate authorized retention action. Before commit, rollback discards the candidate only after recording abort and verifying/restoring the durable source and authority state as described below. After new-schema writes, changing images or pointing at the old snapshot loses those writes: rollback requires a tested reverse migration or restoring a backup with an explicit recovery-point loss decision. Preserve the new state for recovery in either case.

#### Authority state machine and acceptance boundary

Use one authority-owned mutation dispatcher per room, shared by team and local transports. Route **every** live-document mutation through it: open-socket sync step 2/update packets (including packets already decrypted or queued), hub operations, direct receipt/claim/scope/manifest/worker writes, hook-confirm receipt propagation, bridge/publisher callbacks, socket-close cleanup, compaction, expiry, trim, lease renewal/adoption and persistence-retry callbacks that alter live state. An observer after a Yjs transaction cannot serve as the fence. Instrument the complete inventory and fail tests on any ungated mutation.

| State | Admission / mutation rule and transition evidence |
| --- | --- |
| `ACTIVE` | Accept supported connections and serialized mutations, assigning an authority acceptance sequence **at application**, not at socket read, enqueue or preflight. Async preparation conveys no acceptance; re-check state/epoch immediately before applying. |
| `DRAINING` | After durable intent, close admission, cancel pending selections/tickets for attachment, and increment the authority admission epoch under the lock. Existing enrolled clients can flush until their individual barriers. Hub timers can run only through the dispatcher until the global fence. No new connection, including a delayed selection ACK, may attach. Await clients outside the lock. |
| `FROZEN` | **Linearization point L:** under the dispatcher/authority lock, after all in-progress applied transactions finish, atomically set state to `FROZEN`, advance the mutation epoch and record the final acceptance sequence K. There is no await inside this step. From L onward every live mutation path rejects with retry/rejoin guidance or queues bounded semantic work outside the live document; raw old-generation updates are rejected, never queued for replay. Already queued callbacks and timers re-check the new epoch at execution. Disable timer rescheduling and prevent late close/confirm/ACK callbacks from writing. Only the migration coordinator may build a separate candidate. |
| `SOURCE_DURABLE` | With the live source immutable, flush all updates accepted through K plus hub leases/counters, registry and policy revisions to durable storage. Write and fsync the source artifact and drain journal; only then acknowledge durable drain and enter candidate build. A persistence await never reopens the live document. |
| `BUILDING` / `COMMITTING` | Construct and validate the candidate while the source remains fenced. Stage/fsync candidate and journal, then publish the one authoritative commit marker. New callbacks remain rejected/queued through every await. |
| `ACTIVE_NEW` | Recover the committed generation, validate its policy and reopen admission with a new epoch. Queued semantic work must reconnect/revalidate; no automatic replay during commit. |
| `ABORTING` / `RECOVERY_REQUIRED` | Before commit, durably record abort, discard uncommitted candidate references, and verify/restore the source through K with its saved leases/counters and policy. Reopen only after storage is healthy, the abort marker is durable and queued old callbacks are invalidated. Reconnect/revalidate clients under a new epoch; timers resume from saved state under normal expiry rules. If any restore is uncertain, stay fenced in `RECOVERY_REQUIRED`. After commit, recover only the committed generation. |

The gate covers implicit writes too (e.g. checking a lease may expire it). At L no partially executing async mutation is allowed: its synchronous transaction either applied before L and is included through K, or its continuation must revalidate and reject. Kernel/socket arrival time is not acceptance. Bytes received before L but applied afterward are rejected and reported as uncertain, not silently counted as retained data. Source capture waits for all pre-L persistence tasks to settle and a final durable flush through K. Existing ordinary hub ACKs prove neither this flush nor indefinite durability.

#### Per-client barrier and durable drain evidence

A negotiating client pauses **all** producers, including raw Yjs receipt/claim writes, hooks and bridges; it persists its pending semantic outbox, then flushes its raw updates and semantic requests. It sends `drainBarrier(migrationId, connectionId, lastFrameSequence, operationIds, generation)` as an ordered frame on each writing connection after those frames. The authority processes it in that connection's ordered mutation queue, records applied/failed sequence results and seals that connection against further writes. A session with multiple transports must barrier every one; no barrier on the probe covers the final publisher. A state vector alone is insufficient evidence for deletions or queued raw frames. ACKs for outstanding semantic requests are accounted for by ID, including unknown outcomes.

The initial barrier response proves **transport application through its watermark**, not durable storage. After L and the final flush, a second durable-drain response references a journal record proving the persisted authority sequence K covers each successful client watermark. A disconnected negotiating client retains its barrier/outbox and queries that record on reconnect; loss of the response is not evidence of absence. Legacy clients cannot send this barrier. Ask them to finish/save and disconnect, then seal their authority connection queues and include everything actually applied. This proves retained authority state, not delivery of their pending local bytes.

Persist a bounded, private drain record with migration/authority IDs, source and target schemas/generations, policy/registry revisions, K, source artifact digest/location, durable hub counter/lease references, each client/connection watermark and application/durability result, disconnected/timeout clients, unknown operation IDs, and the recovery-point acknowledgment (operator identity, time and explicitly stated uncertainty). Include no message bodies, private code or credentials. Bind its digest into the migration journal/commit marker; retain it alongside source/candidate artifacts for the published recovery period. Ordinary selective local memory snapshots are insufficient: use a separate full source artifact to preserve retained roots, with the same private-path protections.

Drain waits at most 60 seconds per room, with a 10-second notification/response budget per client within that total. At timeout, seal remaining connections and classify their unproved work as uncertain. Do not wait indefinitely for old/offline client proof. If the operator has acknowledged that listed client-only/unacknowledged writes may be absent at this recovery point, proceed; otherwise abort before commit and preserve the source. Uncertain writes themselves are never a storage blocker. An unresolved authority flush, invalid source or failed fsync **is** a blocker and cannot be waived as client uncertainty. The report distinguishes applied-through-K retained state, durable barriers, and uncertain client-only work; never label the whole migration lossless.

Queue no raw updates after L. Optional semantic deferral is at most 1 MiB/1,000 operations per room, subject to process budget, and receives only a `queued`, never durable-success, response; overflow rejects so the client keeps its outbox. A disconnect cancels pending negotiations and unaccepted work, not already accepted state.

#### Aggregate migration budget and semantic outbox

Permit one migration per authority process by default. Reserve memory for source + candidate Y.Doc heaps + encoded source/candidate + in-flight persistence/encoding buffers + journal + deferred work **together**. On the documented 512 MiB deployment the migration reservation is at most 128 MiB and process working-set budget at most 384 MiB, leaving 128 MiB headroom. Admission requires measured decoded-heap estimates from fixtures, not just individual encoded-size caps; stop candidate construction before the reservation is exceeded. Bound the drain evidence to 1 MiB (client count must fit existing connection quotas); cap staged disk artifacts plus journal at 256 MiB per migration with space for atomic replacement. Export/offline migration is the remedy for larger rooms. Report measured peak heap/RSS and disk in acceptance evidence; bounds may be lowered by deployment policy. No client-input waits hold the authority lock; storage staging uses the fenced state and short final publication lock. A 120-second post-fence build/flush deadline aborts pre-commit safely; an uncertain commit outcome remains fenced for journal recovery, never times out into old-schema service.

Initially only semantic **message posts** have replayable stable IDs, persisted with destination identity, sender, generation, lease context and sharing-policy revision in a private fsynced client outbox before send. Retain pending/unknown entries across restart and migration for up to 30 days, bounded to 1 MiB/1,000 entries per client; overflow refuses new queued posts. Expiration moves unresolved IDs to an explicit recovery report and requires an explicit discard/reconciliation decision, never silent replay or deletion. Before replay, revalidate current sharing grants/ceiling, destination, sender/lease, schema and operation semantics; changed or narrowed policy holds the entry for reconciliation. Receipts, claims and other direct Yjs writes are covered by the raw transport barrier, **not** a claimed exactly-once semantic API. Give each any future stable-ID operation a registered reconciliation/dedup contract before enabling replay.

Current post dedup checks message/mail/archive/outcome retention ([hub.ts:685](../../../packages/hub-core/src/hub.ts#L685)), not infinite execution history. Reconcile IDs against durable migration evidence and retained dedup records; when those records have expired or the outcome cannot be established, report **unknown**, never “absent” and automatically repost. Publishing retained-state migration guarantees does not upgrade ordinary post acknowledgments to durable delivery.

Local snapshots use the same staging/commit discipline under clone authority, with fsync and atomic rename; never copy an actively changing old relay's memory and call it a consistent migration. Server persistence outages, quarantine and record-size limits remain blockers. Negotiation removes the server/client installation cutover; an incompatible schema change still has a deliberate per-room write pause and capability floor.

## Compatibility

The first negotiation release N supports the pinned stable 0.17.0–0.17.32 baseline fixtures, schema 2/proto 1 without requiring old clients to learn negotiation. It does not reopen 0.16 admission or alter its existing archive/reclamation rules. Legacy clients can use only baseline-safe document features; an HTTP response advertising proto 2 does not authorize them to use it. Missing optional capabilities disable named operations with reasons, while missing safety semantics block those operations.

Hub proto versions, bootstrap envelopes, schemas, generations, relay encryption, hook endpoint formats, viewer links and plugin releases are independently versioned. A documented profile ties tested combinations together. Required capabilities and active schema live in authority-owned policy, selected capabilities in connection state, and diagnostic build IDs in logs/state. A participant's self-reported release or Y.Doc metadata never grants permission.

Roll out N server/relay adapters first, N clients second, opt-in features third, and per-room schema changes after an explicit drain. Ship daemon D only after N with its separate drained runtime cutover; a daemon lifetime change does not itself require a schema migration. Keep one machine/volume topology; this design does not promise zero-disconnect deployment or solve multi-node routing, which remains deferred ([docs/roadmap.md:24](../../roadmap.md#L24)).

## Failure modes

| Failure | Required result |
| --- | --- |
| No common protocol/schema/required capability | Terminal compatibility error before sync, no claims/publication or repeated worker join loop; name the side and update action. |
| Discovery succeeds but server changes before connect | Socket selection is authoritative; recompute against current policy under lock. Never apply cached selection to another process/room. |

## Security

Use the deployed threat model, not capabilities as an authorization system. Self-hosting requires a TLS-terminating proxy; without configured authentication the non-GitHub server can be open ([deploy/self-hosting.md:10](../../../deploy/self-hosting.md#L10), [deploy/self-hosting.md:49](../../../deploy/self-hosting.md#L49)). GitHub admission requires push access, other namespaces use configured token/providers, and browser view keys are bearer read capabilities ([deploy/self-hosting.md:41](../../../deploy/self-hosting.md#L41), [deploy/self-hosting.md:71](../../../deploy/self-hosting.md#L71)). Admitted writers remain trusted: the identity guard is observe-only by default; enforcement is experimental and can desynchronize causal streams ([deploy/self-hosting.md:234](../../../deploy/self-hosting.md#L234)). Negotiation does not sandbox a malicious admitted Yjs writer or repair those limitations.

An on-path attacker may strip advertisement or lower ranges on unauthenticated transport. Require TLS for all remote discovery, negotiation **and legacy fallback** and preserve existing local key proof/encrypted framing. Confirm the full offer/selection inside the authenticated connection; bind browser tickets to the offer, room, credential and policy. Health proof currently authenticates relay identity, not `compat`. On first local contact a stripped manifest is indistinguishable from an old authority under that proof: permit only the fixed supported schema-2/proto-1 baseline after key proof and encrypted handshake, subject to the local runtime requirement and persisted floor. The actual authority must enforce baseline retirement and refuse it; a legacy hello cannot confirm an offer it does not understand. Do not claim first-contact downgrade detection. A learned negotiating floor blocks later stripped-advertisement fallback, including on another port. Never weaken encryption from discovery. No cross-origin redirect carrying credentials. Explicit no-overlap, TLS failure and advertised negotiation failure cannot trigger legacy retry. Remembered security floors and server-side minimums prevent honest clients silently returning to a retired profile; do not claim they resist an administrator controlling the server or local account.

A member may lie about capabilities or intentionally choose the oldest supported contract. The server enforces the minimum and required dependencies and never trusts claimed plugin version. This may disable an optional room feature until the operator excludes that profile; it must not silently widen sharing, grant write access, restore URL credentials, bypass managed-repository approval, weaken read-only views or reset lease epochs. New policy records are outside the replicated document. Keep provider-qualified ownership and credential revocation checks after asynchronous work ([index.ts:1102](../../../packages/server/src/index.ts#L1102), [deploy/self-hosting.md:246](../../../deploy/self-hosting.md#L246)).

Anonymous manifests disclose only global supported contracts. Bound lists, negotiations and logs; log selected profile, build, reason and policy revision, never tokens, hook keys, message bodies or private code. Incompatible clients must not trigger migrations or repeated expensive loads. Local same-user processes can read discovery secrets and replace writable files: that is already within the documented same-account path boundary ([deploy/self-hosting.md:249](../../../deploy/self-hosting.md#L249)); negotiation does not defend against that principal.

## Open questions

Keep rooms on the previous schema for the compatibility window unless an operator explicitly accepts a drained per-room migration and its client floor. This decision, the stable baseline, window and matrix owner are settled above; fixture artifacts and passing release evidence remain prerequisites, not open policy questions.

1. Which first optional feature actually needs a new hub protocol, versus a capability over proto 1? Freeze the capability registry using that concrete implementation, not speculative flags.
2. Which storage record owns the migration commit marker across LevelDB, optional Postgres and hub files? Specify and fault-test the journal recovery algorithm before implementing schema 3.
3. Message posts are the first semantic outbox scope; which operation, if any, should follow receipts/claims' raw barrier coverage? The current release explicitly permits acknowledged-post loss when every replica disappears before persistence ([CHANGELOG.md:269](../../../CHANGELOG.md#L269)); negotiation must not advertise stronger delivery without a separate durability change.
4. What policy can reliably exclude old local collectors before claiming review-hold enforcement? Network capabilities alone cannot constrain another same-user process operating on a checkout.
5. Should viewer assets be embedded or copied per process, and how are retained copies bounded and reclaimed after process death? Either choice must work after a plugin cache update/removal.
