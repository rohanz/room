# Standalone local daemon

**Revision 2026-11-05.** Resolves [the local daemon review](../reviews/2026-11-05-spec-review-local-daemon.md): must-fix 1 separates capacity from I/O failure and preserves bounded authenticated shrink/export recovery; must-fix 2 retains the client Y.Doc across every involuntary reconnect. Incorporates maintainer decisions: protocol negotiation ships first while compatible in-session relays remain permitted; the daemon ships at an explicit drained cutover; any verified bound clone client may start/restart it; viewers do not keep it alive and idle shutdown is the default. Also closes should-fix 1–6 with explicit load states, first-start key ownership, pending-handshake fencing, version-specific migration evidence, endpoint compatibility/Windows ACL gates, and corrected persistence/process claims and citations. These are implementation requirements, not claims of completed validation.

Date: 2026-11-05. Status: proposed, for maintainer review. Source references below describe the current checkout (0.17.32), not the earlier review trees. This design replaces the *session-owned relay lifetime*, not `roomd`, the per-session publisher, or the team server.

## Problem

On 2026-11-04, a worker's Room server took over the local relay twice after the lead restarted. Its lagging event loop then prevented join-only Codex workers from joining. 0.17.31 prevents workers and hosts inside worker worktrees from creating or taking over the relay; without a lead they now wait. That is containment, not independence from a lead's lifetime ([CHANGELOG.md:9](../../../CHANGELOG.md#L9); [docs/reference.md:11](../../reference.md#L11)).

A handover endpoint was built during 0.17.31 development, then deleted before release. The first review found both a non-lead creation loophole and a handover that could destroy the only current replica after a failed save ([review:7](../reviews/2026-11-05-prerelease-review-0.17.31.md#L7), [review:9](../reviews/2026-11-05-prerelease-review-0.17.31.md#L9)). Verification confirmed removal of `/handover`, `yieldToLead`, reclaim machinery and handover timers, but still found lossy ordinary shutdown ([verification:15](../reviews/2026-11-05-prerelease-verification-0.17.31.md#L15), [verification:17](../reviews/2026-11-05-prerelease-verification-0.17.31.md#L17)). Those reports are dated intermediate evidence: current shutdown does propagate final-save failure, retry, and retain the listener, documents and authority. It cannot retain them after its enclosing host process exits ([packages/relay/src/index.ts:585](../../../packages/relay/src/index.ts#L585), [packages/relay/src/index.ts:805](../../../packages/relay/src/index.ts#L805)).

Two leads in one clone expose the same coupling without a crash. One owns transport for both; leaving that session tears down transport and makes the other reconstruct it. Separately, two idle MCP servers in one checkout burned cores for ten hours, and duplicate graph rebuilds took 86–131 seconds on a loaded lead. 0.17.30 added diagnostics and checkout publisher ownership for graphs ([CHANGELOG.md:25](../../../CHANGELOG.md#L25), [CHANGELOG.md:31](../../../CHANGELOG.md#L31), [CHANGELOG.md:32](../../../CHANGELOG.md#L32)). Moving transport out removes that event-loop dependency; it does not cure duplicate indexing or CPU contention elsewhere.

The desired invariant is: leaving or restarting any session cannot voluntarily destroy the room's transport or the daemon's unsaved memory; every involuntary recovery in a surviving client preserves its replica. A daemon crash can still lose state absent from both disk and surviving clients. The current delivery contract already admits that limitation ([docs/reference.md:43](../../reference.md#L43)).

## Current mechanism

- The local boundary is the Git common directory: linked worktrees share it, independent clones do not. `joinLocal` validates a worker's lead clone, detects worker worktrees even with scrubbed environment variables, then calls `ensureLocalRelay` with its role and a replica seed ([packages/room-mcp/src/session.ts:940](../../../packages/room-mcp/src/session.ts#L940)). `ensureLocalRelay` computes `lead = !joinOnly && lead !== false`; a non-lead cannot start an absent relay ([packages/relay/src/index.ts:643](../../../packages/relay/src/index.ts#L643), [packages/relay/src/index.ts:699](../../../packages/relay/src/index.ts#L699)).
- Discovery is schema-2 `<common>/room/relay.json`, carrying port, PID, key, start time and optional `lead`. Publication uses a private temporary file and rename. Clients prove the listener's key and clone identity; an occupied port alone proves nothing. The canonical port hashes the real common directory; unrelated occupancy falls back to a free port ([packages/relay/src/index.ts:332](../../../packages/relay/src/index.ts#L332), [packages/relay/src/index.ts:370](../../../packages/relay/src/index.ts#L370), [packages/relay/src/index.ts:654](../../../packages/relay/src/index.ts#L654), [packages/relay/src/index.ts:708](../../../packages/relay/src/index.ts#L708)).
- The first eligible MCP process holds `<common>/room/hub/authority.lock` and runs `startRelay` in that process. Recovery requires a dead owner; unknown liveness blocks. Nonce comparison protects release from deleting a successor's lock ([packages/relay/src/hub.ts:19](../../../packages/relay/src/hub.ts#L19), [packages/relay/src/leases.ts:17](../../../packages/relay/src/leases.ts#L17)). Each retained room has a Y.Doc, awareness, memory and hub ([packages/relay/src/index.ts:128](../../../packages/relay/src/index.ts#L128)).
- Joiners probe every two seconds, tolerate three consecutive 2.5-second timeouts, and distinguish refusal from delay. A surviving lead takes the lock and starts on the same port with its replica; workers mark the relay lost instead ([packages/relay/src/index.ts:732](../../../packages/relay/src/index.ts#L732)). The header's claim that restart “loses nothing” is conditional on surviving replicas; it is not a durability guarantee.
- The hub remains the authority for names, ordering, trimming and expiry. Type-7 frames, 45-second lease TTL, 15-second renewal and five-second settlement are already defined ([packages/hub-core/src/protocol.ts:9](../../../packages/hub-core/src/protocol.ts#L9)). Incarnations are durable before issuance; private lease files, not replicated holder assertions, restore authority ([packages/hub-core/src/hub.ts:247](../../../packages/hub-core/src/hub.ts#L247), [packages/hub-core/src/hub.ts:278](../../../packages/hub-core/src/hub.ts#L278), [packages/hub-core/src/hub.ts:251](../../../packages/hub-core/src/hub.ts#L251), [packages/relay/src/hub.ts:50](../../../packages/relay/src/hub.ts#L50)).
- `RoomMemory` loads private `.ydoc` snapshots, saves after a two-second debounce or ten-second activity deadline, and reconciles repeated historical array events by identity. It copies selected values into fresh CRDT types, not the entire live document. Coordination, retained claims, owed mail and bounded completed-worker publications survive; live file text and graphs rebuild. Target is 5 MiB, hard ceiling 64 MiB ([packages/relay/src/memory.ts:46](../../../packages/relay/src/memory.ts#L46), [packages/relay/src/memory.ts:119](../../../packages/relay/src/memory.ts#L119), [packages/shared/src/memory.ts:12](../../../packages/shared/src/memory.ts#L12), [packages/shared/src/memory.ts:47](../../../packages/shared/src/memory.ts#L47)). Atomic replacement fsyncs a writable handle before rename. Failures before replacement preserve the prior file; directory fsync runs after rename, so its failure may leave the new file installed with durability uncertain ([packages/relay/src/memory.ts:82](../../../packages/relay/src/memory.ts#L82), [packages/relay/src/memory.ts:100](../../../packages/relay/src/memory.ts#L100)).
- Final save retries at 100/200/400/800/1500 ms. Successful save precedes synchronous detachment and socket termination; failure leaves the relay serving. `leaveSession` first stops the publisher, then stops its relay and returns a save warning ([packages/relay/src/memory.ts:179](../../../packages/relay/src/memory.ts#L179), [packages/relay/src/index.ts:590](../../../packages/relay/src/index.ts#L590), [packages/room-mcp/src/session.ts:1196](../../../packages/room-mcp/src/session.ts#L1196)).
- Automatic join is single-flight, bounded to 120 seconds, with backoff and a 30-second tool-triggered retry cooldown; explicit leave cancels it. It remembers adopted session policy. This is not an indefinitely running worker reconnection service ([packages/room-mcp/src/auto-join.ts:42](../../../packages/room-mcp/src/auto-join.ts#L42), [packages/room-mcp/src/auto-join.ts:96](../../../packages/room-mcp/src/auto-join.ts#L96), [packages/room-mcp/src/auto-join.ts:136](../../../packages/room-mcp/src/auto-join.ts#L136)).

Historical decisions describe keyless loopback access and a relay-served page; neither describes today's security boundary ([docs/decisions.md:210](../../decisions.md#L210)). Current code uses proofs, encrypted sockets and a packaged file viewer ([packages/relay/src/index.ts:194](../../../packages/relay/src/index.ts#L194), [docs/reference.md:39](../../reference.md#L39)).

## Proposed design

### Process lifetime and ownership

Run one small Node daemon per canonical Git common directory, shared by its existing named local rooms. Ship a separate bundled daemon entry point alongside the MCP bundle, reusing `@room/relay` and `@room/hub-core`. The daemon runs transport, memory and hub maintenance only. Watching, parsing, wake delivery, worker launch/collection and team bridging remain with their current owners. No login service, global daemon, OS service installation, supervisor, SQLite migration or new participant role is required. Database consolidation and host adapters remain separate; protocol negotiation must ship before this lifetime change, while the in-session relay remains supported. The roadmap lists those projects ([docs/roadmap.md:37](../../roadmap.md#L37)).

Any verified repository-bound local client may *ensure or restart the daemon*, including a dispatched worker or a nested host. It may launch the shipped executable; it never takes relay authority in its own MCP process. This deliberately replaces the 0.17.31 lead-only startup rule: the incident concerned running transport on a worker's busy event loop, not granting that same-user process permission to request a separate transport process. Existing worker clone validation remains mandatory. No daemon starts from an unbound MCP, tool listing, browser page, or mere repository scan.

Launch without a shell, using the running Node executable and absolute bundle/common-directory paths. Use a stable cwd outside removable worker worktrees, ignored stdin, private rotating logs (1 MiB per file, three files including the active log, bounded/truncated individual records), and a detached/unreferenced child independent of the launching session's pipes. Pass an allowlisted runtime environment; strip worker/session identity, team credentials and host configuration. The daemon reads an existing key from private discovery, never from its command line. On first start, only the authority-lock winner generates a cryptographically random clone key after confirming discovery is absent (ENOENT); parents never write keys or discovery. Unreadable, malformed or unsupported discovery blocks initialization with a repair diagnosis, never silent key rotation. Under the lock, re-read discovery, validate private ownership, bind and initialize authority, then atomically publish the key/endpoint once readiness is possible. Publication failure must return a bounded startup error within the join deadline and close the unpublished listener/release authority; do not accept writers or leave an orphan. Reuse a valid existing key on restart; explicit rotation requires drained maintenance. Do not fall back to an in-process relay if launch is denied by the host sandbox: report the launch failure and retain the existing bounded join retry behavior.

The child itself takes the existing authority lock before listening or writing shared state. Concurrent launches may create short-lived contenders; only one child acquires authority, and losers exit. Parents wait for authenticated readiness rather than treating a successful spawn as connection. Keep a single launch in flight per MCP, with bounded attempts inside the join deadline; repeated early crashes produce a visible failure, not a tight respawn loop. A startup child that cannot publish discovery closes its listener and releases authority before accepting writers. This closes the current discovery-write path's log-and-continue ambiguity.

Session exit and explicit `room_leave` disconnect that client and end its publisher/leases; neither requests daemon stop. Failed initialization, host identity rebinding and involuntary connection recovery instead follow the replica-preserving transport contract below. Within a live client, explicit user leave is the only lifecycle path that disposes its Y.Doc; process death remains loss of that replica. Worker process ownership and stop authorization do not move into this daemon.

Default exit policy: after **five minutes with zero authenticated writer sockets across all rooms**, attempt a durable idle stop. Leads, workers, bridges and nested hosts count equally. Read-only viewers, pending handshakes and unauthenticated probes do not keep it alive or reset the countdown. A verified writer arrival before draining cancels the countdown. There is no lead count or parallel heartbeat registry. Status distinguishes writer, viewer and pending counts; the viewer shows that idle shutdown can disconnect it.

On idle expiry, enter draining in the same event-loop turn that checks the writer count. Refuse new upgrades and reject completion of *already upgraded* secure handshakes with a retryable draining response before `attachReady` or any document attachment. Re-check draining after each awaited admission/negotiation step; no pending handshake may become a writer during the awaited lease flush. Current handshake completion has no such fence ([packages/relay/src/index.ts:220](../../../packages/relay/src/index.ts#L220)). Flush private hub leases before the final snapshot pass; save success and detachment share a synchronous turn, as today. Disconnect remaining viewers only after successful save. A racing client retains its replica and retries discovery. On failure, reopen bounded admission (including capacity repair), retain documents/listener/authority, expose the specific storage state, and retry after backoff capped at 60 seconds even without further edits. Never exit merely to satisfy the idle timeout while memory is unsaved.

An explicit local maintenance command may request an authenticated orderly daemon stop, refusing while authenticated writers remain (viewers receive shutdown status). It reports pending/failed save rather than claiming success. An OS termination request follows the same save-first path; forced kill, logout and power loss remain abrupt-death cases. No automatic reboot startup: the next bound client starts it. Daemon status and logs must make a save-blocked, otherwise idle process discoverable to the user.

### Discovery and crash recovery

Keep `room/relay.json`, the existing clone identity, deterministic port with collision fallback, clone key, authority lock, incarnation record and per-room lease paths. Avoid a second lock, PID registry or election protocol. Extend discovery and nonce-authenticated health with runtime kind (`in-session` during the negotiation release, `daemon` at cutover), compatibility version and bundle release; schema 2 and hub protocol 1 remain distinct fields. Validate port range, record size and supported versions before connecting. Add no secret to public health beyond its existing nonce proof.

A dead daemon is restarted by the next bound local client, whether lead or worker. Recover the existing lock only with affirmative process-death evidence; timeout or unknown identity is never permission to replace a live owner. Prefer the recorded port and key so existing providers and browser links reconnect. If that port is occupied, prove the occupant's clone identity before choosing a fallback; clients must rediscover and rebind their transport URL if the port changes, retaining the same Y.Doc as specified below. A file viewer cannot read discovery: show a disconnected state and request a fresh link in this exceptional case.

Load snapshots, advance the hub incarnation through the existing durable store, restore private leases, then accept room traffic. A lazily opened room returns `starting` until its hub is ready. Surviving clients resync their replicas through normal encrypted Yjs sync; they do not supply a special startup seed or regain authority from replicated holder records. Preserve the hub's existing settlement and stale-replica rules. Preserve client IDs for retrying uncertain posts so an acknowledgement lost during a crash does not create a new logical post.

The logical local session owns the Y.Doc independently of providers and join attempts. Transport rebinding disconnects/destroys only the old transport, then connects a replacement provider to that **same Y.Doc**, renegotiates and completes ordinary Yjs resync before resuming publication or declaring joined. Rewire hub, awareness and session references without creating duplicate publishers or granting authority from replicated holders. Do not implement recovery by `leaveSession`: today it calls roomd stop, which destroys both provider and document ([packages/room-mcp/src/session.ts:1198](../../../packages/room-mcp/src/session.ts#L1198), [packages/roomd/src/index.ts:707](../../../packages/roomd/src/index.ts#L707)). Split transport disposal from explicit-leave disposal in implementation.

This rule covers same-port reconnect, fallback-port rediscovery, daemon restart, delayed/failed participant initialization, host session-ID rebinding, compatibility refusal, retry exhaustion, internal cancellation and late join results. Failed/cancelled attempts dispose only their transport/resources; keep the one session-owned replica paused and visible for the next tool-triggered or explicit join, without endless background retries. Only explicit user leave ends recovery intent and disposes it; a late result cannot recreate a left session. Explicit room close/forget retains its authorized replicated deletions, but is not a recovery mechanism or a reason to destroy the client document. A mismatch requiring a different room/schema/generation must stop and request an explicit user decision rather than discard/merge the surviving replica automatically. The daemon cutover itself changes none of those axes.

Retain busy-host probe tolerance for connection diagnostics. Eliminate the relationship between missed probes and becoming the relay. Clients may request a replacement child after verified death; the authority lock remains the final exclusion mechanism. If the daemon is alive but wedged, report its identity and last successful probe; no automatic kill or forced takeover. Ordinary join remains bounded; workers still working outside Room may need a later tool call or explicit join after its retry window ends.

### Authentication of local clients

Reuse the current loopback-only listener, clone-key challenge/response, port-bound `Authorization: Room-Proof`, replay checks, in-band secure handshake and AES-GCM frames. Keep schema and hub admission checks. Do not use PID, `lead: true`, an asserted worker tag or an HTTP origin as authentication. The daemon owns no agent identity; local writers remain authenticated as clone-key holders with distinct hub session leases ([packages/relay/src/index.ts:470](../../../packages/relay/src/index.ts#L470), [packages/relay/src/index.ts:560](../../../packages/relay/src/index.ts#L560), [packages/hub-core/src/protocol.ts:48](../../../packages/hub-core/src/protocol.ts#L48)).

Use the existing proof for the small maintenance stop API; require loopback, a method/path-bound proof and the exact daemon PID/nonce. Attached writers recover as for planned compaction; an already-draining daemon refuses another stop. Browser view capabilities cannot call it or forget memory. New local administration does not imply a new permission hierarchy between same-user leads and workers.

### Memory snapshot persistence

Keep the existing selective snapshot format, target/ceiling, temp-write/fsync/rename discipline and publication-revision rules. No WAL or save-on-every-post promise in this change. Preserve the two-/ten-second schedule, but track dirty generation, last successful snapshot and failure cause per room; a failed periodic save schedules bounded retry even after traffic stops. Surface this through authenticated diagnostics and `room_state(check=true)`, with a rate-limited actionable warning. Public `/health` may expose a storage status without room contents or paths.

Keep separate per-room capacity and I/O states; neither automatically forgets a room or disposes its live replica. Do **not** wire all snapshot failures into hub `unavailable`. That callback suspends admission/lease timing, not repair policy ([packages/hub-core/src/hub.ts:394](../../../packages/hub-core/src/hub.ts#L394)).

- **Capacity blocked:** an over-ceiling selective snapshot or live document cap rejects growth, while retaining authenticated reads, status, export, empty sync and deletion-only updates. Reuse the local non-growing admission path ([packages/relay/src/index.ts:240](../../../packages/relay/src/index.ts#L240)); it bounds deletion-update decoding to 4 MiB ([packages/hub-core/src/doc-cap.ts:55](../../../packages/hub-core/src/doc-cap.ts#L55)). Apply capacity admission for snapshot overflow too, even if the live-size meter has not caught up. New posts/publications and other growing coordination requests receive a distinct capacity diagnosis. Do not reject a repair connection merely because the room is full. Clients pause growth, keep the replica and offer read/export and deliberate deletion of selected retained records, including protected roots. Deletion protection against automatic shedding is not a ban on authorized explicit cleanup. Do not require a new receipt/acknowledgement record that itself inserts structs to perform repair; use deletion-only updates in bounded batches. Unsent growing local changes remain in the retained client replica and must not prevent a separate deletion-only repair batch from reaching the daemon.
- **Repair/export contract:** retain clone-key authentication and normal room/ownership checks. Read-only viewer tickets cannot mutate or administer storage. Use the existing encrypted sync path for deletions; Yjs update delivery alone is not a tool acknowledgement. A repair tool verifies the requested deletions by authenticated daemon read-back and reports applied-in-memory with dirty generation and last saved generation; it reports persisted only after a successful snapshot covering that repair. Export is bounded streaming of retained logical records (including protected roots) under existing frame/output budgets, with backpressure and cancellation, never an unbounded single-buffer snapshot. Report coverage, completion/failure and generation; partial export is not a backup. Export/cleanup never calls forget or clears unrelated state. Retry the snapshot after reduction; clear capacity status only after remeasurement and successful save. Keep the repair/export route available during failed-stop retries; no restart is needed to repair.
- **I/O degraded:** ENOSPC, permission, write, rename or fsync failures retain the document and authority and schedule autonomous bounded retry/status. Preserve existing bounded growth admission and the same repair/export route; do not introduce blanket publisher or coordination suspension for periodic snapshot I/O failures. Accepted posts retain the in-memory acknowledgement contract and carry a visible unsaved-storage warning. Private authority-store failures may still use hub unavailable, with reads/export retained and authority repair surfaced separately. On pre-rename failure preserve the prior snapshot; on post-rename directory-fsync failure report durability uncertainty and retain memory, since the prior file may already be replaced. Capacity and I/O failures can coexist and must be reported separately.

A successful orderly stop means selected memory is saved, not that every live overlay or graph is archived. Keep completed-worker cache authority checks. The maintainer accepts delayed-snapshot durability: after **loss of every replica**, acknowledged posts since the last successful snapshot can be lost (normally the two-/ten-second scheduling window; persistent I/O/capacity failure extends it until the next successful save). Acknowledgement is not disk durability. With any surviving client replica, every involuntary reconnect must preserve it and resync those facts; the loss exception never authorizes recovery code to discard that replica. No WAL or save-before-ack requirement is introduced.

Snapshot load has four explicit outcomes: **absent** (ENOENT: initialize new memory), **loaded** (validated bounded snapshot), **unreadable** (retry without rename/replacement), and **invalid** (readable but undecodable/incompatible: preserve evidence and block normal room startup). Oversized files are capacity-blocked load failures: preserve bytes, expose bounded raw export and require validated offline reduction before load, never treat them as absent. While unreadable/invalid, do not publish an empty room, attach writers or overwrite the original from an empty document. Bounded authenticated status/export remain available where reading is possible. Empty recovery requires an explicit user decision acknowledging incomplete history and a verified preserved copy/quarantine of the original; failed preservation blocks it. Current `loadMemory` conflates errors, ignores quarantine failure and starts empty, so changing that loader is required ([packages/relay/src/memory.ts:58](../../../packages/relay/src/memory.ts#L58)). Authority recovery is independently fail-closed: unreadable/invalid lease/incarnation files block issuance until repaired, retaining evidence. `Hub.start` currently catches lease-load failures and adopts none, so that behavior must also change ([packages/hub-core/src/hub.ts:267](../../../packages/hub-core/src/hub.ts#L267)); this is not already provided by reusing the loader.

`room_close confirm=true` keeps its export/forget contract and current replica-clearing behavior; it is not daemon shutdown and must not stop other named rooms. Do not permit retries to recreate forgotten snapshots ([packages/relay/src/memory.ts:158](../../../packages/relay/src/memory.ts#L158)). Stronger close generations against stale replicas are a separate protocol decision, not a claimed benefit of moving the process.

### Workers, nested hosts and browser view

All use the same per-clone endpoint. Preserve local destination, worker run identity, sharing policy and cross-clone refusals. Nested hosts with scrubbed variables can request the daemon but never host it; restarting them cannot move transport. A team lead's local-worker bridge connects as another local client and remains responsible for team publication.

Two leads in one checkout remain separate participants and clients. Checkout publisher/graph arbitration remains in `checkoutLead`; the daemon neither indexes that checkout nor chooses which agent may publish it ([packages/room-mcp/src/session.ts:1186](../../../packages/room-mcp/src/session.ts#L1186)).

Keep the packaged file viewer and fragment capabilities. The room-scoped view key mints short-lived, single-use, read-only tickets; viewers cannot publish awareness, document updates or hub operations ([packages/relay/src/index.ts:491](../../../packages/relay/src/index.ts#L491), [packages/relay/src/index.ts:255](../../../packages/relay/src/index.ts#L255), [packages/relay/src/index.ts:180](../../../packages/relay/src/index.ts#L180)). No executable viewer content comes from the daemon. A viewer can reconnect after a daemon crash once a Node client restarts it; the browser cannot launch local processes. Do not promise a daemon restart from a lone browser.

### Windows

Use the same Node child entry point, loopback TCP and common-directory files on macOS, Linux and native Windows. No Unix socket, fork-only path, shell wrapper, `nohup`, service installer or new native dependency. Detachment, survival of terminal/host closure and log handle lifetime require native Windows end-to-end evidence, including any host process-tree termination behavior; an option called detached is not proof of survival.

Reuse birth-marker/executable checks and their unknown-liveness behavior. Cached Windows identity queries run asynchronously with bounded concurrency; own-identity initialization and definitive `fresh`/`confirm` queries remain synchronous ([packages/relay/src/process.ts:198](../../../packages/relay/src/process.ts#L198), [packages/relay/src/process.ts:296](../../../packages/relay/src/process.ts#L296), [packages/relay/src/process.ts:305](../../../packages/relay/src/process.ts#L305)); an unreadable or pending identity is not death ([packages/relay/src/process.ts:11](../../../packages/relay/src/process.ts#L11), [packages/relay/src/process.ts:62](../../../packages/relay/src/process.ts#L62)). Retain writable-handle fsync ([packages/relay/src/memory.ts:98](../../../packages/relay/src/memory.ts#L98)). Test discovery replacement under antivirus/OneDrive contention, spaces, linked worktrees and canonical path aliases. POSIX modes are insufficient on Windows: before publishing discovery, verify the state directory and key/snapshot/log files are owned by the current user and have a protected DACL granting access only to that user, SYSTEM and local Administrators. Inspect resolved inherited/explicit ACEs via Windows security APIs or a bounded native ACL query; POSIX chmod success is not evidence. Refuse startup if ACL inspection is unavailable, ownership is wrong, or another principal has access. Diagnose the offending path/principal without printing secrets and give a remedy: use a private local clone/state directory, remove broad inherited grants and apply the stated DACL, then rerun verification. Do not silently alter ACLs of the whole checkout. Native tests must cover broad inherited grants, explicit grants, denied inspection and the corrected private DACL. Do not claim network-shared Git directories provide cross-machine singleton semantics; that remains unsupported.

## Compatibility and migration from 0.17.x clones

Release **protocol negotiation first**, with the existing in-session relay still permitted; ship the daemon later as an **explicitly drained cutover**. The update-on-disk incident motivates checking the running process rather than installer files ([docs/roadmap.md:26](../../roadmap.md#L26)). Follow the [protocol-negotiation spec](2026-11-05-protocol-negotiation.md) for its tested baseline and support window; this spec does not withdraw compatible legacy connections at negotiation introduction.

1. **Negotiation release:** new clients may join an old compatible in-session relay using the tested schema-2/proto-1 baseline adapter, until the drained daemon cutover release. Runtime `in-session` or missing daemon metadata alone is not an incompatibility in this phase. New relay/client builds negotiate before sync when both support it; explicit baseline fallback is allowed only for a positively identified supported legacy contract, never after a failed/malformed advertised negotiation. Keep the existing role/ownership lifecycle in this release. Publish exact supported tags and baseline matrix; no release number is invented here.
2. **Prepare daemon cutover:** inventory every old local client across the clone and linked worktrees: leads on both hosts, dispatched workers, nested hosts, local/team bridge sessions and viewers. Stop new launches/reconnect loops with the old plugin while retaining worker files/results. Quiesce publication and establish preservation before stopping the old owner. On 0.17.31–0.17.32, require observed successful final save/owner exit and validation of the resulting selective snapshot and private authority files. On 0.17.25–0.17.30, stop success alone proves nothing: while the old replica is alive, obtain a quiescent checkpoint, validate it through the selective snapshot loader in isolation and compare required claims, mail, receipts and completed-publication revisions with the live room. An ordinary human-readable export is supplementary, not necessarily reloadable selective memory. If evidence cannot be established, keep the owner/replica alive, resolve storage or use a separately verified checkpoint tool; postpone cutover. Never kill the sole replica to upgrade.
3. **Drain fully, then restart:** finish all old client shutdowns and verify the old owner is dead with the existing birth-identity checks. Update installed plugins on both hosts; restart updated clients only after that drain is complete. Unknown liveness blocks. The daemon takes the same authority lock, preserves key/port where possible and loads existing schema-2 snapshots, incarnation and lease files in place. Keep the bounded 0.16 catch-up helper for older retained history. No new bulk migration/deletion or `/handover` is introduced.
4. **Daemon cutover release:** only at this release do new local clients require daemon runtime and refuse mixed local runtimes. Finding a live in-session owner reports its PID/port, release when known and the drain requirement, without competing or forcing shutdown. An owner without `lead` is still an old runtime; do not stamp `lead: true` on a daemon to hide warnings. Old code cannot be fenced by new discovery fields: it can attempt reconnect or become an in-session owner after daemon death. The daemon requires a negotiated local daemon-lifecycle capability from writers (external transport ownership, replica-preserving rebinding and no in-session takeover); negotiation-first clients lacking it are refused too. Viewer profiles require compatible read negotiation, without launch authority. Reject unnegotiated/unsupported writer and viewer profiles before sync; new clients finding an old takeover report unsupported mixed runtimes and require another drain, never start a parallel listener. This is a visible diagnosis and operator procedure, not a guarantee that metadata controls old binaries.

Compatibility is checked at the **consuming endpoints**. Authenticated health binds clone identity/runtime/release/compatibility advertisement to its nonce proof; discovery is only a hint. After secure authentication, the negotiation selection and acknowledgement must complete before attaching either incoming or outgoing Yjs, awareness or hub operations, including on an already upgraded socket. Both client providers (probe and final roomd), relay and packaged viewer enforce the selected runtime/contract. Viewer ticket issuance binds the offer to room/read-only credentials; a viewer mismatch shows a disconnected compatibility error with versions and restart/update guidance, disables empty-room panels and stops retrying incompatibility. Reconnect renegotiates; incompatible installed viewer assets cannot silently attach to an old running relay. Use the shared negotiation machinery from the first release, not a second daemon-only protocol.

No endpoint identity or snapshot-schema bump is needed for lifetime alone. Rollback requires a successful drained daemon stop and validated reloadable snapshots, then all daemon clients stopped before old binaries start. Never run old/new owners concurrently. For later daemon upgrades, a strictly newer numbered client requests an authenticated exact-instance graceful stop, then starts its release under the same authority lock; equal or older clients reuse it. Development builds on either side have no version order and are reused. Refusal or timeout keeps the running process with a diagnostic; never kill it for an upgrade. Its self-contained bundle must survive installer removal without lazy imports from that version's directory.

## Failure modes and recovery

| Failure | Required behavior and recovery |
| --- | --- |
| Launching lead leaves, restarts or crashes | Daemon and other clients remain connected; no authority transition. If no authenticated writers remain, idle-save policy applies. |
| Worker or nested host launches first | A separate daemon owns transport. Worker remains an ordinary client and can leave without stopping it. |
| Simultaneous starts or crash recovery by several clients | Existing authority lock admits one daemon. Losers exit; parents authenticate the winner. No second state store. |
| Healthy but lagging daemon | Tolerant probes and bounded retries; never reclaim a live/unknown lock. Report delay instead of a successful connection. |
| Forced daemon death | Next bound client restarts it; recover snapshot/private leases and rebind/resync survivors without destroying their Y.Doc. Unsaved-history loss is admitted only if every replica holding it was lost. |
| Snapshot/live-state capacity exceeded | Reject growth; retain authenticated bounded deletion-only repair, read/export and status. Keep memory and authority, retry after reduction, then permit orderly stop; never forget automatically. |
| Disk full, permission, rename/fsync error | Retain memory/authority and bounded admission, expose I/O degraded, retry without new edits. Prior file survives pre-rename failure; post-rename fsync failure means durability uncertainty. Idle stop fails visibly and reopens repair admission. |
| Unreadable/invalid snapshot | Block empty-room publication and replacement, preserve evidence, retry reads or require explicit verified repair/empty-recovery decision. |
| New room/update arrives during stop retries | Fence upgrades and pending handshakes during each drain attempt; reopen bounded repair admission on failure; retries snapshot every retained room. No accepted update between successful final snapshot and detach. |
| Stale/malformed discovery, foreign port or PID reuse | Validate bounded record, key and clone proof; use process birth identity for recovery, never kill by PID alone. Report foreign ownership and rediscover. |
| Unreadable lease/incarnation record | Preserve evidence; surface authority recovery failure, never infer ownership from a replicated holder. Incompatible or corrupt authority state requires explicit repair. |
| Removed worktree/plugin directory | Daemon cwd and loaded bundle survive; it does no indexing. Removed common directory yields a visible storage failure, not recreation through an unverified replacement path. |
| Host disallows detached process/listen | Report daemon startup unavailable; files remain usable locally. No concealed transport fallback or team-room switch. |

Preserve the current local caps (eight retained rooms, 200 total sockets, 100 per room), document cap and bounded awareness/output queues; retain idle room documents until safe whole-daemon stop. These bounds already exist to limit a retained relay's cost ([packages/relay/src/index.ts:75](../../../packages/relay/src/index.ts#L75), [packages/relay/src/index.ts:437](../../../packages/relay/src/index.ts#L437), [docs/reference.md:200](../../reference.md#L200)). Log metadata and causes, not document contents, keys or message bodies. Expose daemon PID, release, uptime, connection count and storage status separately from MCP health so two leads do not obscure who owns transport.

## Security against the threat model in deploy/self-hosting.md

The current `deploy/self-hosting.md` has no separately titled threat model. Its concrete boundaries are explicit team admission and bearer view capabilities ([deploy/self-hosting.md:39](../../../deploy/self-hosting.md#L39), [deploy/self-hosting.md:69](../../../deploy/self-hosting.md#L69), [deploy/self-hosting.md:41](../../../deploy/self-hosting.md#L41)), safe capacity settings ([deploy/self-hosting.md:45](../../../deploy/self-hosting.md#L45)), private credential backups ([deploy/self-hosting.md:174](../../../deploy/self-hosting.md#L174)), and a local path boundary that trusts the user's own writers and explicitly does not close directory-swap races ([deploy/self-hosting.md:249](../../../deploy/self-hosting.md#L249)). This proposal applies those boundaries locally; it does not invent a stronger guarantee for same-user malicious code.

| Actor / asset | Boundary and design response |
| --- | --- |
| Remote network attacker | Bind literal loopback only; no team proxy, forwarded-address trust, public listener option or remote spawn API. Team credentials/admission never enter this daemon. |
| Hostile web page probing localhost | Loopback is insufficient authentication. Retain explicit proofs, replay limits, single-use room tickets, secure handshake and encrypted frames. A view capability grants only room reads; no ambient cookies or raw-key URL path. |
| Unrelated local OS user | Protect discovery, snapshots and logs with private directories/files and Windows ACLs. Proof possession, not port/PID knowledge, permits writes or maintenance. A shared checkout whose key is readable by another user does not meet this boundary. |
| Authorized local writer or malicious repository content | Local clone-key holders share a trust domain, not per-person permissions. Never execute repo startup/config scripts to start transport; resolve bundle from the installed plugin and preserve current file/path validation. Transport isolation is not a sandbox against same-user code. |
| Leaked browser link or disk backup | Retain fragment-only room capability and private redirect files. Links remain sensitive even after the last lead exits because the daemon may still serve them. Key rotation requires a drained maintenance operation and fresh links; do not silently rotate on restart. Snapshots can contain claims, plans and completed-worker code: treat backups as private. |
| Resource exhaustion / poisoned authority data | Preserve transport/hub quotas, load ceiling, frame validation and trusted-incarnation bounds. Unknown liveness fails closed. Reject unsupported compatibility before syncing rather than corrupting shared state. |

Capturing canonical roots and refusing replaced/symlinked state roots must follow the existing local-path contract. No claim is made that Node closes a malicious same-user directory swap between check and use. Starting the daemon must never widen sharing, resurrect a retired worker's publisher authority, or silently select a team destination.

## What is deleted

At the daemon cutover release, after negotiation has shipped and the explicit migration path is implemented and verified (retain these mechanisms during the negotiation-first release):

- Delete in-process relay creation and `owned` stop semantics from MCP clients; `joinLocal` becomes ensure-daemon plus connect, and `leaveSession` only leaves. Remove the replica seed closure and teardown on failed participant initialization ([packages/room-mcp/src/session.ts:953](../../../packages/room-mcp/src/session.ts#L953)).
- Delete session-side relay takeover intervals, ownership role detection solely for relay creation, owner-warning transfer logic and the worker “waiting for the lead” branch. Retain worker identity and clone checks wherever they protect worker operations, and retain checkout publisher leadership.
- Replace takeover tests with separate-process lifetime/recovery tests. Do not retain both mechanisms as selectable defaults; sandbox launch failure is an error, not an ownership mode.
- Do not rebuild the already deleted handover endpoint, reclaim timers or a client reference-count registry. Authenticated writer socket count supplies idle evidence; the existing authority lock supplies exclusion.

Keep the relay transport implementation, proof/secure/ticket logic, caps, hub, process-identity helpers, discovery identity checks, snapshot machinery, final-save retry, migration helpers still needed for older data, `roomd`, worker registry and checkout graph arbitration. Each protects an incident or an existing security boundary; daemonization does not justify removing it. The additional machinery is a child entry point/launcher for isolation, an idle timer for bounded lifetime, storage retry/status for save failure, and reuse of the previously shipped negotiation gate for update skew. Transport rebinding and explicit storage load/capacity/I/O states are required correctness changes; they are not already supplied by process isolation.

## Remaining open question

What exact release tags/digests and date will identify the negotiation-first compatibility matrix and the later drained daemon cutover? The ordering, replica/durability contract, symmetric verified launch authority, viewer exclusion and five-minute writer-idle default are settled. Native host survival, Windows ACL privacy and storage recovery remain implementation acceptance gates, not unresolved policy choices or completed evidence.

## Five-line summary

One daemon per Git common directory owns transport independently of agent sessions.
Any verified bound clone client may start/restart it; viewers do not delay the five-minute idle stop.
Every involuntary reconnect retains the Y.Doc; all-replica loss admits the delayed-snapshot loss window.
Capacity retains bounded authenticated shrink/export recovery; I/O failures retain memory and retry.
Negotiation ships first with compatible old relays allowed; daemon runtime enforcement begins at drained cutover.
