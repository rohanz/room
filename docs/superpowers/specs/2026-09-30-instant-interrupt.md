# Codex `instant_interrupt` and Room wakes (2026-09-30)

Codex 0.159.0 added the opt-in `instant_interrupt` feature (PRs 48135 and 48141). User input typed into an active session can preempt a streaming model response, retry backoff, or a running code-mode cell. The cell yields and the turn continues with that input. The feature is disabled by default. This worker runs Codex 0.158.0; the lead checked the wake behavior on 0.159.2.

Room sends a content-free pointer with `codex queue --thread … --message …` (`wake-path.ts`). `WakeReconciler.pass` checks `CodexTurnProbe.busy` before sending. All wakeable kinds, including interrupt-priority messages, addressed notifications and worker events, use this same path. Failed sends retry through the same reconciler. There is no priority bypass. The ledger's MF8 rule treats a wake as a prompt to call `room_state`, never a delivery receipt. `wake-turn.test.ts` also requires no queue while a Codex turn is active, so a hook can receipt a message without a redundant wake.

The lead's live check on 0.159.2 used `--enable instant_interrupt`. In the interactive TUI, a 1,500-word response started at 03:56:22Z and `codex queue` sent "STOP…" at 03:56:41Z. The response completed at 03:57:25.778Z; a new turn began at 03:57:25.793Z and read the queued message. A `codex exec --json` run behaved the same way. Thus `codex queue` input waits for the turn boundary even with `instant_interrupt` enabled. A Room wake arriving in the busy-check-then-queue race does not preempt the active response. The existing busy check still prevents ordinary mid-turn queue attempts and redundant wakes; no change to the wake path is needed. `wakes.json` still records only that a pointer was queued, never that the ledger message was seen.

`codex queue --help` lists `--disable instant_interrupt`, but there is no need to pass it: the observed queue behavior already waits for the turn boundary. The PRs describe preemption in the receiving session, so a flag on the separate queue CLI process should not be assumed to change that session. The lead did not test a human typing into an active response; that is the feature's intended path and is separate from Room. Room's interrupt priority does not deliberately preempt an active model turn under the current ledger rules.
