## 4. Ledger B: kill -9 the Claude-side MCP between the hook's print and its confirm — PASS

`s4.mts` sets up the room:
- `lead` (the bundle) is in `/tmp/room-w2-s4`.
- `bea` is the bundle with `ROOM_HOST=claude`, `CLAUDE_CODE_SESSION_ID=w2-bea-session-1` and
  `ROOM_ROOM=local/room-w2-s4/main`, in the worktree `/tmp/room-w2-s4b`. It binds to that session and publishes
  `mcp.json` and `state.json` in `<common>/room/sessions/6c44361f56dadb06/`.
- The lead sends bea a question. Then the script runs the real `before-edit.mjs` with a `PreToolUse` Bash event
  for that session.

**How the kill lands between print and confirm:**
- The first hook's stdout is a FIFO that the script has already filled to capacity (8 KiB).
- On macOS, Node writes to a pipe asynchronously. The hook's `writeStdout` callback, which sends the confirm, fires
  only after the pipe drains. A probe measured the callback at 1468 ms while the FIFO was held full.
- The script waits 1.5 s, so the hook has selected and the MCP holds the hook batch. It then sends kill -9 to bea's
  MCP and drains the FIFO with `cat`.
- The hook's bytes are handed off, and the confirm goes to a dead endpoint.

The first attempt drained the FIFO with `fs.readSync` on a non-blocking fd, which never returned. That hung the
driver after the kill (the hook itself exited). It was rerun with the `cat` drain on a fresh repository.
