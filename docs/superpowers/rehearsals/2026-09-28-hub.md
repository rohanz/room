## 3. Partitioned holder — PASS (4/4)

`r3.mts` puts a TCP proxy between P and the server; Q connects directly. Both are logged in as `pat`, with two
sessions. While black-holed, the proxy queues every byte and every close in both directions: it forwards nothing
and closes nothing, as a TCP partition would. A connection that arrives meanwhile is accepted and held the same
way. P acquires `pat` and posts `p-0` under the lease. P then renews, and the proxy black-holes as soon as the
ack arrives. Every 25 ms the script polls `P.paused()`. Every 2 s P posts under `lease: {name: 'pat', epoch}`.
Every 500 ms Q tries to acquire `pat`. The proxy resumes 3 s after Q is granted. Then the script sends one renew
frame for P's old epoch over P's connection, through HubClient's request path without HubClient's local lease
check, since HubClient has already dropped the lease. Last, it reads the bus in Q's replica.

## 4. Two relays started together — PASS (40/40, 10 rounds)

Each round of `r4.mts` makes a fresh temp repo and has a foreign HTTP listener (`not a relay`) hold the clone's
`deterministicPort`. It then spawns two `r4-racer.mts` processes, X and Y. Both wait on a file barrier, polling
every 1 ms, and call `ensureLocalRelay` as soon as the `go` file appears. Each racer calls `hello` through the
relay URL it got. The orchestrator then records the racers' listening sockets (`lsof`) and the

## Observations (not failures)

- **(a) The paused text after a lost lease names the wrong cause.** After P reconnected in rehearsal 3, the hub
  was answering, but P had lost its lease. `HubClient.post` and `renew` still say "not sent: hub unreachable",
  and `paused()` still returns "[room] hub unreachable; coordination paused…". The cause is the lost lease, not
  the hub. The wording should be settled when wave 4 wires `paused` into replies.
- **(b) "Graceful" server restart.** The server installs no `SIGTERM` handler, so the graceful restart in
  rehearsal 2 is Node's default `SIGTERM` exit, with no flush. It passed all the same, because the incarnation
  record is fsync'd before the hub serves.
- **(c) The laptop-asleep variant is not rehearsed.** Spec §12 rehearsal 3 also asks for the partition with the
  laptop asleep for 2 min. That variant is covered only by the HubClient unit test for a 60 s wall jump
  (`room-mcp/test/hub-client.test.ts`).
