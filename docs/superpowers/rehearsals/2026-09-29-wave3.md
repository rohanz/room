| # | Scenario | Result |
|---|---|---|
| 1 | Flask-style: A at `declared` edits inside and outside its area; B previews A | **FAIL**: the manifest half holds (D1: no hash or size of an out-of-area file anywhere in the doc), but every preview of another participant fails with "participants' changes moved during the preview; re-run" |
| 2 | Carried preview: a local worker carries a file outside the lead's declared area | **FAIL**: the same preview error, from the worker and from the lead. There is no `withheld` special case in the source. |
| 3 | A `where: local` worker edits inside a teammate's team claim | **FAIL**: no conflict notice and no conflict slot. The projection never becomes fence-valid. |
| 4 | Both sides edit a file one of them holds outside its area | **FAIL**: nothing is reported at all, neither a possible nor a certified conflict. `ConflictSet` returns early and leaves no slot, not even an `unknown` one. |

**One cause behind all four: in the running system nobody writes a holder record.** The wave-3 readers
(`snapshot`, `versionOf`, `acceptedGit`, `ConflictSet`, the preview's currency check) accept a participant's facts
only when its `<name>\0holder.sessionId` equals the manifest fence. But in this bundle, no code path writes `\0holder`:
- The hub writes it on `acquire` (`hub-core/src/hub.ts:386`).
- `HubClient.acquire` (`room-mcp/src/hub-client.ts:141`) has no caller. Name acquisition is wave 4 (`names`).
- The daemon's fence is `daemon_<id>`, because `startRoomd` is never given a `sessionId` (`session.ts:552`;
  `roomd/src/index.ts:344`).

As a result:
- `fenceValid` (`shared/src/manifest.ts:79-82`) is false for every participant.
- `acceptedGit` (`shared/src/views.ts:63-66`) is `'updating'` for everyone.
- `buildCombinedTree`'s `isCurrent` (`combined-tree.ts:321`) is never true, so the preview throws after two
  attempts (`combined-tree.ts:21`).
- `room_read person=` answers "changes moved during the read".
- `ConflictSet.run` returns at `conflict-set.ts:177`.

The unit suites pass because their fixtures write a holder (`room-mcp/test/fixtures/manifest.ts`, `FIXTURE_HOLDER`).

**What would pass once holders exist (a harness stand-in, not a PASS).** To see whether the holder is the only
blocker, each scenario was run a second time:
- An in-process observer wrote `<name>\0holder = {sessionId: <that participant's manifest fence>}` for every direct
  writer, standing in for wave 4's hub grant (`emulateHolders` below).
- With that stand-in, scenarios 1, 2 and 4 behave exactly as the plan asks.
- Scenario 3 still fails. A projection is fence-valid only while the lead is `fresh`, and `fresh` requires
  `presence.sessionId === holder.sessionId` (`views.ts:43`). The daemon never puts a `sessionId` in its presence
  (`roomd/src/index.ts:533`, `this.sessionId` is unset). No doc write from outside can stand in for this.

**Finding B (a real bug, found while setting up): a local worker is refused admission when the lead's checkout path
is not canonical.**
- The first run used `/tmp/rh3-s2`, so `PWD=/tmp/…`, which is how a macOS shell reports a `cd /tmp/x`. The worker
  never joined:

  ```
  room-mcp: join attempt 1 failed this worker run was collected, discarded or superseded; retrying in 1s
  … join attempt 10 failed …; giving up for now
  LEAD: room_collect → [wk:…:1] [interrupt] lead+cw → lead's agent: worker cw failed: exited without room_done
  ```

- `admitWorkerEnvironment` compares `path.resolve(env.ROOM_REGISTRY) !== registry.root` lexically
  (`worker-registry.ts:101`).
  - The lead computed `/tmp/rh3-s2/.git/room/registry`. `gitCommonDir` (`roomd/src/git-dirs.ts:39`) resolves the
    relative `.git` against the lexical dir.
  - The worker's worktree computed `/private/tmp/rh3-s2/.git/room/registry`. Git reports a worktree's common dir as
    a realpath.
- Any lead whose working directory is reached through a symlink (`/tmp`, `/var`, a symlinked `~/code`) therefore
  loses every local worker. Comparing realpaths (`realGitCommonDir`, `git-dirs.ts:48`) would fix it.
- All later runs use `/private/tmp/…` paths.
