## Setup

- **No host configuration was touched.** `HOME=/private/tmp/rh5-home` was a scratch home. Nothing in `~/.claude` or
  `~/.codex` was read or written, and no plugin was installed.
- **Clean environment.** Every process ran under `/tmp/rh5-scripts/env.sh`: `env -i` with `PATH`, `HOME`, `USER`,
  `LOGNAME`, `SHELL`, `TMPDIR=/private/tmp/rh5-tmp/`, `LANG`, `TERM` and `GIT_TERMINAL_PROMPT=0`.
- **Participants** are bundles over stdio, each driven by a tsx MCP-SDK `Client` with a `StdioClientTransport`
  (`lib.mts` `participant()`). They run with Claude's environment:
  - `ROOM_HOST=claude`, `CLAUDE_CODE_SESSION_ID`, `ROOM_NAME`;
  - `ROOM_SERVER=ws://127.0.0.1:1264`;
  - a per-person `ROOM_CREDENTIALS` file;
  - `PWD` and the cwd set to the clone.
- **Observers** are pure CRDT readers: a raw `y-websocket` provider with awareness `null` and no hub frames. They
  connect either with `?session=…&schema=2` (repo room) or without `schema` (a 0.16-style socket on a branch room),
  and they record close codes.
- **Server.** A local dev server: `GITHUB_CLIENT_ID=fake PORT=1264 HOST=127.0.0.1`, with
  `YPERSISTENCE=/private/tmp/rh5-data`. Logins went through the fake `/auth/device` + `/auth/poll`. For one control
  (§2b), the released 0.16.34 server from a worktree at `8097a8b` also ran on :1265.
- **Fake GitHub host.** `mkrepo.sh <org/repo> <dir>:<branch>…` sets each repository up as follows:
  - It copies `examples/demo-repo` and makes one commit, then a bare origin from it.
  - It clones that origin, then runs `git remote set-url origin https://github.com/<org>/<repo>.git`. The clone
    therefore derives the team room `github.com/<org>/<repo>`, which the fake issuer admits.
  - It sets `url.<bare>.pushInsteadOf` so pushes land in the bare repository.
  - Fetches from the github.com URL cannot work. Where a fetch was needed it was done by hand from the bare
    repository (§1).

Scripts are in `/tmp/rh5-scripts/`: `lib.mts`, `mkrepo.sh`, `s1.mts`, `s1wait.mts`, `s2a.mts`, `s2b.mts`, `s3.mts`
and `s4.mts`. Logs are in `/tmp/rh5-logs/`. Both directories were removed after this report was written.

user who only calls `room_state` sees "OFFLINE" rather than the update text. Their `room_send` notes say "queued",
and those notes will never be delivered.

Control: the released 0.16.34 client against the released 0.16.34 server, on a plain `DELETE /rooms` 4001, behaves
the same way. The 0.17 server is not the cause.

A schema-2 socket that names the legacy room is mapped to the repo doc. A probe write through it landed in the repo
doc (`rh5probe`), and the archive stayed at 5584 bytes, unchanged.

**Claims carried: FAIL.**
- **Straight after migration** the repo doc held ann's claim, with `plans` and `origin: …/rm/main` and no `anchor`.
  The unique scopes (ann, dee) were copied, and cy's claims sat in `unresolved`.
- **Ben's claim and scope were already gone** by the time the first observer read the doc: ben's own 0.17 start had
  removed them.
- **Each owner's first 0.17 start releases its migrated claims and clears its scope,** although no line changed in
  any clone:

```
ben017 log: room-mcp: cleared 1 stale claim(s) from an earlier session
bus: [fyi] ben's agent: ben released 1 claim(s)
bus: [fyi] ann's agent: ann released 1 claim(s); ended 1 plan(s)      (ann017 start; plan on save ended)
bus: [fyi] cy's agent: cy released 1 claim(s)                         (cy017 start, right after reclaiming …/main\0cy)
POST2 claims: []     every 0.17 room_state: open claims (0); areas: none yet
```

The spec (reporooms, "Claim validation") says a migrated claim is kept where its `claimedHash` is found in the
clone. `Roomd.validateMigratedClaims` (`roomd/src/index.ts:892`) implements exactly that. The MCP's `adopt()` runs
first, though:
- `packages/room-mcp/src/index.ts:109-111` calls `tools.clearStale(s)` on every auto-join.
- `clearStale` = `cleanupMine(s, 'stale from an earlier session')` (`tools/state.ts:164`) →
  `releaseClaimsOnDone(s)` (`tools/claims.ts:143-147`).
- That releases every open claim `by` this name, with no exception for `origin`, and clears the scope.

The same path removes a reclaimed `unresolved` entry's claims once `aliases` re-owns them.

**The `5eddd26` build (`mig` run).** Migration and the 4001 behave the same. But the build's `room_claim` was refused
("no claim needed; nobody else is near", because the scopes failed to announce), and every `room_send` returned
"not sent: hub unreachable". So nothing owed existed to migrate, and that run proves nothing about mail or claims.

## 4. `room_close` while not joined — PASS

Two cases:

In each, the closer joined, called `room_leave` (after which `room_state` gave "error: not in a room"), and then


**Minor.** The teammate's `room_state`, 1.5 s after the close, showed the normal room with no "closed" or OFFLINE

- `room_state` is exempt from the closed check (`room-mcp/src/tools/index.ts:102-103`);
- `scope.ts:120-124` prints only `offlineSince`, not `s.closed`.

**Wording.** "the room could not be joined" is the fixed unjoined text (`tools/join.ts:266`). It is inaccurate when
the user simply left first.
