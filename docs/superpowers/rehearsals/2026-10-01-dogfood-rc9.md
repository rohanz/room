## New findings

1. **medium — a new worker inherits an old worker's owed messages.** The docs worker's first
   room_scope delivered three stale answers addressed to an earlier `rohanz+docs` worker (an earlier
   batch's), one telling it to update `doctor-entry.test.ts`. A reused tag reuses the participant name,
   and owed messages are keyed by name, not by worker session.
2. **low — room_claim clamps silently.** `room_claim to=561` on a 560-line file became 560 with no word.
3. **process — the skipwalk worker could not find the reported reason text.** The finding said
   "(N .gitignore)"; no roomd path emits that label. Human-paraphrased log lines cost a question round:
   quote logs verbatim in findings.
4. **medium (fixed here) — the hot-path throttle counted unchanged republications.** Found by skipwalk:
   every reconcile marked every changed file as published, so after five edits to one file any other
   changed file was "hot" and its next real edit waited 30 s. Only a real text change counts now
   (`packages/roomd/test/hot-path.test.ts`).
5. **low — roomd runs one `onDiskChange` per changed path in a batch** (skipwalk); not changed here.
6. **low — "[inbox N]" blocks precede tool replies,** so an `error:` line is not at the start of an
   error reply (refresh). Tool-text changes also need `npx tsx scripts/eval-mocks.mts`, which AGENTS.md
   does not say.
7. **low — the room_send budget had 17 characters of slack** before the refresh parameter (refresh
   trimmed two parameter descriptions to fit; no routing words touched).
8. **low — the PreToolUse hook says "Claim before editing" on files the worker already claimed**
   (notices). `roomagent` (`packages/agent`) keeps its own wake path, which the new solo gate does not
   cover; the web timeline still shows migrated 0.16 history.
9. **low — `tsc -b` in a worker leaves `dist/`, which the preview reports** as the worker's build
   output (skipwalk, notices). Harmless, but every preview names it.
10. **medium — a resumed worker's second room_done did not reach the lead.** notices was resumed with
    a follow-up, finished and called room_done (its log shows the report), but the lead's room_wait only
    said "1 worker still running (preview)" and room_state still showed the first report's summary. The
    lead found the second report in the worker log.
11. **low — an overlap that merges cleanly arrived as a CONFLICT notify.** notices' one-line edit in
    `messaging.ts`, near the lead's collected refresh changes, was reported as `CONFLICT … overlaps
    rohanz+notices's new claim`; it merged with no conflict. Useful as a heads-up, loud as a conflict.
12. **high — the lead's Room MCP server stopped itself while the lead was alive.** About five minutes
    after the bundle rebuild and commit, the lead's server logged `stopping: host session ended` and exited
    (`presence-end.ts`, `hostSessionAlive`); the next room_wait answered "Connection closed" and the session
    had no Room tools for the rest of the batch. Just before, room_wait had said "Room was updated on disk;
    restart this session to pick up fixes", which is right, but losing the tools is not. **Cause (fixed in
    rc9):** macOS has no fixed boot time; `kern.boottime` is the wall clock minus uptime, and a clock
    correction moved it from `1789781722` to `1789781723`. Room's macOS process identity is
    `darwin:<boot>:<lstart>` and was compared exactly, so the live host no longer matched its own session
    record and read as dead. Nothing in the batch caused it; any long macOS session could hit it, and
    workers could read as "not ours" the same way. Diagnosed by a read-only built-in subagent, since the lead
    had lost room_spawn. macOS starts now compare by `lstart`, with the boot part allowed to drift by a
    minute (`sameStartTime`, used by liveness, session binding, worker ownership, launch checks and the
    local migration).
13. **good — what worked.** Five parallel workers with four real design questions answered in-thread
    (the skip log's provenance, one possible notice per holder, what counts as worker scratch, where
    unsaved scratch goes). A CONFLICT notice caught a resumed worker editing near the lead's collected
    changes; the combined preview was clean. The preview worker profiled before fixing and found the real
    cost (carried untracked files, not the ignored tree).

## Outcome

Astra (gpt-6-astra, high, read-only): 3, 1, 1, 1, 1, 2, 0 must-fix (SHIP at round 7). Round 1: refresh's
ignored-file check missed file/folder overlaps, its borrower check ran outside the operation lease, and a
spawn frontier of 0 was treated as "none". Rounds 2–6 were all refresh's ignored-output check, each a
state it did not cover: a staged untracking, an unstaged file-to-folder replacement, the worker's own
replayed commits, a trimmed name, a case-only alias; round 6 also caught that a rebase drops merge
commits. The class closed when the check covered every path a rebase can write (the lead's tracked tree
plus every path the replayed commits touch). Rebasing a worker is the new machinery in this batch, and
it took six of the seven rounds, as rc2's and rc4's new machinery did. Brief "every path the operation
can write" up front next time.

The lead lost its Room tools after the round-0 commit (finding 12), so every review fix was made by
hand and the waits were shell polls. Typecheck, knip and build:plugin clean on every commit. Full suite:
297 files / 3,285 → 3,296 tests across eight runs, green on six (the last, on the final commit: 3,296/3,296); the two failures were load timing in
tests' own harness (a 10 s cleanup hook, fixed; a hook reading "Room is reconnecting") and passed alone.
