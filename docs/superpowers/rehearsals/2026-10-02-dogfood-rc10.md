# Dogfood: leading the rc10 batch on Room 0.17.0-rc9 (2026-10-02)

The rc10 batch (exactly two fixes from the [rc9 notes](2026-10-01-dogfood-rc9.md): findings 10 and 11) was
led from a headless Claude Code session loading Room from this checkout (`--plugin-dir plugins/room`, 0.17.0-rc9)
in the clone's local room. Each fix was a few lines once its cause was found, so the lead made both itself and
spawned no workers. Reviews ran outside Room (direct read-only `codex exec -m gpt-6-astra`).

## The two fixes

1. **rc9 finding 10 (a second room_done never reached the lead).** The rc9 notes said the worker was "resumed".
   The registry says otherwise: `notices` (`w_01M3VT60KWGS71BZSET04E1EDE`) has one run, its report has
   `"posted": "wk:w_01M3VT60KWGS71BZSET04E1EDE:1"` and `done.at` 22:04:41, and its exit is 22:19:16. The lead's
   follow-up reached the worker while its host was still exiting after the first room_done (status `running`,
   so room_send posts rather than resumes), and the worker's second room_done landed in the same run. Two
   layers dropped it: `writeReport` kept the first `done` (`previous.done ?? report.done`) and `postCompletion`
   returned early on `report.posted`. room_done still told the worker "Your lead … has been told". A real
   resume (and `refresh=true`) starts run n+1 with its own message id and already worked; the new end-to-end
   test covers all three paths (`worker-refresh.test.ts`, "every room_done reaches the lead once").
2. **rc9 finding 11 (a clean overlap arrived as CONFLICT).** The notice was an `edit-in-claim` slot ("your
   earlier change to … overlaps rohanz+notices's new claim"), labelled CONFLICT by priority alone; nothing
   checked whether the texts merged. The new test reproduces the rc9 text verbatim before the fix.

## New findings (left for the roadmap)

1. **process — paraphrase hid the cause again.** "Resumed" in the rc9 notes sent the first suspicion to
   resume state; the registry record (one run, posted marker) answered it in one read. Quote registry facts

2. **low — room_done does not check that its completion was posted.** `postCompletion` returns `false` when it

3. **low — the web timeline still draws a clean overlap as a conflict span** (`deriveConflictSpans` counts every
