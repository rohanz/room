# Dogfood: leading the rc12 batch on Room 0.17.0-rc11 (2026-10-02)

The rc12 batch (the four medium/high findings of the [all-Codex Werkzeug rehearsal](2026-10-02-codex-all.md): R1–R4)
was led from a headless Claude Code session loading Room from this checkout (`--plugin-dir plugins/room`, rc11) in
the clone's local room. The lead fixed R1 and R4 itself and spawned two Claude workers (`claude-opus-5-5`, high,
`carry=false`) for R2 (`r2fail`) and R3 (`r3claims`). Reviews ran outside Room (direct read-only `codex exec -m
gpt-6-astra`).

## What happened

- **Spawn, work, report, preview, collect: all through Room.** Both workers reported in one `room_done` each with
  the root cause, the change and the failing-first tests. The lead's `room_preview_merge(people=[both], run="npm run
  typecheck")` read both as "trusted local worktree", applied 24 paths with no conflicts and passed; one
  `room_collect()` brought both in and cleaned up their worktrees, branches and logs. No question was needed.
- **The workers' claims and the lead's edits never met:** the lead's R1/R4 files and the workers' files were
  disjoint, as briefed.

## Findings

1. **process — this Mac has no `timeout`.** Both briefs said to prefix commands with `timeout 600`; the lead found
   out on its own first command and corrected both workers with a `room_send` note. Brief foreground limits as "your
   Bash tool's timeout", not a binary.
2. **low — `room_done` does not publish a commit made just before it.** In the R1 end-to-end test a worker that
   commits and calls `room_done` within the 3 s HEAD poll publishes its old overlay with the report. The lead no
   longer depends on it (its preview and collect read its own workers' worktrees in any room now), but another
   worker previewing in those seconds sees the pre-commit state. `room_done` could run one HEAD poll and reconcile
   first.
3. **low — a launch records the host's executable right after `spawn`.** The registry's `launch.process.executable`
   is read once the child starts; a probe before `nice` or a shell has exec'd into the host would record `nice` and
   make every later liveness check say "dead". Not seen in any log (all records say `codex`/`claude`), but the R4
   probe cache keeps young processes to a 250 ms reuse for this reason.
4. **note — previews of workers now cost what they should.** Before R1, workers in a team room published no changes
   (unanchored), so their previews of each other were quick and empty ("PARTIAL due updating manifests"). With R1
   they merge real text: in the load reproduction a worker's eight-way preview went from 0.3 s (nothing merged) to
   2.5 s p50 (four files each from eight participants), after R4 cut its Git reads (each base file once per preview).
5. **note — reproducing R4 needed `CODEX_HOME`.** `room_spawn(host="codex")` compares the lead's version with the
   Room plugin installed for Codex (`~/.codex/plugins/cache`); the reproduction points `CODEX_HOME` at an empty
   folder so its fake `codex` is not refused, without touching `~/.codex`.

## The four fixes, in one line each

- **R1:** a team-room worker anchors to its registry-pinned spawn base, or the newest remote commit under it, when
  the room's remote gives it no anchor (or an older one), so its manifest completes and keeps its commits; the lead previews its own workers from their worktrees
  in any room, not only local rooms.
- **R2:** the failure notice and worker status quote the host's error event (Codex `turn.failed`/`error`, Claude
  `is_error` result or API error), say when it is transient capacity or a rate limit and how to retry.
- **R3:** claim lines map exactly through long files (common prefix and suffix, then a bounded Myers diff of the
  middle); uncertain lines are a plain note in the holder's own numbers, never `CONFLICT` or 1–N.
- **R4:** the lead's MCP spent 120 of 316 s blocked in synchronous `ps`/`sysctl` probes of its workers on every
  status read; probes are now bounded per pid, `codex --version` is read asynchronously, and commit-addressed file
  reads are cached.
