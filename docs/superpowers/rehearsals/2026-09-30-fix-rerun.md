## Found in the rerun

- **Fixed during the rerun (`c6c2e3a`).** The first `room_join` took 147 s, 145.7 s of it in `room_state`:
  `waitingOn()` awaited the whole symbol-graph build (`graph: indexed 2997 files in 143389ms`). `room_send`'s
  changed-message upgrade awaited it too. After the fix, the same join took 13 s, and the reply says "symbol index
  still building".
- **Harness hazard, worth a line in the install docs.** Codex runs plugin hooks from the marketplace source, but
  starts the MCP from its plugin cache. It also re-syncs the cache from the marketplace source when a session
  starts, after launching that session's MCPs. The first cy session ran without the `marketplaces.room.source`
  override, so it got the 0.17.0 MCP with the 0.16.40 hooks from the main checkout. Those hooks wrote the legacy
  `.git/room-session.json`, so the MCP never bound to its thread and its wakes were off: its receipts were
  recorded under a synthetic `mcp:<pid>` session. That session also left a 0.16.40 cache behind, which the next
  launch loaded. The F1 results above come from a session with both halves at 0.17.0, bound to thread
  `01a0ef5a-…`.
- **Codex `/quit` gives no catchable signal** (F6 residual). The 0.17 MCP logged nothing, and the server
  released cy's lease only on expiry. Ctrl-C (stdin closed) leaves cleanly.
- **"cy's agent" did not resolve** for a tagged agent: cy joined as `cy+codex`, a remembered tag (C7), and a tagged
  agent's display name is its full name. The refusal listed the known names, and the agent retried at once. When
  an owner has exactly one agent, `"<owner>'s agent"` could resolve to it.
- **Slow calls in the 86 MB repo:** `room_collect` of a one-file worker took 20.8 s, and `room_spawn` 9.1 s
  (`worktree add 3848ms`). Codex's first `room_state` after startup took 17.5 s (`body`).
- **Preview cache disk use.** One Rust preview left 6.2 GB under `.git/room-preview/` (the warm `target/`), one slot per live process; it
  was removed after the run. README documents how to reclaim it.
- **Server log noise.** `dropped presence under "(client N)"` repeats for every participant.
- **Lead side (this batch's lead ran the installed 0.16.40).** `room_wait` returned the same worker note on
  consecutive calls until that worker was collected. Worker previews that named collected workers reported
  hundreds of paths from a base mismatch.
