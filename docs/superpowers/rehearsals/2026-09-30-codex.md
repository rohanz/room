## Findings

- **C1 (high).** On this 86 MB repository a preview with `run` first spends ~3 minutes extracting the combined tree
  (`setup 173052ms`, `setup 180078ms`), and cy's hit the 180 s limit, so cy could not test the combined code at all.
  The 09-28 run's three-way preview also timed out on git. The setup cost should not be paid per preview (reuse a
  cached tree or a worktree), and the limit should scale with repository size.
- **C2 (medium).** Every preview with a test run produced a 2.3–2.7 s `event loop lag` line in the MCP, so Room
  calls and hooks for that session stalled while it ran.
- **C3 (medium).** `room_claim` took 3.8–9.5 s per call here (`body`), five calls in a row.
- **C4 (medium).** A force-push is announced as an ordinary push from the old base (`f9ff683..d1cae4f`,
  "1 commit") with fast-forward pull advice. A teammate on the same branch would follow that advice and be refused.
  Room knew the previous head (`f5ce848`); the notice should say the branch was rewritten and that `pull
  --ff-only` will refuse.
- **C5 (low, wording).** "you edited … inside cy+codex's claim" was sent to ana about her commit from before the
  claim existed. The conflict was real; the tense was wrong, which is why ana's agent opened with a denial.
- **C6 (low).** `areas from .github/CODEOWNERS: .github/CODEOWNERS/, …` lists the CODEOWNERS file itself as an area.
- **C7 (low).** A per-clone remembered tag outlives the login it was chosen for: cy joined as `cy+codex` because
  the 09-28 session (user rohanz) had saved the tag `codex`. `room_create` also rewrote this clone's
  `.git/room-choice.json` to `where: "ws://127.0.0.1:1301"`, dropping `share`, `warned` and `warnedLevels`; both
  scratchpad clones were restored to `where: "team"` after the run.
- **H1 repeated.** ana's agent again passed its own display name to `room_preview_merge` (see httpx H1).
