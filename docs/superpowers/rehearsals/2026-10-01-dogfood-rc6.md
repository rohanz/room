# Dogfood: leading the rc6 batch on Room 0.17.0-rc5 (2026-10-01)

The rc6 batch (six small fixes) was led from a Claude Code session loading Room from this
checkout (`--plugin-dir plugins/room`, 0.17.0-rc5), in the clone's local room, with Claude
workers (claude-opus-5-5, effort high). Reviews ran outside Room (direct read-only `codex exec`).
This file records every Room problem met while doing the work, as it happened.

Severity: **high** = wrong or lost work or a blocked batch; **medium** = misleading output or a
manual workaround needed; **low** = wording or noise.

## Findings

1. **medium — a remembered 0.16 branch room survives the 0.17 upgrade.** `.git/room-choice.json`
   (written 2026-09-27 by 0.16) holds `"room":"local/room-redesign/redesign-wave0"`. 0.17 joined
   that branch-suffixed room instead of the repository room `local/room-redesign`, so "one room per
   repository across branches" does not hold for an upgraded clone that ever chose a branch room;
   room_state shows `local/room-redesign/redesign-wave0`. The upgrade notice for an explicit team
   branch room (rc2) has no local counterpart.
2. **low/medium — thirteen identical stale branch notices on the first command.** The first Bash
   call's hook inbox carried 13 copies of `room [bot] → rohanz's agent: you switched to redesign;
   the room is for redesign-wave0; commits here are not the room's base until they are pushed to
   redesign-wave0`. 0.17 no longer emits this text (only `relevance.ts` filters it); these are 0.16
   bus messages carried over by the local-room migration (`relay/migrated-*.json`). The relevance
   filter keeps them because the clone is still on `redesign`. They are 0.16 concepts (a room per
   branch) that 0.17 contradicts, and they were not deduplicated.
3. **high — in a workspace monorepo, a worker's cross-package tests run the lead's code.** Worker
   worktrees (`.room/workers/<tag>`) have no `node_modules`; Node resolves `@room/*` by walking up
   to the lead's `node_modules`, whose workspace links point at the lead's `packages/*`. A worker
   that edits `packages/shared` and tests from `packages/room-mcp` silently tests the base code and
   can report green on an untested change. The roomcap worker noticed and symlinked its own
   packages by hand; nothing in the spawn reply or the worker brief warns about it. Room should
   either link the worktree's own workspace packages or say so in the spawn reply.
4. **low — the "uncommitted changes not in this worktree" note repeats on `carry=false`.** Every
   spawn with an explicit `carry=false` still says "4 uncommitted changes in your clone are not in
   this worktree ... Commit them first if the task builds on them" — the lead already chose not to
   carry. Five spawns, five identical notes.
5. **medium — fix 1's premise is half wrong for Claude workers.** Mid-run, all five Claude worker
   logs were 0.5–1 MB, so stream-json output already reaches `.room/workers/<tag>.log`
   incrementally; what is missing is a readable "what is it doing now" line. room_state's worker
   section shows `last: [notify] rohanz+progress claims …` (the last bus message, truncated
   mid-word), not activity.
6. **low — room_state's claim summary collapses to `packages/`.** With eight open claims, the
   summary reads `rohanz+export: 3 claim(s) · packages/` for every worker: the common prefix of a
   monorepo says nothing. The file or package would help.
7. **low — the merge preview lists every participant's gitignored `dist/` directories.** A
   five-worker preview opened with six `NOT previewed (gitignored, <name>): packages/*/dist/ …`
   lines, about 900 characters of regenerable build output that collect already treats as
   disposable. One line ("build output not previewed") would do.
8. **good — what worked.** Five parallel Claude workers spawned in seconds with `carry=false`,
   claimed regions without being asked twice, and asked one real design question (fix 3's login
   evidence), which woke the lead and was answered in-thread. Two workers edited
   `packages/server/src/index.ts` and two edited `views.ts`/`scope.ts`; the combined preview
   merged them cleanly and ran the typecheck. One `room_collect` brought in 27 files and cleaned
   up all five worktrees. Worker logs streamed live throughout.

## Linux readiness (fix 6)

CI (`.github/workflows/ci.yml`) already runs only on `ubuntu-latest`; there is no macOS job, so
there was nothing to add to a matrix. This branch has been tested only on macOS, and Docker Desktop
returned 500 on this machine, so the suite was not run on Linux here. A read-only audit of tests and
platform branches found nothing certain to fail; the changes and the open risks:

- **Changed:** `timeout-minutes` 20 → 45 (the suite takes about 6 min on an M-series Mac before
  `npm ci`, builds and the image build; the watchdog still ends any one file at 15 min).
  `relay/test/local-migrate.test.ts` used pid 999999 as a dead process; Linux pids go up to
  4194304, so it now uses 4999999.
- **Linux bug, not fixed (needs a hook-script edit this session was not allowed to make):**
  on Linux, `probeProcess` (`relay/src/process.ts`) and the hooks' `processTable`
  (`plugins/room/hooks/common.mjs`) name a process by `basename(readlink /proc/<pid>/exe)`. The
  native Claude installer links `~/.local/bin/claude` to `~/.local/share/claude/versions/<version>`
  (seen on this Mac: `-> versions/2.1.286`), so on Linux a Claude process is named `2.1.286`, not
  `claude`. `workerProcessOwnership` then calls a live Claude worker `not-ours`, so it is never
  signalled. Session matching still works because both sides use the same rule. The fix is to read
  `/proc/<pid>/comm` (the name as invoked, as macOS `ps -o comm=` reports) first and fall back to
  `exe`, **in both files together**: `session.ts` `sameProcess` compares the two. A test with
  injected readers was written and then reverted along with the half-change.
- **Flake risks on a slower runner:** event-loop stall bounds of 200 ms in
  `preview-run-cache.test.ts`, `stop(20)` under 200 ms in `agent/test/runner.test.ts`, a 500 ms
  bound in `tools.test.ts`, and the 1 s READY window of the preview lock helper.
  `relay.test.ts`, `hub.test.ts` and `local.test.ts` listen on a `deterministicPort` in 40000–59999
  with no error handler. That band lies inside Linux's ephemeral range (32768–60999), so a busy
  port hangs the test until it times out.
- **First CI run of Linux-only branches:** `flock -n` in `preview-cache.ts` (macOS uses `lockf`);
  `/proc` scans in `worker-process.ts` (no test checks a positive match on either OS); inotify
  through chokidar in roomd tests.
