## Must fix before the trial

1. **Legitimate multi-user updates can be rejected, then subsequent work silently stops arriving.** `packages/server/src/readonly.ts:173`, `:236`, `:295`; `packages/shared/src/doc.ts:58`; `packages/server/src/index.ts:381`. **REPRODUCED.** Alice and Bob join concurrently and independently choose color slot 0. Both initial updates pass the guard. Alice receives the merged state; the real `RoomDoc.reconcileColors` changes Bob's slot to 1. The guard rejects that legitimate update with `colors mutation for bob`. In a second real-Yjs experiment, after one rejected client update, the next update to that client's own scope returned `{ok:true}` but left the server's scopes empty and `pendingStructs` populated: its preceding client clock was missing. The connection remains usable-looking; refusal is only logged/audited on the server. This can hide subsequent scopes, edits and questions from both friends. A client replaying a mixed Alice/Bob document to an empty server also gets `scopes mutation for bob`, relevant to restoration before persistence has loaded. **Smallest fix:** make color repair author only the caller's slot, or perform cross-user repair on the server; await persisted state before accepting reconciliation; implement an explicit rejection/resynchronization path that rebuilds rejected client history rather than continuing a causally broken stream. Closing and reconnecting the same unchanged rejected document alone is insufficient. Verify two actual client streams, a rejected update followed by a valid one, and persistence reload. Keep the read-only viewer restriction.

2. **Successful collection can delete ignored worker output without copying or preserving it.** `packages/room-mcp/src/tools/collect.ts:179`, `:227`; `packages/room-mcp/src/workers.ts:305`. **TRACED.** A friend's worker finishes source changes and leaves an ignored reproduction artifact or diagnostic result in its worktree. Normal `room_collect()` excludes ignored files from the combined tree, permits `gitignored` omissions, and calls `cleanupWorker(..., true)`, which forcibly removes the entire worktree. There is no recovery patch on this path. The new ignored-artifact check at `collect.ts:85` protects **discard only**. The existing discard test's `artifact.bin` would therefore be protected on discard but unprotected on successful collection. **Smallest fix:** run `ignoredWorkerArtifacts` before automatic cleanup too; collect ordinary changes but retain the worktree and list uncopied artifacts until explicitly copied or discarded. Do not describe that worker as fully collected and delete it. Keep `force` confined to the explicitly requested destructive/copy operation.

3. **Finished declared output is unreadable while still connected, then withdrawn on restart.** `packages/room-mcp/src/tools/context.ts:288`; `packages/room-mcp/src/tools/claims.ts:124`; `packages/roomd/src/index.ts:180`, `:344`, `:773`. **REPRODUCED for the read failure; TRACED for restart.** Following README's recommendation, Alice shares `declared`, finishes without committing, and calls `room_done`. Her overlay remains, but her scope is cleared. Bob's `room_read(path, person="alice")` now returns `app.py: not shared (alice shares declared paths only; app.py is outside their scope)`. I executed the real completion helper and the real withholding predicate: the text still existed when that answer was produced. Whole-diff/preview paths can still consume retained overlays, so the replies disagree. Restarting Alice loses the in-memory retained-path set; startup reconciliation then withdraws the finished uncommitted output. **Smallest fix:** persist the explicitly published path boundary per worktree/participant independently of active scope, use that same boundary in daemon and read/preview replies, and remove entries on deliberate withdrawal, clean integration or collection. Retain only previously authorized paths; do not solve this by widening to full sharing.

4. **Merge preview can certify failing tests as passed.** `packages/room-mcp/src/tools/files.ts:181`, `:206`, `:130`; `packages/room-mcp/src/tools/workers.ts:53`. **REPRODUCED.** A friend or worker previews with a piped pytest command to limit output; the final pipeline command exits 0. `testVerdict('=== 1 failed, 2 passed in 0.1s ===', 0)` prints that failure followed by `tests: PASSED (exit 0)`. The preview also derives its pass bookkeeping from successful command execution, so completion can repeat the false success. This directly compromises the trial's combined-result check. **Smallest fix:** distinguish command exit from test success, treat recognized failure/error summaries as a failure even on exit 0, and use one structured result for the reply, `lastPreview`, and ledger. Run pipelines with failure propagation where supported; do not label an arbitrary zero-exit command as proof that tests passed.

5. **The Codex seat can silently lack pre-edit coordination despite the hook-health mechanism.** `packages/room-mcp/src/hooks-bridge.ts:382`; `packages/room-mcp/src/tools/index.ts:77`; `plugins/room/hooks/session-start.mjs:20`. **TRACED.** If the Codex user skips hook trust, join and scope calls made within 30 seconds produce no health warning. They can then edit for most of the task with no further Room calls and no pre-edit claims/inbox context; the diagnostic only runs after a later Room tool reply. Separately, trusting SessionStart but not the before-edit hook writes the same activity evidence that sets `health.observed=true` permanently, suppressing the warning altogether. README/onboarding's promise that missing hooks are reported does not cover these cases. **Smallest fix:** track SessionStart and PreToolUse evidence separately, and expose unverified pre-edit coverage in the team join/scope reply until a real PreToolUse receipt arrives. A single concise actionable note is enough; do not depend on a skipped hook to deliver its own failure notice or add a recurring warning.

6. **Snapshot reuse still invents dependency edges and omits facts needed for later edits.** `packages/room-mcp/src/graph-index.ts:77`, `:102`. **REPRODUCED.** Bob joins shortly after Alice and reuses her ready graph. A snapshot with exactly `a.py → c.py: Config`, `b.py → c.py: Token`, and `b.py → d.py: Config` becomes a graph saying that `c.py` uses `Config` from **both** `a.py` and `b.py`. The synthetic imports retain provider paths but lose which symbol each import resolved. Also, snapshot paths without edges get empty definition/reference sets; adding a consumer import cannot find an unchanged previously unreferenced provider until that provider is reparsed. I exercised both through the real `reuse`/`refresh` functions. In neighboring Python work this yields wrong impact answers and can miss pre-edit plans; refresh can publish the reconstructed false edges. The new test only uses one imported symbol per consumer and removes an import, so it misses both cases. **Smallest fix for this trial:** disable snapshot reuse and build each local graph. Retaining exact edge semantics plus complete per-file facts is the longer fix.

7. **A directory claim can silently take another participant's already-declared file.** `packages/room-mcp/src/tools/claims.ts:24`, `:56`, `:88`; `plugins/room/skills/room-etiquette/SKILL.md:11`. **REPRODUCED.** Alice scopes `tests/test_utils.py`; Bob, following the instruction to prefer directory claims, claims `tests/` for his neighboring tests. The real handler replies only `claimed … bob's agent · tests/ · my other tests`, with no conflict or scope warning. The scope check asks whether Alice's narrower scope covers the parent directory, so it misses the intersection. Alice's next edit is then told to respect Bob's whole-directory claim, or interrupts after she edits. This is the already-observed batch failure, directly applicable to three neighboring library tasks. **Smallest fix:** before adding a directory claim, check overlap in both directions against other participants' scope paths and refuse an overbroad claim with the conflicting files/names and a request to narrow it. Keep ordinary scope advisory; do not make every scope a lock.

## Should fix if there is time

1. **Remove Room's control environment from preview subprocesses.** `packages/room-mcp/src/tools/files.ts:206`. **TRACED.** The preview inherits every MCP `ROOM_*` variable, including host/owner/room and worker context, plus `ROOM_MERGED_TREE`. A preview command that starts Room-aware helpers or tests can behave differently from the same command in the friend's terminal. The repository itself documents this failure in the review-fixes batch. Smallest fix: strip Room control variables, then set only the intentional merged-tree marker. **Not a trial blocker by itself:** I found no Werkzeug checkout here establishing that its selected tests consume these variables; the false-pass bug above is the blocking validation issue.

2. **Resolve or reject bare worker tags before posting.** `packages/room-mcp/src/tools/messaging.ts:72`, `:104`. **REPRODUCED.** With worker `bob+graph` present, sending to `graph` stores `to:"graph"` and first says `sent … → graph's agent asks`, then says `nobody called graph is or was in this room; participants: alice, bob, bob+graph`. Thus it is misaddressed, but the current online path **does warn**, and question waiting terminates rather than silently waiting forever. Smallest fix: resolve an unambiguous tag among the sender's own workers, including the workers room, otherwise reject before posting. **Not a blocker** for this trial because the correction is visible and the workers skill already requires full names for previews.

3. **Do not cache an unavailable server sharing ceiling as full.** `packages/room-mcp/src/session.ts:209`. **REPRODUCED with mocked fetch, no network.** A non-OK `/auth/config` response gives `full`; a later response configured to return `intent` is never fetched because `full` was cached. The daemon also retains its existing ceiling across WebSocket reconnects. Smallest fix: distinguish absent legacy fields from a failed fetch, fail closed or defer publishing when the ceiling cannot be established, and refresh on reconnect with a bounded cache lifetime. This is not an independent blocker for the specified trial with unchanged server policy and explicit client sharing, but do not claim the ceiling is dynamically enforced by the hosted server.

4. **Revalidate claims after HEAD moves.** `packages/roomd/src/index.ts:543`; `packages/shared/src/doc.ts:322`, `:329`. **TRACED.** A successful pull reseeds overlays and changes the person's base, but does not refresh claims. Claims made before an overlay exists have no Y.Text anchor; their numerical line ranges can point at different code after the incoming commit. Smallest fix: release/redeclare the caller's unanchored claims on a detected HEAD change, with one precise notice. Git's refusal of a dirty/conflicting pull itself is safe; Room should not imply that `git pull --ff-only` can always proceed.

5. **Correct the Codex base-move wake instruction.** `packages/room-mcp/src/hooks-bridge.ts:291`. **TRACED.** It tells an interrupted Codex seat to pull, preview, then `report and offer to commit and push`, contradicting the etiquette's no finishing permission ritual. Smallest fix: remove the offer and say to handle Git's actual result before continuing. It does not itself commit or push, so this is annoyance rather than an automatic external action.

6. **Retain the hook-health warning's host context.** `packages/room-mcp/src/hooks-bridge.ts:395`. **TRACED.** The same diagnostic ends `In Codex, approve them once in an interactive session` for a Claude seat. Use the detected host; this is secondary to fixing the diagnostic's missing coverage in must-fix 5.

## What to watch during the trial

1. For each seat, record a PreToolUse receipt before its first collaborative edit; distinguish it from SessionStart and record whether company/inbox context actually reached that turn.
2. Log rejected sync packets with client/login and whether the next edit appears on another seat; a green socket is not proof that a write arrived.
3. For a deliberate Python signature change, record edit time, graph publication time, consumer notification time and consumer's next edit. Include the concrete provider/consumer paths.
4. At each directory claim, compare its descendants with the other two scopes; record whether someone stops on a file assigned to them.
5. After `room_done` and after restart, read the same declared changed file from another seat and compare preview inclusion with the publisher's disk.
