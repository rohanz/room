Room is quiet for a human during a healthy solo session, but it is not yet invisible for the agent: it exposes 24 tools, substantial permanent instructions, and a coordination procedure that scales with edits rather than actual overlap. With company, it becomes conspicuous through claims, repeated state reads, waiting rituals, browser links and Git instructions. More seriously, some silence means coordination has failed or sharing has begun without the promised disclosure. The recent fixes materially improve worker reliability and noise, but the remaining work is primarily subtraction, conditional instructions and honest failure reporting. This assessment is based on read-only source inspection and shell measurements, not live failure injection.

TOP 5

1. Make the agent interface conditional on actual coordination. Measured: 1,078 characters of MCP instructions, 24 tools with 7,108 description characters and 9,682 characters of compact JSON input schemas, plus 691 characters of skill descriptions: 18,559 characters before names, annotations and host framing. The complete compact tool catalog is 20,437 characters. Evidence: packages/room-mcp/src/prompt.ts:28; packages/room-mcp/src/tools/index.ts:29; packages/room-mcp/src/index.ts:51; plugins/room/skills/*/SKILL.md:3. These are advertised even when alone; host-specific tool deferral may change what reaches a model, but Room supplies no conditional catalog. Keep only the minimal entry points while alone; expose worker tools on dispatch and server administration on an explicit request, fold room_who into targeted room_read, and move procedural prose out of tool descriptions.

2. Coordinate on overlap, not on every file. The prescribed per-file sequence is room_read, room_claim, room_release and room_send changed: four coordination calls, plus scope, state, preview and done across the task; a single-file task can therefore require eight calls before questions, impact checks or retries. Evidence: plugins/room/skills/room-etiquette/SKILL.md:15,24,34,58; packages/room-mcp/src/tools/scope.ts:15 says “Call before editing and after any wait.” Directory claims reduce claims but do not remove the rest of the procedure. Keep one scope declaration, require claims only where another participant is near, combine release with the dependent-change announcement, and return the relevant state change with wait results.

3. Put the sharing disclosure before publishing, on every entry path that changes the destination. Default sharing is “full” (packages/room-mcp/src/config.ts:76), and the daemon starts before the explicit join reply is composed (packages/room-mcp/src/session.ts:402). An empty team room returns “alone here; the room stays quiet until someone joins” before reaching “note for your human: uncommitted work … is now visible” (packages/room-mcp/src/tools/join.ts:135,146); automatic joins bypass that reply altogether (packages/room-mcp/src/index.ts:89). Eligible changed-file text, including untracked files, and coordination metadata reach the server and room clients even when the user is the only present participant. Describe destination, recipients, sharing level and remembered scope once at the actual sharing decision; preserve that authorization without repeated prompts.

4. Make failed coordination distinguishable from healthy silence. Auto-join failure and missing login currently become log lines—“ready; not logged in: room_login” and “auto-join failed …; call room_join”—while the before-edit hook silently exits without state (packages/room-mcp/src/index.ts:104; plugins/room/hooks/before-edit.mjs:60). Untrusted Codex hooks are silently skipped, and Claude requires a separate launch flag (docs/onboarding.md:50,52). The explicit join reminder is skipped when alone and automatic joins never call it. Surface one actionable degradation notice when coordination is expected, retain it until recovery, and stop claiming wake capability without evidence; do not interrupt ordinary solo work for an unused capability.

5. Delete instructions that make the human supervise Room’s procedure. “Tell your human” follows even a wait where “nothing happened” (packages/room-mcp/src/tools/messaging.ts:162); etiquette requires “Then ask whether to commit and push” (plugins/room/skills/room-etiquette/SKILL.md:65); dispatch requires a browser link (plugins/room/skills/room-workers/SKILL.md:15). Preserve the good rule in packages/room-mcp/src/prompt.ts:37: “Tell your human when … changes your plan.” Apply that test everywhere: report an actual blocker, changed outcome or required decision; omit routine waiting, mandatory links and renewed approval for actions already authorized.

FURTHER FINDINGS — ranked

1. High; both. The fundamental “never writes disk” promise is false and obscures meaningful actions. Evidence: packages/room-mcp/src/prompt.ts:28 says “Room tools … never touch your disk”; plugins/room/skills/room-join/SKILL.md:29 repeats it, while packages/room-mcp/src/tools/collect.ts:118,124,129 stages, commits as the lead and merges, and tools/join.ts:209 exports files. Recommendation: say that live sharing never applies teammates’ edits, and explicitly distinguish requested collection/export from background coordination.

2. High; both. “Local by default” is true only after resolving environment and remembered state, with an additional legacy destination path. Evidence: packages/room-mcp/src/config.ts:67 gives argument > ROOM_SERVER > remembered choice > local, but :73 accepts ROOM_URL when those are absent, and index.ts:87 joins that URL before considering LOCAL; plugins/room/codex-mcp.json:14 forwards ROOM_URL. The remembered choice lives in the common Git directory, affecting sibling worktrees (choice.ts:34). Recommendation: retire the legacy destination path and describe remembered choices as clone-and-worktree-wide rather than implying each session starts local.

3. High; human. An invalid sharing setting silently widens to full text. Evidence: packages/room-mcp/src/config.ts:77 uses “rawShare === 'intent' || rawShare === 'declared' ? rawShare : 'full'”; this normalizes the value before session.ts:226 can reject it. Recommendation: reject unknown sharing values before joining and retain the previous restrictive setting.

4. High; both. Sharing limits produce missing coordination coverage without an adequate agent-visible explanation. Evidence: packages/roomd/src/index.ts:218 sets a 512 KiB file cap and :219 an 8 MiB participant budget; skipped files are logged at :605 and :712, but tools/share.ts:38 reads only skipped().share, omitting size and budget skips. 5. High; agent. A detected merge conflict does not actually wake an idle agent. Evidence: packages/room-mcp/src/conflicts.ts:289 posts “your … now conflict” as an addressed note with priority notify; packages/shared/src/messages.ts:41 defines notes as wakes: 'never', and wake.ts:30 honors that for notify. 6. High; both. Two sessions in one folder still compete for delivery state. 7. High; both. Team coordination disappears across ordinary feature branches. 8. Medium; agent. Reply size is bounded only in selected places, not across the tool interface. ALREADY GOOD

- Healthy solo hooks inject nothing; ordinary work need not call Room tools (prompt.ts:31; before-edit.mjs:94).
- Local rooms need no account, and surviving sessions attempt relay takeover on the same port every two seconds (packages/relay/src/index.ts:327); absent survivors, the stopped browser link is accurately documented.
- Offline sends explicitly say “queued/not delivered,” waits stop promising replies, and state identifies the last-known view (tools/messaging.ts:112,140; tools/scope.ts:48).
- Expired credentials are removed when the server identifies them, and the recovery is device login rather than asking for a token (session.ts:498,509; tools/join.ts:18).
- Questions to finished or unknown workers return immediately with useful status instead of wasting a timeout (tools/messaging.ts:44,54).
- Failed workers now produce an addressed interrupt with the actual log tail and release abandoned claims (registry.ts:51,63).
- Routine broadcasts, own messages and ended-plan fyi traffic generally stay out of agent inboxes; busy-worker timeouts now say “nothing needs you” (messages.ts:73; messaging.ts:161).
- The browser groups workers under their lead, collapses finished history, bounds file rows and batches rendering; it can remain optional without losing coordination (web/src/panels.ts:186,190,304; web/src/scheduler.ts).
